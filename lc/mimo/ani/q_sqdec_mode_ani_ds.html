块大小 B ≈ √N · 预处理 mode[i][j] = 第 i 块到第 j 块的众数 · 单次查询 O(√N)

📖 原理简介 · 分块如何把区间众数查询降到 O(√N)？

区间众数（出现次数最多的值）是个经典难题，因为"众数"不像"最大值"那样可合并—— 两段的众数合并后不一定是整体的众数。分块的做法是： 把数组按 B ≈ √N 切成若干块，先 O(N√N) 预处理出每一对"起始块到结束块"的众数 mode[i][j]。 查询 [l, r] 时，把区间拆成"左碎片 + 中间整块 + 右碎片"。 由于最优解要么落在中间整块里（此时它一定是 mode[左块+1][右块-1]），要么落在两端碎片里， 所以只需对 两端碎片中的每个值 + 中间块的众数 这几个候选值统计它们在 [l, r] 内的真实频率即可。

核心 1
块大小 B ≈ √N
N 个元素分成 N/B 块。
· 预处理 O(N²/B) = O(N√N)
· 单次查询 O(B + 候选数) = O(√N)
块太大预处理慢，块太小查询慢——√N 是平衡点。
核心 2
mode[i][j] 预计算
mode[i][j] = 从第 i 块到第 j 块的众数。
固定 i，逐步增加 j：每次把第 j 块加入计数，
更新当前众数即可。
共 O(N/B)² 个状态，每个状态均摊 O(B)，总 O(N²/B)。
核心 3
查询：两端暴力 + 中间查表
区间 [l, r] 拆成：
· 左碎片（l 到左块末尾）
· 中间整块（直接查 mode 表）
· 右碎片（右块开头到 r）
候选值 = 左碎片 ∪ 右碎片 ∪ {中间块的众数}
证明
候选集合为什么够用？
设 v* 是 [l, r] 的众数。
· 若 v* 出现在中间块 → 它在中间块的频率 ≤ mode 的频率，
而 mode 也在候选里，所以 v* 不会漏。
· 若 v* 不出现在中间块 → 它必然出现在两端碎片中，也在候选里。
复杂度
O(N√N) 预处理 + O(√N) 查询
预处理：O(N²/B) = O(N√N)
每次查询：
· 枚举候选：O(B)
· 每个候选统计频率：O(1)（用位置列表 + 二分）
总计 O(√N log N) 或 O(√N)（用前缀频率表）
对比
分块 vs 其他做法
· 暴力：每次 O(r−l+1)
· 莫队：O((N+Q)√N)，需离线
· 分块：O(N√N + Q√N)，可在线
· 可持久化线段树：只能求"出现次数"，求众数做不到
