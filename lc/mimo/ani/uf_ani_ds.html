并查集（DSU）· 路径压缩 + 按秩合并 动画

单次操作的均摊复杂度 O(α(N))，α 是阿克曼函数的反函数，实际使用中可视为常数

📖 原理简介 · 并查集如何做到近乎 O(1)？

并查集维护一堆不相交的集合，每个集合用一棵树表示，树根是集合的代表元。 每个节点只需记录它的 parent 指针。核心操作只有两个： find(x) 沿 parent 链找到根；union(x, y) 把两棵树合并。 单独使用时，树可能退化成链，单次操作退化为 O(N)。 加上路径压缩和按秩合并后，单次操作均摊复杂度降为 O(α(N)) < 5。

优化 1
路径压缩 Path Compression
find(x) 时把路径上的所有节点直接挂到根上。
下次再查这些节点，一步就能到达根。树被压得很扁。
优化 2
按秩合并 Union by Rank
union 时把矮树挂到高树下（按 rank 比较）。
rank 只在两棵树一样高时才会 +1，因此树高 O(log N)。
性质
为什么是 α(N)？
单独用路径压缩是 O(log N)，单独用按秩合并是 O(log N)。 两者一起用，均摊复杂度降到反阿克曼函数 α(N)， 对 N < 10⁶⁰⁰ 都 ≤ 5。这是一个几乎常数的复杂度。
操作
find(x)
沿 parent 一路向上，直到 parent[x] == x， 这个 x 就是所在集合的根。返回根作为代表元。
操作
union(x, y)
分别找到 rx = find(x)、ry = find(y)。 若 rx == ry 说明本来就在一起，什么都不做； 否则按 rank 把一棵树挂到另一棵下。
用途
典型应用场景
· 图的连通性判断
· Kruskal 最小生成树
· 动态维护等价类
· 带权并查集（维护节点到根的权值差）
基本操作 当前集合数：8 每个元素一开始都是自己的集合，初始 8 个独立集合
