# 图的连通分量：一套自顶向下的完整知识体系

---

## 〇、先给一张知识地图

```
连通性问题
├── 无向图
│   ├── 连通分量（CC）  ──┬── 范式A：DFS/BFS 染色  O(V+E)
│   │                     └── 范式B：并查集 DSU     O((V+E)·α)
│   ├── 桥 / 割点 / 边双（e-DCC）/ 点双（v-DCC）  lowlink O(V+E)
│   └── 缩点 → 树（生成森林 / 块割树）
├── 有向图
│   ├── 弱连通分量（= 无向 CC）
│   ├── 单侧连通分量（较少考）
│   └── 强连通分量（SCC）── Kosaraju / Tarjan / Gabow  O(V+E)
│                         └── 缩点 → DAG
├── 网格/像素：连通域标记（两遍扫描 + 并查集）
├── 动态连通性：增量 / 减量 / 全动态 / 离线回滚 / 在线 ETT·HLT
└── 高层视角：等价关系划分 · 环秩 m−n+c · 拉普拉斯零特征值重数
```

## 一、顶层思想：连通性到底在问什么

### 1.1 统一抽象：路径诱导的**等价关系**

无向图上定义关系：$u \sim v \iff$ 存在 $u \to v$ 的路径。

- **自反**：空路径；**对称**：路径可逆；**传递**：路径可拼接。
- 所以 $\sim$ 是等价关系，**连通分量就是它的等价类**，也就是顶点集的一个**划分**。

这一步抽象的价值在于：它立刻告诉我们所有连通分量算法的本质任务只有两件事——

> **判定"是否同属一类"** + **把元素合并进同一个类**。

于是天然长出两大范式：

| 范式 | 核心动作 | 数据结构 |
|---|---|---|
| **遍历染色** | 从一个源点出发"扩散"，把整片可达区域染同一个颜色 | 栈/队列 + visited 数组 |
| **等价类合并** | 每看到一条边就把两端所在类合并 | 并查集（Union-Find） |

**几乎所有连通分量问题，都是这两个范式的变体或组合。**

### 1.2 "连通"的四个层级（无向 → 有向）

| 概念 | 定义 | 说明 |
|---|---|---|
| **无向连通** | 任意两点有路径 | 基础 |
| **弱连通（weakly connected）** | 有向图忽略方向后连通 | 等价于把有向图当无向图求 CC |
| **单侧连通（unilateral）** | 任意两点，至少一个能到达另一个 | SCC 是它的细化 |
| **强连通（strongly connected）** | 任意两点**互相**可达 | SCC = 强连通的极大子图 |

关键区别：**无向图的 CC 是"划分"，有向图的 SCC 也是"划分"，但弱连通分量不等价于 SCC**——一个弱连通分量可能包含多个 SCC。SCC 之间由单向边连接，缩点后得到 DAG。

### 1.3 三个等价的数学视角（高级视角，可跳过）

**视角一：秩与环。** 设无向图 $n$ 点 $m$ 边，$c$ 个连通分量，则：
- 生成森林边数 $= n - c$
- **环秩（圈空间维数）$= m - n + c$**

于是"有没有环""是不是树（$c=1 \land m=n-1$）"都可以用连通分量数表达。Kruskal 算法的正确性、图拟阵的秩，都建立在这上面。

**视角二：线性代数。** 图的拉普拉斯矩阵 $L = D - A$，**特征值 0 的重数恰好等于连通分量个数**；第二小特征值（Fiedler 值）衡量"代数连通度"，Fiedler 向量用于谱聚类、图二分。这是大规模图划分算法的理论根。

**视角三：等价类闭包。** 连通分量 = 由边集生成的传递闭包；因此"增量式加边"用并查集最自然，"删除式"则困难得多（下文第六节）。

## 二、无向图连通分量：两大范式

### 2.1 范式 A：遍历染色（BFS / DFS）

**原理**：任取一个未染色点 $s$，从它能走到的所有点必与它同色；走完后这些点全部染上新颜色 $k$，再找下一个未染色点重复。颜色数即分量数。

```cpp
vector<int> comp(n, -1); int cnt = 0;
for (int i = 0; i < n; ++i) if (comp[i] == -1) {
    queue<int> q; q.push(i); comp[i] = cnt;
    while (!q.empty()) {
        int u = q.front(); q.pop();
        for (int v : g[u]) if (comp[v] == -1) { comp[v] = cnt; q.push(v); }
    }
    ++cnt;
}
```

**复杂度 $O(V+E)$ 的证明**：每个顶点入队/出队至多一次 $\Rightarrow O(V)$；每条无向边被两个端点各检查一次 $\Rightarrow O(E)$。总 $O(V+E)$，**与图的稀疏程度无关地达到下界**（读入图就要 $\Omega(V+E)$）。

**必须注意的工程细节：递归爆栈。**
$V=10^6$ 的一条链会让 DFS 递归深度达到 $10^6$，C++/Python/Java 全部栈溢出。**竞赛和工程中一律用迭代 DFS**：

```cpp
vector<int> stk{i}; comp[i] = cnt;
while (!stk.empty()) {
    int u = stk.back(); stk.pop_back();
    for (int v : g[u]) if (comp[v] == -1) { comp[v] = cnt; stk.push_back(v); }
}
```

**特点**：一次性拿到完整信息（每个点的分量编号、分量大小、分量内点集）；适合**离线静态图**；易于并行化改造；内存局部性好（BFS 尤其）。

### 2.2 范式 B：并查集（DSU）

**结构**：森林，每个集合的根为代表元。两个操作：
- `find(x)`：找代表元（沿父指针上溯）
- `union(x, y)`：把两棵树接起来

**朴素实现的致命问题**：链状退化，单次 `find` 是 $O(n)$。

**两个正交的优化**（这是本节的灵魂）：

| 优化 | 做法 | 作用 | 单独使用的代价 |
|---|---|---|---|
| **按秩/按大小合并** | 小树挂到大树下 | 树高 $O(\log n)$ | 每次操作 $O(\log n)$ |
| **路径压缩** | `find` 时把沿途点直接挂到根 | 树趋于扁平 | 单独也可，但需配合上者 |
| **两者同时** | — | **均摊 $O(\alpha(n))$**，$\alpha$ 为 Ackermann 反函数 | $\alpha(n)\le 4$（对一切现实规模） |

```cpp
struct DSU {
    vector<int> p, r;
    DSU(int n): p(n), r(n, 0) { iota(p.begin(), p.end(), 0); }
    int find(int x) {
        while (x != p[x]) x = p[x] = p[p[x]];   // 迭代 + 路径减半，避免递归爆栈
        return x;
    }
    bool unite(int a, int b) {
        a = find(a); b = find(b);
        if (a == b) return false;               // 返回 false ⇒ 这条边是"多余"的
        if (r[a] < r[b]) swap(a, b);
        p[b] = a;
        if (r[a] == r[b]) ++r[a];
        return true;
    }
};
```

**复杂度的本质**：$m$ 次操作总代价 $O(m\,\alpha(m,n))$，由 Tarjan (1975)、Tarjan–van Leeuwen (1984) 给出严格分析；Fredman–Saks (1989) 在 cell-probe 模型下证明 $\Omega(\alpha(n))$ 是**下界**，即并查集已达到理论最优。证明思路大致是：用势能函数衡量"树高秩"，一次 `find` 的摊还代价与路径压缩改变的节点数成正比，而秩的单调性保证总量受控。

**一个漂亮的副产品**：`unite` 返回 `false` 的次数 = 冗余边数，于是

> **分量个数 $c = n - (\text{成功合并次数})$**，环秩 $= m - (n-c)$。

**回滚版并查集（rollback / persistent DSU）**：去掉路径压缩，只保留按秩合并，另开一个栈记录每次改动。这样支持 **撤销**（用于离线分治、可持久化），单次操作 $O(\log n)$，回滚 $O(1)$。

### 2.3 两大范式对比与选型

| 维度 | DFS/BFS 染色 | 并查集 |
|---|---|---|
| 时间 | $O(V+E)$ | $O((V+E)\,\alpha)$，常数略大 |
| 空间 | 邻接表 + 标记 | 只需 $O(V)$（**边可流式输入，不必存图！**） |
| 增量加边 | 需重跑 $O(V+E)$ | $O(\alpha)$ 在线处理 |
| 删除边/点 | 需重跑 | 不支持（需回滚或动态结构） |
| 能否输出分量内点集 | ✅ 自然 | ✅ 需按根归组，或额外维护链表（启发式合并） |
| 并行化 | BFS 较易（level-synchronous） | 较难（需 Shiloach–Vishkin 等） |
| 实现难度 | 极低 | 低，但优化细节多 |
| **典型场景** | 静态图一次性求解、网格标记 | Kruskal、流式边、连通性查询、离线动态问题 |

**经验法则**：
- 图已完整给出、只问"哪些点同属一个分量" → **BFS/DFS**。
- 边是一条条来的 / 只关心"两点是否连通""最后有几个分量" / 与 MST、环判定结合 → **并查集**。
- 拿不准 → 两者都写，15 行以内。

## 三、网格 / 像素：连通域标记（特殊场景）

图像处理里的"前景连通域标记"是连通分量问题的高频工程版本，$n = W\times H$ 可达 $10^7$。

**朴素两遍扫描（Two-Pass）**：
1. 第一遍从左到右、从上到下，用 $(上, 左)$ 邻域的最小标签作为候选，冲突标签对用并查集合并；
2. 第二遍把每个像素替换为其标签的 `find` 根。

**三个必须明确的决策**：
- **4 连通 vs 8 连通**：$(0,1),(1,0)$ vs 再加 $(1,1),(1,-1)$。8 连通会导致"两个 4 连通的对角块"被合并，语义完全不同，必须与任务匹配。
- **标签压缩**：标签号不连续，最后 `find` 一遍并做 id 重映射。
- **并行/超大图**：run-based（按行游程编码）+ 并查集合并游程；或使用 union-find 的 GPU 并行变体、label propagation。BFS 版本在超大稀疏图上可用 direction-optimizing BFS（Beamer）加速。

**复杂度**：$O(WH)$，一次线性扫描即可，不能更优。

## 四、有向图：强连通分量（SCC）

### 4.1 定义与缩点

SCC 是"互相可达"这一等价关系的等价类（确实对称、传递）。**把每个 SCC 缩成一个点，得到的图一定是 DAG**，记作 $G^{\text{SCC}}$。这一步是大量题目（差分约束、2-SAT、DAG 上 DP、可达性压缩）的基石。

三个经典算法复杂度全是 $O(V+E)$，区别在于**常数、实现难度、是否需要转置图、是否天然支持递增**。

### 4.2 Kosaraju（两次 DFS）

**步骤**：
1. 对 $G$ 做 DFS，按**完成时间**（finish time）压栈；
2. 建转置图 $G^{T}$（所有边反向）；
3. 按栈的出栈序（完成时间递减）在 $G^{T}$ 上做 DFS，每棵 DFS 树 = 一个 SCC。

**为什么正确（严格论证）**：
- DFS 的完成时间逆序 = 缩点 DAG 的**拓扑序**。因此完成时间最大的点 $v$ 位于 $D = G^{\text{SCC}}$ 的一个**源点** SCC 中。
- 一个源点 SCC 在 $D^{T}$（即 $G^{T}$ 的缩点图）中是**汇点**：没有边能离开它。
- 所以从 $v$ 在 $G^{T}$ 上 DFS，**只能访问到自己 SCC 内的点**，正好输出一个完整 SCC。
- 把这些点标记后，剩下的图里，下一个完成时间最大的未访问点又是剩余部分某个"源点 SCC"的成员，递归成立。

```cpp
void dfs1(int u){ vis[u]=1; for(int v:g[u]) if(!vis[v]) dfs1(v); order.push_back(u); }
void dfs2(int u){ comp[u]=cnt; for(int v:gr[u]) if(comp[v]==-1) dfs2(v); }
// 主流程
for(i) if(!vis[i]) dfs1(i);
reverse(order);
for(u : order) if(comp[u]==-1){ dfs2(u); ++cnt; }
```

**特点**：概念清晰、容易写对、易并行；**代价是要建转置图**（内存翻倍），且必须两次 DFS。

### 4.3 Tarjan（一次 DFS，lowlink）

**核心工具**：两个时间戳
- $\mathrm{dfn}[u]$：DFS 序（进入时间）
- $\mathrm{low}[u]$：$u$ 的子树中，通过**至多一条回边**能到达的最小 $\mathrm{dfn}$

**关键机制：一个栈**。栈中保存"当前尚未确定归属 SCC 的点"。当一个 SCC 被完整识别时，栈中从顶到 $u$ 的所有点同属一个 SCC，弹出即可。

**判据**：$u$ 是其所在 SCC 的"根" $\iff \mathrm{low}[u] = \mathrm{dfn}[u]$。

```cpp
void tarjan(int u) {
    dfn[u] = low[u] = ++timer;
    stk.push(u); inStk[u] = true;
    for (int v : g[u]) {
        if (!dfn[v]) {
            tarjan(v);
            low[u] = min(low[u], low[v]);
        } else if (inStk[v]) {
            low[u] = min(low[u], dfn[v]);     // 注意：这里用 dfn[v]，不是 low[v]
        }
    }
    if (low[u] == dfn[u]) {                   // u 是 SCC 根
        while (true) {
            int x = stk.top(); stk.pop(); inStk[x] = false;
            comp[x] = scc_cnt;
            if (x == u) break;
        }
        ++scc_cnt;
    }
}
```

**原理拆解**：
- 为什么必须 `inStk[v]` 判定？——一条指向**已出栈**点的边，指向的是**另一个已完成的 SCC**，绝不能用它降低 `low`，否则会把两个 SCC 错误合并。这是 Tarjan 最常见的 bug 来源。
- 为什么用 `dfn[v]` 而不是 `low[v]`？——`low` 的意义是"能回到哪个祖先"，用 `dfn[v]` 语义最干净；SCC 版本用 `low[v]` 在某些图上也会错。
- 递归版同样面临爆栈，工程上需改迭代版或加大栈（`#pragma`/线程栈）。

### 4.4 Gabow（路径法）

用两个栈：一个"路径栈"记录当前 SCC 候选，一个"边界栈"记录回边目标。出栈条件与 Tarjan 等价，但不需要 `low` 数组，常数略优，实现较巧妙。实际使用较少，**竞赛与工程首选 Tarjan**。

### 4.5 三者对比

| | Kosaraju | Tarjan | Gabow |
|---|---|---|---|
| DFS 次数 | 2 | 1 | 1 |
| 额外图 | 需转置 $G^{T}$ | 否 | 否 |
| 时间 | $O(V+E)$ | $O(V+E)$ | $O(V+E)$ |
| 空间 | $O(V+E)$（两图） | $O(V+E)$ | $O(V+E)$ |
| 实现难度 | 低 | 中 | 中高 |
| 抗爆栈 | 中 | 中 | 中 |
| 易并行 | ✅ | ❌ | ❌ |
| 常见用途 | 教学、大规模并行 | **竞赛/工程默认** | 理论/低常数需求 |

**结论**：一般场景写 Tarjan；需要并行或想快速验证正确性时用 Kosaraju；两者输出可互相对拍。

### 4.6 SCC 的经典应用

- **2-SAT**：建蕴含图，$x$ 与 $\neg x$ 在同一 SCC 则无解；否则按 SCC 缩点的拓扑逆序赋值。
- **可达性压缩**：缩点后在 DAG 上做 DP/拓扑排序，把 $O(V\cdot E)$ 降为 $O(V+E)$。
- **最小环/强连通性判定**：$scc\_cnt = 1$ 即整图强连通。
- **SCC 分解本身就是分治**：每个 SCC 内部递归。

## 五、更细粒度的结构：桥、割点、点双、边双

这是"连通性"的**脆弱性分析**：删除哪个点/边会破坏连通？

### 5.1 统一框架：lowlink

无向图 DFS 树上：
- **树边**（父亲→儿子）；**回边**（连向祖先，**不构成有向环的横叉边在无向图 DFS 中不存在**）。
- $\mathrm{low}[v] = \min\{\mathrm{dfn}[v],\ \mathrm{dfn}[\text{回边目标}],\ \mathrm{low}[\text{儿子}]\}$

### 5.2 桥（bridge / cut edge）

> 树边 $(u,v)$（$v$ 是儿子）是桥 $\iff \mathrm{low}[v] > \mathrm{dfn}[u]$

**直觉**：$v$ 的子树连 $u$ 都回不去，更别说绕过 $u$，删掉 $(u,v)$ 就断开。

```cpp
void dfs(int u, int pe) {          // pe = 进入 u 的边编号
    dfn[u] = low[u] = ++timer;
    for (auto [v, id] : g[u]) {
        if (id == pe) continue;    // ⚠ 用边编号跳过父边，不能用 v != fa
        if (!dfn[v]) {
            dfs(v, id);
            low[u] = min(low[u], low[v]);
            if (low[v] > dfn[u]) isBridge[id] = true;
        } else {
            low[u] = min(low[u], dfn[v]);
        }
    }
}
```

**经典坑：重边。** 若 $u,v$ 之间有两条边，则任一条都不是桥。用 `v != fa` 会错误地把第二条边当成回边…… 实际上会把重边错判为桥。**必须用边编号去重**。

### 5.3 割点（articulation point）

> 非根点 $u$ 是割点 $\iff$ 存在儿子 $v$ 满足 $\mathrm{low}[v] \ge \mathrm{dfn}[u]$
> 根点 $r$ 是割点 $\iff$ 在 DFS 树中**儿子数 $\ge 2$**

注意 $\ge$（含等于）与桥的 $>$ 不同：`low[v] == dfn[u]` 意味着 $v$ 的子树只能通过 $u$ 回去，删掉 $u$ 就断了。**根必须特判**，这是第二大坑。

### 5.4 边双连通分量（e-DCC）

定义：任意两点之间都有**两条边不重复**的路径的极大子图 ⇔ **不含桥**的极大子图。

**求法**：（a）删掉所有桥后，剩下的每个连通块就是一个 e-DCC；（b）等价地，用并查集把所有**非桥边**两端合并。

**缩点**：把每个 e-DCC 缩成一点，连接它们的都是桥，结果是**一棵树**。很多"加最少的边使图边双连通"的题目 = 树上配对叶子。

### 5.5 点双连通分量（v-DCC / block）

定义：任意两点之间都有**两条点不重复**（端点除外）路径的极大子图 ⇔ **不含割点**的极大子图。

**求法**：DFS 过程中维护**边栈**，当发现 $\mathrm{low}[v] \ge \mathrm{dfn}[u]$ 时，把栈顶到边 $(u,v)$ 的所有边弹出，这些边涉及的点构成一个 v-DCC。

**特殊情形**：
- 一条孤立边、一个孤立点也各自构成 v-DCC（**孤立点容易漏计**）。
- 一个割点会同时属于多个 v-DCC。

**缩点 → 块割树（block-cut tree）**：把每个 v-DCC 和每个割点都当作节点，割点与它所属的 v-DCC 相连。**结果是一棵树，且是二分图**。这是解决"两点间路径是否必经某点""点双内构造环"等问题的强大工具。

### 5.6 四者关系速查

| 结构 | 破坏方式 | 缩点结果 | 判据 |
|---|---|---|---|
| 连通分量 | — | 森林 | 染色 / DSU |
| **边双 e-DCC** | 删桥后 | **树** | $\mathrm{low}[v] > \mathrm{dfn}[u]$ |
| **点双 v-DCC** | 割点 | **块割树（二分树）** | $\mathrm{low}[v] \ge \mathrm{dfn}[u]$ |

## 六、动态连通性：从静态走向动态

| 问题 | 支持操作 | 经典解法 | 复杂度 |
|---|---|---|---|
| **增量（incremental）** | 加边 / 连通查询 | 并查集 | $O(\alpha)$ 每次 |
| **减量（decremental）** | 删边 / 连通查询 | 难！需专门结构 | — |
| **全动态（fully dynamic）** | 加边、删边、查询 | Euler Tour Tree / HLT | 均摊 $O(\log n)$~$O(\log^2 n)$ |
| **离线动态** | 已知全部操作的时间轴 | **回滚 DSU + 时间轴分治** | $O(\log n\cdot\alpha)$ 每次 |
| **持久化** | 查询历史版本 | 可持久化数组 + DSU | — |

**离线分治技巧（务必掌握）**：
把时间轴建成线段树，每条边的存在区间 $[l,r]$ 挂到线段树的 $O(\log T)$ 个节点上；DFS 这棵线段树，进入时 `unite` 挂在当前节点的边，离开时**回滚**。配合"无路径压缩 + 按秩合并 + 改动栈"的回滚并查集即可。

**为什么删除困难**：并查集只记得"当前森林"，忘了"合并的顺序和被合并掉的其他可能路径"，删除信息不唯一可恢复。

**并行与超大规模**：Shiloach–Vishkin、Afforest、label propagation、Graph500 BFS；MapReduce/GraphLab 里用"标签传播 + 最小标签约简"迭代至收敛。

## 七、总对比表（一页速查）

| 问题 | 算法 | 时间 | 空间 | 关键点 |
|---|---|---|---|---|
| 无向 CC | BFS/DFS 染色 | $O(V+E)$ | $O(V+E)$ | 迭代防爆栈 |
| 无向 CC | 并查集 | $O((V+E)\alpha)$ | $O(V)$ | 可流式、支持增量 |
| 网格连通域 | 两遍扫描 + DSU | $O(WH)$ | $O(WH)$ | 4/8 连通、标签压缩 |
| 强连通 SCC | Kosaraju | $O(V+E)$ | 需转置 | 两次 DFS |
| 强连通 SCC | Tarjan | $O(V+E)$ | $O(V+E)$ | 栈 + inStack |
| 强连通 SCC | Gabow | $O(V+E)$ | $O(V+E)$ | 双栈 |
| 桥 / 割点 | lowlink | $O(V+E)$ | $O(V+E)$ | 重边、根特判 |
| e-DCC / v-DCC | lowlink + 弹栈/DSU | $O(V+E)$ | $O(V+E)$ | 缩点成树 |
| 动态连通（增量） | DSU | $O(\alpha)$/次 | $O(V)$ | — |
| 动态连通（全） | ETT / HLT | $O(\log n)$ 均摊 | $O(V)$ | 实现复杂 |

**选型决策树**：
1. 有向图？→ 要强连通：Tarjan；只要弱连通：当无向图做。
2. 无向图，边陆续到来/只要"是否连通+个数"？→ 并查集。
3. 无向图，一次性完整图，要每个点的归属？→ BFS/DFS。
4. 问删除点/边后连通性？→ lowlink（桥/割点）或块割树。
5. 有时间维度的加删操作？→ 回滚 DSU + 分治（离线）/ ETT（在线）。
6. 超大图（$10^8$ 边）？→ 并行 label propagation / direction-optimizing BFS。

## 八、常见错误清单（踩坑即查）

1. **递归爆栈**：$10^5$~$10^6$ 顶点的链状图。→ 迭代 DFS / 手工栈 / 扩栈。
2. **重边判桥**：必须用边编号跳过父边，而非 `v != fa`。
3. **割点根节点**：必须按"DFS 树儿子数 $\ge 2$"单独判断。
4. **Tarjan 的 `inStack`**：漏判或用 `low` 代替 `dfn`，都会导致 SCC 合并错误。
5. **有向图用并查集**：只得到**弱**连通分量，别当成 SCC。
6. **缩点后重边**：DAG 建图不去重会干扰拓扑 DP / 最短路（通常无害但影响复杂度与部分算法）。
7. **点双漏计孤立点**：v-DCC 计数时要把孤立点单独算。
8. **4/8 连通混用**：图像任务里语义完全不同。
9. **下标越界 / 0-index 与 1-index 混用**：`comp`、`dfn` 数组初始化值要能区分"未访问"。
10. **把"分量个数"与"生成森林边数"混淆**：$c = n - \text{成功合并数}$；生成森林边 $= n - c$。
11. **图不连通时的算法假设**：如 Kruskal 求"最小生成树"其实是求**最小生成森林**。
12. **多测不清空数组**：`dfn`、`timer`、`inStk` 必须重置。

## 十、一句话收束

> **连通分量 = "路径"诱导的等价类。**
> 求它只有两条路：**遍历染色**（把一片区域一次性染色）与**并查集**（把边一条条并成等价类）。
> 无向看连通，有向看强连通（缩点成 DAG）；怕删点删边，就用 **lowlink** 拆出桥、割点、点双、边双（缩点成树）；图会变，就上**回滚并查集或 Euler Tour Tree**。
> 复杂度上，除了动态版本，**一切静态连通分量问题都已是 $O(V+E)$ 最优**——真正考验人的，是重边、根特判、爆栈、`inStack` 这些细节，以及"什么时候该用哪个范式"的判断力。
