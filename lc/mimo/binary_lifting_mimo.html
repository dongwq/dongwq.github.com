02

开场：一个「跳一万次」的问题

MAIN先看一道真实问题。它不难，但朴素解法会直接超时——这就是倍增登场的理由。

FIG.02 · 序列跳 k 步问题
THE PAIN朴素做法卡在哪

一步一步跳，时间随 k 线性增长。

k = 10⁵，再乘上 10⁵ 次查询，就是 10¹⁰ 次操作。

◆ 慢的不是算法，是「一次只走一步」
THE HINT为什么还能更快

因为 k 是可以被拆开的：10000 = 8192 + 1024 + …

只要能「一次跳 2 的幂这么多步」，任何 k 都只要 O(log k) 次跳。

问题就变成：怎么知道「跳 2^k 步到哪」？

PREVIEW答案就一句
跳 2^k 步
= 先跳 2^(k−1) 步，
再跳 2^(k−1) 步

这就是倍增的全部核心，剩下的都是细节。

为什么「一步一步走」会超时

MAIN先把问题想透。倍增的价值不在代码，而在于它把「加法」变成了「乘法」。

FIG.04 · 同一个问题，两种跳跃节奏
COUNTING把代价算清楚
朴素
每次 O(k)，k 最大 10⁵
倍增
每次 O(log k)，约 17 次
预处理
一次性的 O(n log n)

查询多的时候，预处理的那点成本几乎不值一提。

KEY IDEA本质的转变

把「加 k」拆成「乘若干个 2」。

一步一步 = 每次 +1
倍增 = 每次 ×2，再决定要不要用它

加法要 n 次，乘法只要 log n 次。这就是全部。

FAMILY你其实已经见过倍增

快速幂是倍增的最小形态；二分查找也是「每次砍一半」。

倍增不是新技巧，是把「砍一半」用到跳跃上。

05

关键一问：为什么偏偏用 2 的幂？

MAIN不能用 3、5、10 吗？——可以，但只有 2 能让你「自己拼自己」。这一节是倍增的根。

FIG.05 · 只有 2 的幂能自我拼装
REASON 12 的幂能递推

因为 2^k = 2^(k−1) + 2^(k−1)，左半边的表建好，右半边直接用。

3 的幂做不到：9 ≠ 3 + 3，得另外记 2 个 3，表就没法递推。

REASON 22 的幂够稀疏

要拼出 n，只需要 log₂ n 个 2 的幂。

10⁵ ≈ 2¹⁷，所以「表」只需要 17 层，非常省空间。

REASON 32 的幂对应二进制

一个数的二进制位是 0/1，正好回答「这一跳要不要跳」。

k = 13 → 1101
= 8 + 4 + 0 + 1

遍历每一位，该位是 1 就跳一次，总共就是 log 次。

08

递推为什么成立：2^k = 2^(k−1) + 2^(k−1)

MAIN整节只有一个公式，但它撑起了后面所有代码。看图一遍就懂。

FIG.08 · 两段拼接，递推成立
PYTHON · 建表（链上倍增）
def build(nxt):
    n = len(nxt)
    K = n.bit_length()        # 需要的层数

    f = [[-1]*n for _ in range(K)]
    f[0] = nxt[:]             # 跳 1 步

    for k in range(1, K):   # 由小到大推
        for i in range(n):
            mid = f[k-1][i]
            if mid != -1:
                f[k][i] = f[k-1][mid]
    return f
顺序
k 必须从小到大，因为要用 k−1 层的结果
WATCH三个小细节
越界
跳出去用 -1 标记，查询时提前结束
层数
bit_length() = ⌈log₂(n+1)⌉，正好够用
自环
若 nxt[i] == i，表会永远停在 i（函数迭代）
09

查询：把 k 拆开，逐位跳

MAIN建好表之后，查询就是一个 for 循环。理解这 6 行，倍增就学会了。

PYTHON · 从 i 出发跳 k 步
def jump(f, i, k):
    """从 i 出发，跳 k 步到的位置；越界返回 -1"""
    K = len(f)
    for b in range(K):      # 从低位到高位
        if (k >> b) & 1:   # 第 b 位是 1
            i = f[b][i]
            if i == -1:
                return -1  # 中途跳没了
    return i
核心一行
if (k >> b) & 1　判断「这一跳要不要跳」
TRACE手工跟一次 k = 13
b=0  k&1=1  → i = f[0][i]  (跳 1)
b=1  k&1=0  → 跳过
b=2  k&1=1  → i = f[2][i]  (跳 4)
b=3  k&1=1  → i = f[3][i]  (跳 8)
# 1 + 4 + 8 = 13 ✓
COMPLEXITY代价一览
阶段时间空间
建表O(n log n)O(n log n)
单次查询O(log n)
朴素对比O(k)O(n)
HINT两处容易写错
  • 把 for b in range(K) 写成 range(n)，白跑很多
  • 从高位往低位跳（能对但不必要，还容易混）

从低位往高位跳最自然，因为建表也是从小到大。

TAKEAWAY这一节的收获

倍增查询 = 一个 for + 一个位判断。

后面所有应用，都只是换个「跳什么」：跳位置、跳幂、跳祖先。

完整模板：链上倍增

MAIN把前面三页合起来，就是一份可直接运行的模板。先把它吃透，后面都是变形。

PYTHON · 链上倍增完整模板
class BinaryLift:
    def __init__(self, nxt):
        """nxt[i] : 从 i 走一步到的位置，-1 表示走出界"""
        self.n = len(nxt)
        self.K = self.n.bit_length()
        self.f = [[-1]*self.n for _ in range(self.K)]
        self.f[0] = nxt[:]

        for k in range(1, self.K):
            fk, fp = self.f[k], self.f[k-1]
            for i in range(self.n):
                mid = fp[i]
                if mid != -1:
                    fk[i] = fp[mid]

    def jump(self, i, k):
        """从 i 跳 k 步，越界返回 -1"""
        for b in range(self.K):
            if (k >> b) & 1:
                i = self.f[b][i]
                if i == -1:
                    return -1
        return i
用法
bl = BinaryLift(nxt); bl.jump(0, 10000)
WHY CLASS为什么要封装

因为后面五个应用都复用同一副骨架：

链上
跳的是下标
树上
跳的是父节点
幂
跳的是平方
矩阵
跳的是矩阵乘法

只有「跳什么」不同，「怎么跳」完全一样。

OPTIMIZEPython 想更快
① 拍平
用 f[k*n + i] 一维数组代替二维列表
② 局部
把 self.f 提前取到局部变量
③ 跳表
只建需要的层数 k.bit_length()

三招合起来能省 40%～60% 时间。

BOUNDARY什么时候用不上

如果 只查一次、或者 k 本身就很小，朴素更简单也更快。

倍增是给「大批量查询」准备的武器。

★ 什么时候不该用倍增

★ OPTIONAL会用工具重要，知道什么时候不用更重要。这一节能帮你避开大部分死胡同。

NO四种不适合的情况
  • 需要修改（单点/区间更新）→ 用线段树 / 树状数组
  • 合并运算不可结合（如带删除的众数）
  • 只查一次，预处理不划算
  • n 太大（> 10⁷），空间开不下
CONDITION倍增的前提三问
  1. 动作能不能「拼一半」？（可结合）
  2. 是不是「跳/迭代」性质？
  3. 是不是「重复查询、静态数据」？

三问都「是」，才上倍增。

VERSUS易混方法对照
方法擅长短板
倍增跳 k 步 / k 级祖先不能改数据
二分单调答案 / 边界需要单调可判
双指针连续区间只能线性扫
线段树区间查询 + 修改代码量大
树链剖分树上路径 + 修改常数大、代码长

倍增是「静态 + 查询密集」的最优解之一。

EXAMPLE举个反例

「区间众数」不能用 ST 表：众数不能重叠合并，删掉一半无法还原。

这类题要莫队 / 分块 / 线段树合并，不是倍增。

◆ 见到「不可逆」就别硬套倍增

应用 A：快速幂 —— 倍增的最小形态

MAIN先看一个你可能已经写过的例子，确认「这就是倍增」，再往下走更复杂的。

FIG.13 · 快速幂：a¹³ = a⁸ · a⁴ · a¹
P1226 【模板】快速幂 ↗ P3197 越狱 ↗ P3414 组合数 ↗
PYTHON · 快速幂（迭代版）
def pow_mod(a, n, mod):
    res = 1
    a %= mod
    while n:
        if n & 1:                 # 该位是 1
            res = res * a % mod
        a = a * a % mod            # 底数翻倍
        n >>= 1
    return res
对照
和 jump() 一个骨架：位是 1 就用，底数每次平方
MAP两种倍增的对应关系
链上倍增快速幂
「跳」移动下标底数平方
表 f[k]跳 2^k 步的落点a^(2^k)
查询跳 k 步算 a^n

结构一模一样，只是把「移动」换成了「平方」。

TRAP三个常见坑
  • 忘记 a %= mod，一开始就溢出
  • n = 0 时返回 1（任何数的 0 次幂）
  • 负数指数 要单独处理，别直接用

★ 龟速乘：大数相乘不溢出

★ OPTIONAL快速幂里 a * a 本身可能溢出怎么办？用同一套倍增思想，把乘法改成加法。

FIG.14 · 龟速乘：用加法代替乘法
PYTHON · 龟速乘（O(log b)）
def mul_slow(a, b, mod):
    """a * b % mod，中途不溢出"""
    res = 0
    a %= mod
    while b:
        if b & 1:
            res = (res + a) % mod
        a = (a + a) % mod          # 翻倍，不是平方
        b >>= 1
    return res

# 配套的「龟速乘 + 快速幂」
def pow_safe(a, n, mod):
    res = 1 % mod
    a %= mod
    while n:
        if n & 1:
            res = mul_slow(res, a, mod)
        a = mul_slow(a, a, mod)
        n >>= 1
    return res
用途
mod 大到 10¹⁸ 附近时，普通乘法会溢出 64 位
WHEN什么时候必须用
  • mod ≈ 10¹⁸ 且要用乘法（Python 自动大整数其实不炸，但慢）
  • 用 C++ 时 a*b%mod 直接溢出
  • 矩阵乘法模大质数时

Python 里更多是「性能考虑」，不是「正确性考虑」。

TAKEAWAY同样一副骨架

龟速乘 = 把「平方」换成「加一倍」的倍增。

看到这里你应该能感觉到：倍增是「换皮」的本事。

应用 B：矩阵快速幂

MAIN把「乘法」换成「矩阵乘法」，倍增就变身成求递推第 n 项的利器。

FIG.15 · 递推式 → 矩阵 → 快速幂
PYTHON · 矩阵快速幂求斐波那契
def fib(n, mod=10**9+7):
    if n == 0: return 0

    def mul(A, B):
        return [[
            sum(A[i][k]*B[k][j] for k in range(2)) % mod
            for j in range(2)]
            for i in range(2)]

    res  = [[1,0],[0,1]]       # 单位矩阵
    base = [[1,1],[1,0]]       # 转移矩阵 M
    while n:
        if n & 1:
            res = mul(res, base)
        base = mul(base, base)
        n >>= 1
    return res[0][1]
观察
和上一页的 pow_mod 逐行对应，只多了 mul
HOW TO怎么写转移矩阵
  1. 列出状态向量：[F(n+1), F(n)]
  2. 写转移式，看它依赖哪几项
  3. 把系数填进矩阵，就是 M

难点不在快速幂，而在把递推式写成矩阵。

应用 C：区间最值（RMQ）

MAIN换一类问题：不跳了，改问「一段区间里的最小值」。倍增在这里变身成 ST 表。

FIG.16 · RMQ：区间最值问题
THE DEAD END前缀和为什么失效

区间求和能用前缀和，是因为「减法能还原」。

但 min 没有逆运算：min(a,b) − min(a) ≠ b。

◆ 遇到「不可逆的合并」，就该想倍增
THE TURN转变的一步

既然整段不好算，就只预处理长度是 2 的幂的段。

查询时把 [l, r] 拆成两个 2 的幂的段（允许重叠），取两者的 min。

O(n log n) 预处理 · O(1) 查询
NOTICE和跳跃表的差别
跳跃表
跳位置，所以要「走到那里」
ST 表
存区间答案，所以能「直接合并」

核心动作还是「2 的幂 + 拼接」，只是拼的东西换了。

17

ST 表：两个 2 的幂，重叠没关系

MAIN查询为什么能 O(1)？关键在「允许重叠」——这一节讲清楚为什么可以重叠。

FIG.17 · 两个 2 的幂区间重叠覆盖
THE TRICK为什么允许重叠

因为 min 是「可重叠合并」的：多算几次相同元素，结果不变。

同理 max、gcd、按位与、按位或 都可以。

◆ 但 sum、xor 不行 —— 重叠会重复计入
WHY 2^k为什么取 ⌊log₂(len)⌋

取最大的、不超过 len 的 2 的幂 k。

于是 2^k ≤ len < 2^(k+1)，两个 2^k 的段必定能覆盖全长。

r − 2^k + 1 ≤ l + 2^k − 1

这就是「必然重叠」的来源。

CONTRAST和跳跃表的对照
跳跃表
拼路径，段与段不能重叠
ST 表
拼答案，段与段可以重叠

差别只在于「拼的是什么」。

ST 表：代码

MAIN一份可直接粘贴的模板。查询 O(1) 是它最大的价值。

PYTHON · ST 表（区间最小值）
class SparseTable:
    def __init__(self, a):
        n = len(a)
        self.log = [0] * (n + 1)
        for i in range(2, n + 1):
            self.log[i] = self.log[i // 2] + 1
        K = self.log[n] + 1

        self.st = [a[:]]
        for j in range(1, K):
            prev, cur, half = self.st[j-1], [], 1 << (j-1)
            for i in range(n - (1 << j) + 1):
                cur.append(min(prev[i], prev[i + half]))
            self.st.append(cur)

    def query(self, l, r):
        """返回 a[l..r] 的最小值，O(1)"""
        j = self.log[r - l + 1]
        return min(self.st[j][l], self.st[j][r - (1 << j) + 1])
O(1) 的原因
log 表提前算好，查询只有两次数组取值 + 一次 min
COMPARE三种做法对比
做法预处理查询空间
暴力O(1)O(n)O(1)
ST 表O(n log n)O(1)O(n log n)
线段树O(n)O(log n)O(n)
单调队列O(n)O(1) 均摊O(n)

ST 表适合「只问不改」；要修改就用线段树。

PITFALL三处细节
  • 查询时 j = log[r−l+1]，不是 log[r] − log[l]
  • 建表时第二层循环上限是 n − 2^j + 1，别写成 n
  • log 表要 预计算，每次调 log2 会拖慢

朴素 LCA：一步一步往上爬

PYTHON · 朴素 LCA（每次 O(深度)）
def lca_naive(u, v, parent, depth):
    # 1. 把深的那个往上提，直到同深度
    while depth[u] > depth[v]:
        u = parent[u]
    while depth[v] > depth[u]:
        v = parent[v]

    # 2. 一起往上爬，直到相遇
    while u != v:
        u = parent[u]
        v = parent[v]
    return u
问题
每个 while 都可能是 O(n)，树是一条链时最惨
WORST CASE最坏长什么样

树退化成一条链，根到叶子深 n 层。

一次查询就要爬 n 次，10⁵ 次查询 = 10¹⁰ 次。

◆ 和第 2 页那个问题，是同一个病
FIG.22 · 链状树是最坏情况
THE FIX倍增改了哪一句

把 u = parent[u] 换成 u = jump(u, 2^k)。

一次跳一大段，O(n) 立刻变 O(log n)。

这一步和链上倍增完全一样，只是换到树上。

树上倍增 LCA：三步走

MAIN这一帧建议截图。整个 LCA 的逻辑就这三步，看图记住，代码只是它的翻译。

FIG.23 · 三步走：对齐 → 一起跳 → 取父
STEP 1对齐深度

让 深的那一个往上跳 depth 差那么多步。

把差值做二进制分解，O(log) 次跳跃就到同一深度。

if (diff >> k) & 1: u = fa[k][u]
STEP 2一起上跳（最容易错）

从 最大的 k 往下试：若 fa[u][k] != fa[v][k]，就一起跳上去。

跳完之后，它们必然不相等，且一定是 LCA 的儿子。

◆ 是「不等才跳」，跳过头就找不回来了
STEP 3取父节点

循环结束时，fa[u][0] 就是答案。

因为它们已经在 LCA 的正下方了。

树上倍增 LCA：完整代码

MAIN把三步走直译成 Python。这是一份能直接提交的模板，值得抄进笔记。

PYTHON · 树上倍增 LCA 模板
import sys
from collections import deque

def build_lca(g, n, root=0):
    K = (n+1).bit_length()
    fa = [[-1]*n for _ in range(K)]
    depth = [0]*n

    q = deque([root]); seen = [False]*n; seen[root]=True
    while q:                          # BFS 求深度 + 父节点
        u = q.popleft()
        for v in g[u]:
            if not seen[v]:
                seen[v] = True
                depth[v] = depth[u] + 1
                fa[0][v] = u
                q.append(v)

    for k in range(1, K):         # 倍增递推
        for v in range(n):
            mid = fa[k-1][v]
            if mid != -1:
                fa[k][v] = fa[k-1][mid]
    return fa, depth

def lca(u, v, fa, depth):
    K = len(fa)
    if depth[u] < depth[v]: u, v = v, u
    diff = depth[u] - depth[v]

    for k in range(K):          # ① 对齐深度
        if diff >> k & 1:
            u = fa[k][u]

    if u == v: return u

    for k in range(K-1, -1, -1): # ② 一起上跳
        if fa[k][u] != fa[k][v]:
            u, v = fa[k][u], fa[k][v]
    return fa[0][u]               # ③ 取父
COMPLEXITY代价
建表
O(n log n)　BFS O(n) + 递推 O(n log n)
查询
O(log n)　两个 for
空间
O(n log n)　fa[K][n]
TRAPS五处必检查
  • ② 的循环 必须从大到小，反了会跳过头
  • ② 判的是 !=，写成 == 就全错了
  • ③ 返回 fa[0][u]，不是 u
  • 根节点 fa[0][root] = -1，别设成自己
  • u == v 时提前返回，否则会被跳到根的父
EXTRA顺手得到 k 级祖先

把「对齐深度」那段单独拿出来，就是求第 k 个祖先。

应用 E：树上距离 / 路径最值

PYTHON · 距离 + 路径最大边权
# 距离：一行搞定
def dist(u, v, fa, depth):
    w = lca(u, v, fa, depth)
    return depth[u] + depth[v] - 2*depth[w]

# 路径最大边权：再多存一层
# mx[k][v] = v 向上跳 2^k 这条链上的最大边权
# 递推：
# mx[k][v] = max(mx[k-1][v], mx[k-1][ fa[k-1][v] ])

def path_max(u, v, fa, mx, depth):
    res = 0
    if depth[u] < depth[v]: u, v = v, u
    diff = depth[u] - depth[v]
    for k in range(len(fa)):
        if diff >> k & 1:
            res = max(res, mx[k][u])
            u = fa[k][u]
    if u == v: return res
    for k in range(len(fa)-1, -1, -1):
        if fa[k][u] != fa[k][v]:
            res = max(res, mx[k][u], mx[k][v])
            u, v = fa[k][u], fa[k][v]
    return max(res, mx[0][u], mx[0][v])

WHY为什么可以这样算

PYTHON · 树上路径和
def build_sum(g, w, n, root=0):
    """w[u][v] : 边 (u,v) 的权；返回 s[] 与 LCA 表"""
    s = [0]*n
    fa, depth = build_lca(g, n, root)   # 复用第 24 页
    q = deque([root]); seen=[False]*n; seen[root]=True
    while q:
        u = q.popleft()
        for v in g[u]:
            if not seen[v]:
                seen[v] = True
                s[v] = s[u] + w[u][v]   # 前缀和
                q.append(v)
    return s, fa, depth

def path_sum(u, v, s, fa, depth):
    L = lca(u, v, fa, depth)
    return s[u] + s[v] - 2*s[L]

★ 树上差分：路径打标记，最后一次性求和

★ OPTIONAL如果给 m 条路径各 +1，最后问每条边被经过几次？暴力是 O(m·n)。

FIG.27 · 树上差分：四个标记 + 一次 DFS
WHY为什么要减两次

因为 u 和 v 各把「根 → LCA」那条链加了一次，等于多加了两遍。

所以 LCA 处 −1、LCA 的父 −1，正好抵消。

PYTHON · 树上差分模板
def path_add(u, v, d, fa, depth):
    L = lca(u, v, fa, depth)
    d[u] += 1
    d[v] += 1
    d[L] -= 1
    if fa[0][L] != -1:
        d[fa[0][L]] -= 1

# 最后一次 DFS 求子树和，得到每条边的答案
def dfs_sum(u, par, g, d):
    for v in g[u]:
        if v != par:
            dfs_sum(v, u, g, d)
            d[u] += d[v]
    return d          # d[u] = u 到父这条边被经过次数
复杂度
m 条路径 + 一次 DFS：O(m log n + n)，而不是 O(m·n)
PITFALL两个常见错点
  • 问点的次数时，不要再减 parent(LCA)，只减 LCA
  • 问边的次数时，要减两次（如模板）

看清题目问的是「点」还是「边」。

★ Kruskal 重构树：把「边权最小值」变成「祖先」

PYTHON · Kruskal 重构树骨架
def build_kruskal(edges, n):
    """edges: [(w, u, v)]，返回重构树与点权"""
    edges.sort()                     # 按边权升序
    fa = list(range(2*n))
    wval = [0]*(2*n)
    g = [[] for _ in range(2*n)]
    cnt = n

    for w, u, v in edges:
        ru, rv = find(u), find(v)
        if ru == rv: continue
        cnt += 1
        wval[cnt] = w                 # 虚点点权 = 边权
        g[cnt] += [ru, rv]
        fa[ru] = fa[rv] = cnt
    return g, wval, cnt

★ 倍增二分：找第一个「合法」的位置

★ OPTIONAL倍增不止能跳「已知的点」，还能跳「未知的答案」。这就是 staircase walking。

FIG.30 · 倍增扩界 + 二分收界
PYTHON · 倍增二分（exponential search）
def first_true(f, hi):
    """f 单调：False...False True...True
    返回最小的 x (0<x≤hi) 使 f(x) 为 True
    全为 False 时返回 hi+1"""
    if f(1): return 1

    step = 1
    while step <= hi and not f(step):
        step <<= 1            # 倍增扩上界

    lo, hi2 = step >> 1, min(step, hi)
    while lo + 1 < hi2:      # 二分收界
        mid = (lo + hi2) >> 1
        if f(mid): hi2 = mid
        else:      lo = mid
    return hi2 if hi2 <= hi and f(hi2) else hi + 1

纯二分倍增二分
需要右端必须知道不用
判定次数log(R−L)log 答案
代码更短略长

七个最常见的坑

MAIN倍增代码不长，但坑很密。逐条对号入座，能省你几个小时。

WRONG会直接出错的四处
  • LCA 一起上跳时从低位往高位枚举 k
  • 把 fa[k][u] != fa[k][v] 写成 ==
  • ST 表建表循环写成 range(n)，越界
  • 忘了 根节点的父节点要标 −1
TLE / MLE会超时或爆内存的三处

  • Python 用二维 list 存大表，内存超限
  • ST 表查询时调 math.log2，应预处理 log 数组
SAFE HABITS四个好习惯
  • 建表永远 k 从小到大，查询「一起跳」永远 从大到小
  • 先写 depth 和 fa[0]，再写倍增递推，分两步走
  • 越界用 -1 统一表示，每次跳完都判一次
  • 大表用 array 或拍平成一维，省内存

  2. depth 是不是从根开始 +1？
  3. 「一起上跳」的 k 是不是从大到小？
  4. 返回的是 fa[0][u] 还是 u？

for j in range(1, K):
    for i in range(n - (1<<j) + 1):
        st[j][i] = min(st[j-1][i],
                       st[j-1][i + (1<<(j-1))])

def q(l, r):
    j = log[r-l+1]
    return min(st[j][l], st[j][r-(1<<j)+1])
B · LCA 三步（背熟可直接默写）
# ① 对齐深度
if depth[u] < depth[v]: u, v = v, u
diff = depth[u] - depth[v]
for k in range(K):
    if diff >> k & 1:
        u = fa[k][u]

if u == v: return u

# ② 一起上跳（从大到小！）
for k in range(K-1, -1, -1):
    if fa[k][u] != fa[k][v]:
        u, v = fa[k][u], fa[k][v]

# ③ 取父
return fa[0][u]

★ 调试与对拍：写错时怎么办

★ OPTIONAL倍增很容易写出「答案差一点点」的错。掌握对拍，能省下半天。

DATA三类必造的数据
  • 链：1→2→3→…→n，最坏深度
  • 星：根连所有点，最浅深度
  • 随机：随机父子关系，覆盖中间情形

倍增的错在小数据上往往看不出来，一定要造大数据。

CHECK输出中间量
print('depth:', depth[:10])
print('fa[0]:', fa[0][:10])
print('fa[1]:', fa[1][:10])

PYTHON · 对拍脚本骨架
import random, subprocess

def gen(n):
    """生成随机树（节点 1..n）"""
    edges = []
    for i in range(2, n+1):
        edges.append((random.randint(1, i-1), i))
    random.shuffle(edges)
    return n, edges

def run(exe, data):
    p = subprocess.run([exe], input=data, text=True,
                       capture_output=True)
    return p.stdout.strip()

for t in range(100):
    n = random.randint(1, 30)      # 先用小数据
    data = encode(gen(n))
    a, b = run('./fast', data), run('./brute', data)
    if a != b:
        print('WRONG on', data)
        break
原则
先小数据跑通，再上大数据压力
BRUTE暴力参考实现的要求
  • 暴力必须简单到不可能错，哪怕 O(n²)
  • 暴力和正解读同一份输入、输出同一格式
  • 倍增的暴力就是一步一步爬，见第 22 页
MINDSET调试心态

不要一次改多处。倍增的错通常只有一两行，逐行对照模板最有效。
