堆是什么：半有序，不是全有序

一个大顶堆，唯一的承诺是「每个节点 ≥ 它的孩子」。它明确不承诺兄弟之间的顺序。

FIG.a · 大顶堆：父 ≥ 孩子，但兄弟乱序

AUX和「有序数组」对比

有序数组 全有序 —— 任意两个元素都能比。
插入 O(n)，取最值 O(1)。
堆 半有序 —— 只保证「父 ≥ 孩」。
插入 O(log n)，取最值 O(log n)。

堆用牺牲「兄弟顺序」，换来 O(log n) 插入 + O(log n) 删除。这就是它的全部卖点。

MAIN堆 vs 平衡树 / 跳表

三者都支持「按大小顺序取出」。堆常数最小、代码最短、最省内存，但只给最值。
平衡树 / 跳表能给完整顺序，但实现成本高、常数大。
面试里 90% 的题，堆就够。

CASE为什么叫「半有序」

把堆完全排序，成本 O(n log n)；
但只要「谁最大」，堆给的是 O(1)。
它精确地只做你真正需要的那一件事。

父 ≥ 孩子 兄弟无序 半有序结构 卖点 = O(log n) 双操作

数组存树：下标公式 与三个关键量

堆不是链式树，它压在数组里。所以父子关系算得出来，不用存指针。

FIG.a · 堆压在数组里：树 = 数组，父子关系 = 下标运算

MAIN关键 ① 不用指针

因为是完全二叉树，形状是锁死的，所以父子位置算得出来。
好处：不用左右指针，每个节点只存值，整体数组连续 → 缓存友好、常数小。

CASE关键 ② 那个 //2

0-based 下 (i-1)//2，1-based 下 i//2。
差一个括号，整个 sift-up 会指向错的父节点 —— 这是最常见的实现 bug。

parent = (i-1)//2 left = 2i+1 right = 2i+2 完全二叉树 无指针 (i-1)//2 ← 少个括号就错

04

两条规则：形状 与 数值，必须分清

初学者最容易把「形状规则」和「数值规则」混成一条。分开记，代码就清楚了。

规则 ① · 形状
完全二叉树除了最后一层，其余每层都满；最后一层从左往右连续填充，不留空洞。
规则 ② · 数值
父 ≥ 孩子每个节点都 ≥（或 ≤）它的孩子。大顶堆取 ≥，小顶堆取 ≤。
两条独立
互不推导形状合法 ≠ 数值合法。数值合法 ≠ 形状合法。两条要同时成立才叫堆。
FIG.a · 两个维度，各自可以单独坏掉

AUX大顶堆 vs 小顶堆

大顶堆：parent ≥ child → 堆顶 = 最大。
小顶堆：parent ≤ child → 堆顶 = 最小。
两者代码完全对称，只差一个比较符号。

MAIN为什么形状要锁死

形状锁死 → 树高 = ⌊log₂ n⌋ + 1，且数组无空洞。
这保证了：任何一次上浮 / 下沉，最多走 O(log n) 层。
形状是「效率保证」的来源。

AUX为什么数值只要「父子」

因为只要最值。根节点天然就是最值。
不需要兄弟有序 → 不需要旋转、不需要回溯。
这就是堆比平衡树简单一个数量级的原因。

父 ≥ 孩子 完全二叉树 两条独立 形状锁死 → 树高可控

复杂度 O(log n) 是怎么来的

不是背的，是数层高数出来的。记住这一个数字，后面所有优化都围绕它展开。

FIG.a · 树高 log n，路径长 log n
O(1)
取堆顶 peek
O(log n)
push 上浮
O(log n)
pop 下沉
O(n)
heapify 建堆

MAIN为什么建堆是 O(n) 而不是 O(n log n)

自底向上下沉，底层节点多但下沉次数少，顶层节点少但下沉次数多。
求和 ∑ (n/2^(h+1)) · h = O(n)。
这就是「一次性建堆 + 反复 pop」比「n 次 push」快的原因。

AUXheapq 默认是小顶堆

没有内置大顶堆。取负（-x）模拟。
代价：元组比较会反、abs 场景会错 —— 第 11 页详解。

AUX优先队列接口

push / pop / peek 三个动作。
C++ 是 priority_queue，Java 是 PriorityQueue，Python 是 heapq。

peek O(1) push/pop O(log n) heapify O(n) 树高 = log n heapq 是小顶堆

06

插入（sift-up）：放在末尾，向上冒

插入只有一个动作：丢到末尾，然后不停和父比、和父换，直到不能再换。

FIG.a · 一次插入最多走树高 h = ⌊log₂ n⌋ 步
PYTHON · sift-up
def _sift_up(a, i):
    """把 a[i] 往上浮，直到父 <= 它"""
    while i > 0:
        p = (i - 1) // 2          # 父下标
        if a[p] >= a[i]:
            break                 # 已合法，停
        a[p], a[i] = a[i], a[p]   # 和父换
        i = p                    # 继续向上
PYTHON · heapq 的等价写法
import heapq
heap = []
for x in nums:
    heapq.heappush(heap, x)   # = 内部 sift-up

CASE手写时的三个坑

  • 父下标公式：0-based 是 (i-1)//2，1-based 是 i//2
  • 循环条件：i > 0，不是 i >= 0
  • 比较方向：小顶堆是 if a[p] <= a[i]: break
末尾插入 上浮 log n 步 父下标 (i-1)//2 比较方向别写反

弹出堆顶（sift-down）：末尾补根，向下沉

弹出不是删掉根就完事。删掉根会留下空洞 —— 必须用末尾元素补上，再让它下沉。

FIG.a · [10,7,8,2,6,5] 弹出 10 的三步
STEP 1 取走 10 STEP 2 末尾 5 补根 STEP 3 沉到合法
PYTHON · sift-down
def _sift_down(a, i, n):
    """把 a[i] 往下沉，直到孩子 <= 它"""
    while True:
        l, r = 2*i+1, 2*i+2
        big = i
        if l < n and a[l] > a[big]: big = l
        if r < n and a[r] > a[big]: big = r
        if big == i:
            break               # 已合法
        a[i], a[big] = a[big], a[i]
        i = big                # 继续向下

def pop_max(a):
    n = len(a)
    a[0], a[n-1] = a[n-1], a[0]
    top = a.pop()              # 取走最大
    _sift_down(a, 0, len(a))
    return top
WHY 为什么「必须」用末尾补根？因为形状规则要求完全二叉树。直接删根会让数组少一个位置，形状就不合法了。末尾补上是唯一不破坏形状的做法。

CASE为什么是「和较大的孩子」换

堆性质只要求 parent ≥ child。
如果和较小的孩子换，换完后父 仍小于另一个孩子 —— 还是不合法。
必须换「最大的那个孩子」，一步到位。

末尾补根 下沉 log n 步 和「较大的孩子」换 别和较小的换 比较方向决定对错

建堆 heapify：自底向上，O(n)

从最后一个非叶节点开始，倒着对每个节点做 sift-down。不用一个一个 push。

FIG.a · [4,1,3,2,16,9,10,14,8,7] 的 heapify 过程
起点 = last parent 下沉到底就停 根天然合法
PYTHON · heapify
def build_max_heap(a):
    n = len(a)
    # 最后一个非叶节点 = (n-2)//2
    for i in range((n-2)//2, -1, -1):
        _sift_down(a, i, n)
    return a
PYTHON · heapq
heapq.heapify(a)          # 一行，O(n)
# 反例（慢 3 倍以上）：
h = []
for x in a:
    heapq.heappush(h, x)  # O(n log n)
WHY O(n) 底层节点多但下沉短，顶层节点少但下沉长。
∑ (n / 2^(h+1)) · h = O(n)
从 h=0 到 h=log n 求和，等比数列收敛到 2n 以内。

AUX起点记法

last parent = 最后一个有孩子的下标。
0-based：(n-2)//2
反过来写：n//2 - 1（等价）

heapify = O(n) n 次 push = O(n log n) 起点 = last parent (n-2)//2 别写成 n//2 倒着来

应用 ① TopK：小顶堆存「最大的 k 个」

反直觉之处：求最大的 k 个，用的是小顶堆。因为堆顶要当「淘汰门槛」。

FIG.a · 已处理 5 个数，堆里只剩 3 个
PYTHON · TopK（最小堆）
def top_k(nums, k):
    """返回最大的 k 个元素，O(n log k)"""
    heap = []
    for x in nums:
        if len(heap) < k:
            heapq.heappush(heap, x)
        elif x > heap[0]:
            heapq.heapreplace(heap, x)  # pop+push
    return heap
PYTHON · 流式版本（在线）
class KthLargest:
    def __init__(self, k, nums):
        self.k = k; self.h = []
        for x in nums: self.add(x)

    def add(self, val):
        if len(self.h) < self.k:
            heapq.heappush(self.h, val)
        elif val > self.h[0]:
            heapq.heapreplace(self.h, val)
        return self.h[0]

CASE一句话秘诀

「小顶堆的堆顶」= 前 k 大里最小的那个 = 门槛。
新元素 > 门槛 才有资格换掉它。

AUX三个坑

  • 搞成大顶堆 → 空间退化到 O(n)
  • 用 heapreplace 前忘了判空 → 报错
  • 返回 堆顶还是 整堆？看题目要求
PROBLEM
数据太大装不下n 很大、或数据在线到达
INSIGHT
只需记住「第 k 大」这个门槛其余都是噪音
METHOD
小顶堆只留 k 个，比堆顶大才换入O(n log k) 时间 · O(k) 空间
TopK = 小顶堆 堆顶 = 门槛 O(n log k) heapreplace 别用大顶堆

应用 ② 多路归并：合并 K 个有序序列

把「k 个序列各自看头」→ 换成「一个小顶堆装 k 个头」。
时间从 O(nk) 降到 O(n log k)。

FIG.a · 堆里始终只有 k 个元素
PYTHON · merge k sorted
def merge_k(lists):
    """合并 k 个有序链表 / 数组"""
    heap = []
    for i, lst in enumerate(lists):
        if lst:
            heapq.heappush(heap, (lst[0], i, 0))

    res = []
    while heap:
        val, i, j = heapq.heappop(heap)
        res.append(val)
        if j + 1 < len(lists[i]):
            nxt = lists[i][j+1]
            heapq.heappush(heap, (nxt, i, j+1))
    return res

MAIN三元组 (val, i, j) 的意义

val 用来比大小；
i 记住它来自哪个序列；
j 记住是第几个元素，用于推进。
少一个就走不下去。

应用 ③ 贪心 + 堆：会议室 II / 分配饼干

贪心负责「怎么选」，堆负责「每次挑出最值得的那个」。分工明确。

会议 · 会议室 II
按开始排序，维护结束时间的小顶堆新会议开始时堆顶已结束 → 复用该房间；否则新开。
饼干 · 分配饼干
两个数组都排序，贪心满足最小的饼干满足最小胃口的孩子；不够就换更大的饼干。
共同点
每一步都选局部最优堆只用来「快速找出当前最值得的那个」。
PYTHON · 会议室 II
def min_meeting_rooms(meetings):
    meetings.sort(key=lambda x: x[0])  # 按开始
    ends = []                         # 小顶堆
    for s, e in meetings:
        if ends and ends[0] <= s:
            heapq.heappop(ends)       # 复用
        heapq.heappush(ends, e)
    return len(ends)
WHY 堆里装的是「当前所有正在进行的会议的结束时间」。堆顶是最早结束的那间。
如果它都来不及，别的更来不及。这就是贪心正确性的来源。
PYTHON · 分配饼干
def find_content_children(g, s):
    g.sort(); s.sort()
    i = j = 0
    while i < len(g) and j < len(s):
        if s[j] >= g[i]:
            i += 1                 # 满足
        j += 1                     # 无论是否满足都换饼干
    return i

MAIN怎么识别「贪心 + 堆」

  • 题面有 「同时进行」「最少资源」「最小代价」
  • 每一步只需 「当前最值」 就能决策
  • 决策后 状态只变一点（一个元素进出）

排序是「一次性排好」；
堆是「边走边维护当前最优」。

应用 ④ Dijkstra：从 O(n²) 到 O(m log n)

朴素 Dijkstra 每轮扫一遍找最小；用堆之后最小现成的，直接取。

FIG.a · 堆里装「候选点 + 当前最短距离」
PYTHON · Dijkstra
def dijkstra(graph, src):
    dist = {src: 0}
    pq = [(0, src)]
    while pq:
        d, u = heapq.heappop(pq)
        if d > dist.get(u, 1e18):
            continue            # 惰性删除
        for v, w in graph[u]:
            nd = d + w
            if nd < dist.get(v, 1e18):
                dist[v] = nd
                heapq.heappush(pq, (nd, v))
    return dist
WHY 堆顶的 d 就是当前能确定的最短距离。
贪心正确：因为边权非负，后面的候选只会更长。
「if d > dist.get(u)」是惰性删除，替代 decrease-key。

AUX三个坑

  • 忘写 惰性删除的 continue → 重复扩展，慢但不错
  • 边权有负数 → 不能用 Dijkstra
  • push 了 (u, nd) 而不是 (nd, u) → 按点比了

应用 ⑤ 贪心进阶：跳跃游戏 II / IPO

这类题的共同形状：「在能力范围内，挑一个最值」。堆把这个「挑」从 O(n) 变 O(log n)。

跳跃游戏 II
在当前可达范围内，取能跳最远的每跳一步，边界更新一次。经典区间贪心。
IPO
资本够时，取利润最大的项目两个堆：一个按利润、一个按资本。反复切换。
本质
「可选集」里挑最值可选集会变化 → 静态排序不行 → 用堆。
PYTHON · IPO（双堆）
def find_maximized_capital(k, W, profits, capital):
    projects = sorted(zip(capital, profits))
    i = 0; n = len(projects)
    able = []                          # 大顶堆（取负）
    for _ in range(k):
        while i < n and projects[i][0] <= W:
            heapq.heappush(able, -projects[i][1])
            i += 1
        if not able:
            break
        W += -heapq.heappop(able)
    return W
WHY 双堆 「按资本排」的数组负责往 able 里加；
「按利润」的大顶堆负责从中挑最大。
两者各司其职，总复杂度 O(n log n)。
PYTHON · 跳跃游戏 II
def jump(nums):
    res = cur_end = far = 0
    for i in range(len(nums) - 1):
        far = max(far, i + nums[i])
        if i == cur_end:
            res += 1; cur_end = far
    return res

「范围在变，要挑最值」→ 堆。
「范围固定，要挑最值」→ 排序或扫描。

IPO 的「能做的项目集」随资本增长 —— 范围在变 → 堆。
分配饼干的「孩子的胃口集」固定 —— 排序即可。

应用 ⑥ 哈夫曼 / 合并果子：最小代价合并

每次合并最小的两堆，代价 = 两堆之和。小顶堆 + 贪心，一行公式就通。

FIG.a · 小顶堆，每次弹两个最小
PYTHON · 合并果子 / 哈夫曼
def min_merge_cost(weights):
    """合并果子：求最小总代价"""
    h = weights[:]
    heapq.heapify(h)             # O(n)
    cost = 0
    while len(h) > 1:
        a = heapq.heappop(h)
        b = heapq.heappop(h)
        s = a + b
        cost += s
        heapq.heappush(h, s)     # 推回去
    return cost
PYTHON · 哈夫曼编码长度
def huffman_length(freq):
    h = freq[:]
    heapq.heapify(h)
    total = 0
    while len(h) > 1:
        a = heapq.heappop(h)
        b = heapq.heappop(h)
        total += a + b           # 加权路径长
        heapq.heappush(h, a+b)
    return total

MAIN为什么贪心对

每次合并，两堆都会被后续所有合并再计一次。
所以小的要尽早合并，让它的「乘数」小。
这就是贪心正确性。

AUX坑

  • 忘记把和 push 回堆 → 只合并一次
  • 用大顶堆 → 贪心方向反了
  • 只有一个元素时没提前返回 → 多算
小顶堆 每次弹两个 push 回去 大顶堆反向 哈夫曼

应用 ⑦ 对顶堆：动态维护中位数

两个堆互相顶住：左大顶、右小顶。中位数 = 对顶的那两个数。

FIG.a · 两堆对顶，中位数在对顶之间
PYTHON · MedianFinder
class MedianFinder:
    def __init__(self):
        self.lo = []  # 大顶堆（取负）
        self.hi = []  # 小顶堆

    def addNum(self, num):
        heapq.heappush(self.lo, -num)
        heapq.heappush(self.hi, -heapq.heappop(self.lo))
        if len(self.hi) > len(self.lo):
            heapq.heappush(self.lo, -heapq.heappop(self.hi))

    def findMedian(self):
        if len(self.lo) > len(self.hi):
            return -self.lo[0]
        return (-self.lo[0] + self.hi[0]) / 2
INVARIANT ① len(lo) >= len(hi) 且 len(lo) - len(hi) <= 1
② lo[0] <= hi[0]
两条同时成立 → 中位数就只看堆顶，O(1) 查询。

堆排序：不稳定 O(n log n)，原地

两步：建大顶堆 → 反复 pop 到末尾。因为是原地，所以不需要额外数组。

FIG.a · 末尾区间逐渐变长，堆区间逐渐变短
PYTHON · 堆排序
def heap_sort(a):
    n = len(a)
    # 1) 建大顶堆 O(n)
    for i in range((n-2)//2, -1, -1):
        _sift_down(a, i, n)
    # 2) 反复 pop 到末尾 O(n log n)
    for end in range(n-1, 0, -1):
        a[0], a[end] = a[end], a[0]
        _sift_down(a, 0, end)
    return a

MAIN为什么是「不稳定」

因为交换会跨位置。
堆只保证父 ≥ 孩，兄弟之间没有顺序 —— 相等元素的位置可能被打乱。
要稳定 → 用归并；要省空间 → 用堆排序或快排。

import heapq
def top_k(nums, k):
    h = []
    for x in nums:
        if len(h) < k:
            heapq.heappush(h, x)
        elif x > h[0]:
            heapq.heapreplace(h, x)
    return h

AUX秒杀脚本（合并 K 路）

def merge_k(lists):
    h = [(l[0], i, 0) for i, l in enumerate(lists) if l]
    heapq.heapify(h)
    res = []
    while h:
        v, i, j = heapq.heappop(h)
        res.append(v)
        if j+1 < len(lists[i]):
            heapq.heappush(h, (lists[i][j+1], i, j+1))
    return res

lo, hi = [], []

    if len(hi) > len(lo):
        heapq.heappush(lo, -heapq.heappop(hi))
