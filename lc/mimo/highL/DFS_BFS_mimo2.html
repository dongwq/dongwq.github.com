★统一模型

所有题都在问："从某个状态出发，能到达哪些状态？以什么次序？" 而答案永远来自两个集合 —— 已访问集 S 与 边界集 F，区别只在"从 F 里取谁"。

判断口诀：问"最短/最少步" → BFS；问"能否/存在/全部" → DFS；问"先后顺序" → 拓扑；问"分组" → 染色。

01 · MODEL

遍历 = 维护两个集合，差别只在取谁

本页回答：DFS 与 BFS 的本质差别？
为什么说"数据结构决定次序"。

1两个集合

S = 已经访问过的点；F = 已经碰到但还没展开的点（frontier，边界）。

不变量：F 中的点都与 S 相邻；每个点至多进入 F 一次

2一次循环

  • 从 F 取出一个点 u（放进 S）
  • 枚举 u 的邻居，未访问的加进 F
  • 重复到 F 为空

3取谁？

F 的实现次序名字
栈 LIFO深度优先DFS
队列 FIFO按层递增BFS
双端队列0-1 代价0-1 BFS
优先队列按距离Dijkstra
一句话：DFS/BFS 不是两个算法，而是同一个骨架的两种取点策略；理解这一点，0-1 BFS、Dijkstra 都是"顺手的推广"。

一个不变量，四个旋钮

什么绝对不能错。

A取点结构

栈 / 队列 / 双端 / 优先队列 —— 决定探索次序。

B标记时机

入队时标记（防重复入队）还是出队时标记（可见性不同）。

C邻居次序

递归版与迭代版要用 reversed() 才同序；要字典序就先排序。

D附加信息

距离、父指针、颜色、时间戳、层号 —— 决定能回答什么。

不变量（写完自查）

  • 每个点至多被"展开"一次（否则会退化）
  • 标记与展开的时机一致：不重复、不遗漏
  • 起点先标记再入队/入栈
  • 不连通时要对每个未访问点重启一次

心智模型

遍历是在状态空间里"刷油漆"：每次取一个没刷过的格子，把它相邻的格子排进队伍。刷的顺序就是算法。

01 · DFS

DFS：一条路走到黑，撞墙再回头

本页回答：DFS 的次序长什么样？
为什么会自然产生"前序/后序"。

两个次序

  • 前序：进入节点时记录（访问顺序）
  • 后序：离开节点时记录（子树处理完）
  • 后序的逆 = 拓扑序（DAG 上）

递归 = 隐式栈

递归版本里"栈帧"就是你的栈；所以递归写法最短，但有爆栈风险。

直觉：DFS 的次序是"尽量深"；这给了它回溯、判环、找连通分量、求 SCC 的天然优势。
回边的意义：遇到已访问的邻居，说明是回边/横边；判环、找桥、求 SCC 全靠这一刻。

01 · BFS

BFS：一圈一圈往外刷

本页回答：为什么 BFS 能求最短？
"层"是怎么产生的。

分层的由来

  • 起点在第 0 层
  • 第 k 层的点，邻居未访问的都在 第 k+1 层
  • 第一次到达某点时，层数就是最短距离

为什么是最短

队列中的距离单调不减；
故第一次弹出 u 时的 dist[u] 即最短
直觉：BFS 是"按距离从小到大"的取点策略 —— 所以它天然是边权为 1 时的 Dijkstra。
记住：BFS 的层号 = 最短距离，这是它和 DFS 最本质的功能差别。

01 · EDGES

DFS 顺带给出边的分类

本页回答：四类边各是什么？
为什么只 DFS 能分、BFS 分不了？

四类边（有向图）

名字方向含义
树边→ 未访问构成 DFS 树
回边→ 祖先有环的证据
前向边→ 后代冗余
横边→ 旁支跨子树

无向图更简单

只有树边与回边（指回非父的已访问点）。桥/割点判定正建立在这一点上。

判定法：记 dfn（进入时刻）：指向更小 dfn 且在栈上 → 回边；指向更大 dfn 且已完成 → 前向/横边。
为什么 BFS 分不干净：BFS 树上可能出现"跨层"的边，前向/回边的界定不如 dfn 天然。
01 · TIMESTAMPS

dfn / fin：把遍历写成括号

本页回答：时间戳有什么用？
"括号化定理"说了什么。

两个时间戳

dfn[u] = 进入 u 的时刻
fin[u] = 离开 u 的时刻（子树处理完）

一个点的活跃期是区间 [dfn, fin]，整个 DFS 形成嵌套括号。

括号化定理

  • u 是 v 的祖先 ⟺ dfn[u] ≤ dfn[v] < fin[u]（区间包含）
  • 两区间互不包含 ⟺ 两棵不相交子树
  • 后代的 dfn 一定更大
用途：判祖先、找 LCA、求子树大小、SCC 的 low 值 —— 全部基于 dfn。

02 · COMPONENTS

连通块计数：三种写法

本页回答：DFS、BFS、并查集怎么选？
各有什么附加价值。

1DFS

写法：外层循环 + 递归染色。每启动一次 = 新块。

附加：顺带得到块内节点、拓扑序、dfn。

2BFS

写法：同上但用队列。天然给出块内距离场。

附加：块内最短路、块的"直径"近似。

3并查集

写法：合并边，最后数代表元。

附加：支持增量加边、块大小、动态查询。

选型

  • 一次性静态图 → DFS/BFS（更直观）
  • 边陆续加入、要在线回答 → 并查集
  • 要块内最短距离 → BFS
  • 要块内结构（树/序）→ DFS

计数不变量

块数 = 启动遍历的次数
= 未访问点中 dfs 启动次数

03 · SHORTEST

无权最短路：BFS 的主场

本页回答：为什么第一次到达即最优？
路径条数怎么数？

为什么正确

队列中 dist 单调不减
⇒ 第一次访问 u 时，dist[u] 就是最短路

因此不能先入队再松弛成更小值；只能一次性确定。

最短路径条数

  • cnt[v] = 到 v 的最短路条数
  • 第一次到达 v：cnt[v] = cnt[u]
  • 再次到达且 dist 相等：累加 cnt[u]

注意取模，别用 DFS 数（会指数爆炸）。

不可达怎么表示

用 -1 或 INF 初始化；输出前一定要判。

常见变形

  • 走 K 步内能到吗 → dist ≤ K
  • 只能转弯若干次 → 状态里带上方向
  • 带钥匙/门 → 状态里带上钥匙集合（状压 BFS）
状态设计是关键：当"点"不够表达时，把(点, 附加状态) 当作新节点，再 BFS。
03 · MULTI-SOURCE

多源 BFS / 反向 BFS：换个起点看

本页回答：多源怎么写？
什么时候反向搜索更好。

多源 BFS

做法：把所有源点一次性入队，dist = 0。等价于加一个"超级源点"连向所有源（边权 0）。

典型：腐烂橘子、距离场（01 矩阵）、多起点扩散。

反向 BFS

做法：从目标集出发往回搜。适用于"多个终点、一个起点"或"能到海边吗"这类问题。

典型：太平洋大西洋水流、能逃出的出口。

好处：把 O(起点数 × V) 的重复搜索压成一次。

03 · UPGRADE

一条升级链：BFS → 0-1 → Dijkstra

本页回答：为什么它们是同一族？
该在哪一档停下。
边权特征取点结构复杂度代表问题
全为 1队列 FIFOO(V+E)最少步数、迷宫
只有 0 / 1双端队列O(V+E)改一次代价、免费通道
小整数 (≤ C)桶（Radix）O(V+E+C)小权图最短路
非负任意优先队列O((V+E) log V)Dijkstra
可能负权、无负环队列 + 松弛O(VE)Bellman-Ford / SPFA
全源矩阵O(V³)Floyd

多源 = 虚拟源点

把所有源点同时入队（dist = 0），等价于加一个超级源点连边权 0 的边 —— 省掉建图。

该停在哪一档

不要见到最短路就上 Dijkstra。先看边权：全 1 用 BFS、0/1 用双端队列，代码更短更快。

共同点：都是"从边界集里挑当前代价最小的点展开"；BFS 的代价 = 层数，所以它是 Dijkstra 的特例。

04 · TOPO DFS

拓扑排序：后序取反

本页回答：为什么逆后序是拓扑序？
怎么判环。

为什么对

节点 u 在子树全部处理完后才进后序列表；所以 u 一定排在它的后代之后，反转后就排在前面 ⇒ 拓扑序。

判环

visited = 0 未访问 · 1 在递归栈上 · 2 完成
指向 1 的边 = 回边 ⇒ 有环
顺带产出：后序本身还给出"子树处理完成的顺序"，可用于 SCC（Tarjan）。
topo_dfs.pyPYTHON
04 · KAHN

Kahn 算法：BFS 的拓扑

本页回答：入度数组怎么用？
为什么它能同时求"字典序最小"。

做法

  • 入度为 0 的点入队
  • 取出 u 输出，把 u 的出边"删除"（入度 −1）
  • 新的 0 入度入队；重复

三种用法

  • 判环：len(order) < n 即有环
  • 字典序最小：把队列换成最小堆
  • 分层求"最长路"：第几轮出队 = 拓扑层
对比：Kahn 便于并行/分层与字典序；DFS 版代码短，且给后序。
kahn.pyPYTHON
04 · DAG DP

拓扑序就是递推序

本页回答：DAG 上怎么 DP？
最长路、方案数怎么写。

套路

拿到拓扑序后，按序逐点松弛：状态只依赖前驱，天然无后效性。

最长路：dp[v] = max(dp[v], dp[u] + cost[v])
方案数：ways[v] += ways[u]（取模）

常见应用

  • 课程表的"最少学期数"（= 拓扑层数）
  • 选课的最大收益
  • 编译顺序、任务调度
提醒：若要求最长路径且图有环 → NP 难；先判环。

05 · CUT & BRIDGE

割点与桥：low 的意义

本页回答：low[u] 是什么？
两个判据为何一字之差。

low[u] 的定义

low[u] = u 及其子树经回边能到达的最小 dfn

两个判据

  • 桥：low[v] > dfn[u]（严格大于）
  • 割点（非根）：low[v] ≥ dfn[u]（大于等于）
  • 割点（根）：子树数 ≥ 2
重边陷阱：用 v != parent 判回边会把"反向重边"当成回边；要按边的编号去重。

本页回答：栈与 onstack 的作用？
缩点之后能做什么。

  • dfn / low：同割点

应用

缩点后是 DAG：求条件可达性、2-SAT、求最少加几条边使之强连通。

06 · STATE SPACE

状态空间 BFS：把状态当节点

本页回答：怎么把棋盘/字符串变成图？
状态数怎么估。

三步走

  • 定义状态：能唯一描述局面的最小元组（如 3×3 棋盘的排列）
  • 定义转移：一个操作 = 一条边
  • 去重：状态用 str / tuple / 位压缩 作 visited 键

状态数估算

滑动谜题 3×3：9! = 362880，BFS 可行
华容道 4×4：16! ≈ 2×10¹³，必须剪枝/ A*

典型题

  • 单词接龙（字符串）
  • 开锁 / 转盘锁（数字元组）
  • 滑动谜题（棋盘排列）
  • 带钥匙的门（点 × 钥匙集合，状压）
成本思维：BFS 的代价是状态数 × 转移数；先估状态数再动手，能省一小时。
06 · BIDIRECTIONAL

双向 BFS：两边对撞

本页回答：为什么能快这么多？
相遇时怎么算答案。

收益

单向：O(b^d)　双向：O(2 · b^(d/2))
d=10、b=26：约 10¹⁴ → 10⁸，量级差

两个要点

  • 每轮扩展较小的一侧（保证不会失衡）
  • 两侧各自记录距离，相遇时 d₁ + d₂ 就是答案
易错：只记录单侧距离、或每轮固定扩展起点侧 —— 都会算错层数。

06 · MEMOIZATION

记忆化搜索 = DFS + DP

本页回答：它和递推有什么区别？
什么时候写记忆化更好。

等价性

记忆化搜索是自顶向下的 DP；递推是自底向上。两者时间复杂度相同，状态转移也相同。

什么时候更好写

  • 状态转移方向不规则（难定递推顺序）
  • 很多状态根本用不到（只算需要的）
  • 边界条件复杂（递归天然处理）
写法：functools.lru_cache 一行搞定；注意状态必须是可哈希的（tuple / int）。

06 · PRUNING

剪枝、迭代加深、什么时候上 A*

本页回答：朴素搜索太大怎么办？
有哪些通用手段。

1可行性剪枝

做法：当前状态无论怎么走都到不了目标 → 立即返回。例如剩余步数 < 曼哈顿距离。

2最优性剪枝

做法：当前代价已 ≥ 已知最优解 → 停。常见于"最少操作数"。

3迭代加深 IDDFS

做法：限制深度上限逐次 +1。空间 O(d)，适合深度小而分支大。

什么时候上 A* / IDA*

状态数 10⁷ 以上、且有可采纳启发式（不高估）时；否则双向 BFS + 剪枝通常够。

不要做的事

不要一上来就写 A*：先估状态数，很多时候朴素 BFS（含双向）已经 AC。

顺序：① 状态设计 ② 去重 ③ 双向 ④ 可行性剪枝 ⑤ 才考虑启发式。

07 · COMPLEXITY

复杂度：O(V + E) 从哪来

本页回答：为什么是线性？
空间复杂度怎么算。

时间

每个点被展开 1 次：O(V)
每条边被检查 1 次：O(E)
合计 O(V + E)

网格图 V = RC，E ≈ 4RC，所以是 O(RC)。

退化条件

  • 入队不标记 ⇒ 重复入队 ⇒ 可能退化
  • DFS 迭代不标记 ⇒ 栈爆炸
  • 每轮都重建大数组 ⇒ 常数变大

空间

项量级
邻接表O(V + E)
visited / distO(V)
BFS 队列O(某层宽度)
DFS 递归栈O(图的深度)
状态空间 BFSO(状态数)
判 TLE 前先算：10⁵ 点 + 2×10⁵ 边 → 常数为 1 时 3×10⁵ 次操作，完全无压力；TLE 通常意味着有重复访问。
07 · STACK

递归爆栈：最先炸的是链式图

本页回答：什么时候会 RE？
怎么安全处理。

三道防线

  • sys.setrecursionlimit(10**6)（只放宽 Python 层限制）
  • 改迭代写法（第 10 页）—— 最稳
  • Java/C++ 手动扩栈或改迭代

危险用例

链式图 1-2-3-…-n（深度 = n）、长条网格（深度 = R+C）、深 DFS 树。

注意

setrecursionlimit 只改 Python 的计数，不改 C 栈大小；深度 10⁵+ 仍可能段错误。真正的解是迭代。

实用规则

n ≤ 10⁴ 且结构可控 → 递归 OK
n ≥ 10⁵ 或图由数据给 → 迭代 / 模拟栈
对拍建议：用 n = 2×10⁵ 的链式图专门测递归版，90% 的爆栈都能在对拍时暴露。
07 · PERFORMANCE

常数优化：四件小事

本页回答：同样 O(V+E)，为什么有人更快？

1用 deque

list.pop(0) 是 O(n)；deque.popleft() 才 O(1)。

2入队即标记

重复入队会把复杂度推向 O(V·E)。见第 20 页。

3早停

BFS 找到目标立刻 return，别跑完整张图。

4复用数组

多组数据时用时间戳 vis[u] == cur_id 代替重置，省 O(n)。

输入规模大的处理

  • 用 sys.stdin.buffer.read() 一次性读入
  • 邻接表用 list 而非 dict（点编号连续时）
  • 网格遍历用局部变量缓存 R, C, DIRS

什么时候不必优化

10⁵ 量级的图，Python 的标准模板足够；先保证正确，TLE 时再做常数。

09 · SUMMARY

带走这 五句话

本页回答：如果只能记住一页，
就记这一页。
1
DFS 与 BFS 只差"取谁"：栈给深度、队列给层数；骨架完全相同（S + F）。
2
最短路用 BFS，其他用 DFS：答案与层数有关 → BFS；只问可行性/存在 → DFS。
3
标记时机是第一易错点：入队即标记防重复；深图把递归改成迭代。
4
升级链顺着边权走：全 1 → BFS，0/1 → 双端队列，非负 → Dijkstra，负权 → Bellman-Ford。
5
状态设计决定上限：把"点"换成"(点, 附加状态)"，能解一大类看似无从下手的题。
升华：遍历的价值不在"会不会写"，而在于把陌生问题翻译成"状态 + 转移"的能力 —— 会翻译，才有算法。
