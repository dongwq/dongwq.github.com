术语与流守恒：把话说清楚

MAIN这一页是全文唯一一次术语页。后面所有页都只用这里定义过的词。

VOCABULARY七个词
容量 c(u,v)
这条边最多能过多少
流量 f(u,v)
这条边实际过了多少
可行流
不超容量 + 除源汇外守恒
残量
c − f，还能再塞多少
增广路
残量网络里 S→T 的路径
割
把点分成 S 侧 / T 侧
最大流
可行流里流量最大者
CONSERVATION「流守恒」的正式定义

除源 S 和汇 T 外，每个点的入流 = 出流：

Σ f(u,v) = Σ f(v,w)
  进 v       出 v

所有流算法都在维护这条性质，只是「怎么找增广」不同。

FIG.04 · 除源汇外，每个点必须收支平衡
CAPACITY两个约束
容量约束
0 ≤ f(u,v) ≤ c(u,v)
守恒约束
除 S / T 外入 = 出

两条约束都满足 = 可行流。

REVERSE反向边：网络流最反直觉的设计

每条正向边都配一条容量 0 的反向边。

推流时：正向 −f，反向 +f。

反向边的物理意义是「撤回之前的决定」。

没有反向边，就没有正确的最大流。

网络怎么存进程序

MAIN网络流的存储有一个专属技巧：把正反两条边存在相邻下标。

PYTHON · 边表 + 邻接（推荐）
# 边：to 终点，cap 剩余容量
# 技巧：正边下标 i，反边下标 i^1
class Edge:
    __slots__ = ('to', 'cap', 'cost')
    def __init__(self, to, cap, cost=0):
        self.to = to; self.cap = cap; self.cost = cost

g = [[] for _ in range(n)]

def add_edge(u, v, cap, cost=0):
    g[u].append(Edge(v, cap, cost))     # 下标偶数：正
    g[v].append(Edge(u, 0, -cost))    # 下标奇数：反

# 找反边：e = g[u][i]，反边 = g[e.to][i ^ 1]
关键
i ^ 1 取反边：正反成对，永不混乱
PYTHON · 邻接矩阵（仅限小图 / 教学）
cap = [[0]*n for _ in range(n)]
cap[u][v] += w          # 重边要累加！
# 反边：cap[v][u] 初始为 0，推流时一起改
COMPARE两种存法
边表 + 邻接邻接矩阵
空间O(n+m)O(n²)
查残量O(1) 通过指针O(1)
遍历邻边O(度数)O(n)
用途几乎所有题n ≤ 300 教学
THREE DETAIL三个存储细节
  • 重边：不能覆盖，要累加容量（除非题目明说是两条独立边）
  • 自环：自己到自己，容量加进去没意义，一般忽略
  • 反向边的容量初始为 0，费用为 −c
PYTHONPython 性能三句
  • __slots__ 能省 30% 内存
  • 大输入用 sys.stdin.readline
  • INF 统一 10**18，容量别用浮点
06

残量网络：「反悔」的机制

MAIN这一页解决「推错了怎么办」。没有这一页，后面的算法全部不成立。

FIG.06 · 反向边让算法有「后悔药」
WHY为什么必须有反向边

贪心找一条增广路，很可能不是全局最优。

反向边给算法一个「退回这步、换条路走」的机会。

没有它，FF 只能算出一个不是最大的「最大流」。

CLASSIC一个经典反例

如果在残量网络里先找到 S→a→b→T（走了次优的桥），

后面通过反向边 b→a，可以撤回这一段，改走更好的路径。

最终结果依然是最大流。

CODE推流的两行
e.cap      -= f          # 正向减
g[e.to][i^1].cap += f  # 反向加

所有流算法，推流都只改这两行。

07

阶梯一 · Ford-Fulkerson：不断找增广路

MAIN要解决的问题：怎么从零流量开始，一步步把流量堆到最大。

FIG.07 · 一条一条推，直到推不动
THE IDEA核心：增广

在残量网络里找一条 S→T 的路径，设路径上最小残量为 d。

沿路径推 d 单位。

重复，直到找不到 S→T 的路径。

WHY CORRECT为什么停止时就是最大

没有 S→T 路径时，把「S 在残量网络里能到达的点」划成一侧，就是一个割。

这个割的容量 = 当前流量 → 这正是最大流最小割定理（第 14 页讲）。

LIMIT它的问题

若每次只推1 单位，而最大流是 10⁹，就要推 10⁹ 次。

甚至遇到刻意构造的数据，永远跑不完。

Ford-Fulkerson：DFS 版与 BFS 版

MAIN要解决的问题：把思想变成可提交的程序。DFS 简单但慢，BFS 是 Edmonds-Karp。

PYTHON · FF · DFS 版（教学用）
def dfs(u, t, f):
    if u == t: return f
    vis[u] = True
    for i, e in enumerate(g[u]):
        if not vis[e.to] and e.cap > 0:
            d = dfs(e.to, t, min(f, e.cap))
            if d > 0:
                e.cap -= d
                g[e.to][i ^ 1].cap += d
                return d
    return 0

def ff_dfs(s, t):
    flow = 0
    while True:
        vis = [False]*n
        d = dfs(s, t, INF)
        if d == 0: break
        flow += d
    return flow
问题
每次 DFS 只推一条路，最坏 O(f · m)，f 是最大流值
PYTHON · Edmonds-Karp（BFS 找增广路）
from collections import deque

def ek(s, t):
    flow = 0
    while True:
        pre = [(-1, -1)]*n
        pre[s] = (s, -1)
        q = deque([s])
        while q and pre[t][0] == -1:
            u = q.popleft()
            for i, e in enumerate(g[u]):
                if e.cap > 0 and pre[e.to][0] == -1:
                    pre[e.to] = (u, i)
                    q.append(e.to)
        if pre[t][0] == -1: break

        # 回溯找瓶颈
        d = INF; v = t
        while v != s:
            u, i = pre[v]
            d = min(d, g[u][i].cap)
            v = u
        v = t
        while v != s:
            u, i = pre[v]
            g[u][i].cap -= d
            g[v][i ^ 1].cap += d
            v = u
        flow += d
    return flow
EKBFS 版为什么更好

每次选边数最少的增广路（BFS）。

可以证明增广次数是 O(nm)。

复杂度
O(n · m²)
优点
不依赖流量大小 f，多项式
COMMON两个版本的共同骨架
  1. 找一条 S→T 的增广路
  2. 找路径瓶颈容量 d
  3. 沿路推 d，正向减反向加
  4. 重复，直到找不到路径
PITFALL三处易错
  • 忘了 vis / pre，DFS 死循环
  • 推流时只改正向忘了反向
  • 瓶颈 d 用 min，别写成边权

转折一：FF 每次只推一条，太慢

TURNING POINT这是全篇最重要的一次失败。看清它为什么慢，后面才是理解而不是背诵。

FIG.09 · FF 的复杂度依赖流量大小
WHAT BROKE到底错在哪

FF 的复杂度是 O(f · m)，依赖最大流值 f。

f 可能是 10⁹，甚至更大。

更糟：如果容量是无理数，FF 甚至可能不终止。

NEW REQUIREMENT新的要求

不能一次只推一条，要一次推多条。

而且要保证：每次推完，距离 T 的层数至少 +1。

这样增广次数就和 n 挂钩，而不是 f。

先想清楚：「怎么一次性把同层的路全推完」？

如果能用 BFS 分层 + DFS 一次推完，算法就出来了。

Dinic：BFS 分层

MAIN要解决的问题：把「所有 S→T 最短路」一次标出来，并只保留有用的边。

PYTHON · Dinic 的 BFS
from collections import deque

def bfs_level(s, t):
    """返回 level 数组；t 不可达时 level[t] = -1"""
    level = [-1] * n
    level[s] = 0
    q = deque([s])
    while q:
        u = q.popleft()
        for e in g[u]:
            if e.cap > 0 and level[e.to] == -1:
                level[e.to] = level[u] + 1
                q.append(e.to)
    return level
关键
只看 e.cap > 0 的边（残量边）——反向边也参与！
WHY为什么反向边也参与

反向边的残量 > 0，说明「这条路可以撤回一些流量」。

撤回后，可能腾出位置走别的路——这正是最大流正确的关键。

TERMINATE什么时候结束

BFS 后 level[t] == -1，说明 S 到 T 已经不可达。

当前流量就是最大流。

FIG.12 · 分层把残量网络整理成 DAG
COMPLEXITY一次 BFS 的代价
时间
O(n + m)
调用次数
最多 n 次（每阶段一次）
合计
BFS 部分 O(n(n+m))
PITFALL两处易错
  • 只给正向边分层，漏了反向边
  • 忘了判 level[e.to] == -1，同一个点重复入队

Dinic：DFS 阻塞流 + 当前弧

MAIN要解决的问题：一次 DFS 把同层能推的全推完，并用当前弧避免重复扫描。

PYTHON · Dinic 完整版
def dfs(u, t, f):
    """沿 level 增广，返回实际推的流量"""
    if u == t: return f
    i = cur[u]
    while i < len(g[u]):
        cur[u] = i               # ★ 记住当前弧
        e = g[u][i]
        if e.cap > 0 and level[e.to] == level[u] + 1:
            d = dfs(e.to, t, min(f, e.cap))
            if d > 0:
                e.cap -= d
                g[e.to][i ^ 1].cap += d
                return d
        i += 1
        cur[u] = i
    return 0

def dinic(s, t):
    flow = 0
    while True:
        level = bfs_level(s, t)
        if level[t] == -1: break
        cur = [0] * n
        while True:
            d = dfs(s, t, INF)
            if d == 0: break
            flow += d
    return flow

CURRENT ARC当前弧是什么

cur[u] 记录「u 的第几条出边已经试过了」。

下次从 u 出发，直接从 cur[u] 开始扫，不再从头。

没有当前弧，Dinic 会退化成 EK。

WHY CORRECT为什么 DFS 一次能推多条

DFS 推完一条路后，不返回顶层，而是继续在同层里找下一条。

直到所有出边都试过、再没有可推的，才返回 0。

这样一轮 DFS = 一个「阻塞流」。

阶梯三 · 最大流最小割定理

MAIN要解决的问题：题目不只问「最多流多少」，还问「瓶颈在哪」。

FIG.14 · 割是「瓶颈」，也是最大流的另一面
THE THEOREM定理：max-flow = min-cut

最大流的值 = 最小割的容量。

换句话说：「最多能运多少」 = 「最窄的切口有多宽」。

这是网络流最美的一条定理。

HOW TO FIND怎么找出最小割

跑完最大流后，在残量网络上从 S 做一次 BFS / DFS。

所有能到达的点划为 S 侧，其余划为 T 侧。

跨过去的正向边就是最小割。

WHY USEFUL为什么这是「阶梯」

最小割能把「选择 / 放弃」类问题变成网络流：

  • 选谁不选谁（闭合子图）
  • 二分图最小点覆盖
  • 每个点二选一，代价是「矛盾边」
15

最小割建模：三件套

MAIN要解决的问题：怎么把「选不选」「花不花」翻译成割。这三招覆盖 80% 的应用。

T1二选一：源表示 A，汇表示 B

每个点 i 必须选 A 或 B。选 A 的代价 aᵢ，选 B 的代价 bᵢ。

S → i 容量 a_i
i → T 容量 b_i

割边 = 选了另一边。最小割 = 最小代价。

T2关联代价：加一条边

若 i 和 j 选了不同侧，额外付 c。

i → j 容量 c
j → i 容量 c   (无向)

跨侧时，这条边被割。

T3最大权闭合子图

点有正权 p（收益）和负权 −q（成本），选了一个点必须选它的所有后继。

构图：

正权点：S → i 容量 p_i
负权点：i → T 容量 q_i
依赖：  u → v 容量 INF（选了 u 必须选 v）

答案 = 正权总和 − 最小割

经典题：太空飞行计划（P2762）

WHY INF为什么依赖边是 INF

依赖必须满足，不能被割断。

如果这条边被割，代价会趋于无穷——最小割自然避开它。

RECIPE最小割建模三步
  1. 谁是源侧，谁是汇侧？
  2. 「选一边」的代价写成 S→i / i→T
  3. 「矛盾」的代价写成 i→j（INF 表示不可违背）

MCMF：SPFA 版代码

MAIN要解决的问题：把「最短路 + 增广」写成可提交的代码。SPFA 能处理负费用反向边。

PYTHON · 最小费用最大流（SPFA）
from collections import deque

def mcmf(s, t):
    flow = cost = 0
    while True:
        # ① SPFA 求费用最短路
        dist = [INF] * n
        vis  = [False] * n
        pre  = [(-1, -1)] * n
        dist[s] = 0
        q = deque([s]); vis[s] = True
        while q:
            u = q.popleft(); vis[u] = False
            for i, e in enumerate(g[u]):
                if e.cap > 0 and dist[u] + e.cost < dist[e.to]:
                    dist[e.to] = dist[u] + e.cost
                    pre[e.to] = (u, i)
                    if not vis[e.to]:
                        q.append(e.to); vis[e.to] = True

        if dist[t] == INF:
            break              # 不可达，已最大

        # ② 找瓶颈
        d = INF; v = t
        while v != s:
            u, i = pre[v]
            d = min(d, g[u][i].cap)
            v = u

        # ③ 推流，累加费用
        v = t
        while v != s:
            u, i = pre[v]
            g[u][i].cap -= d
            g[v][i ^ 1].cap += d
            v = u
        flow += d
        cost += d * dist[t]
    return flow, cost
30 行
费用累加在 dist[t] 上，不是逐边加
WHY SPFA为什么用 SPFA 而不是 Dijkstra

反向边的费用是 −c，是负数。

Dijkstra 处理不了负权边。

SPFA 天然支持负权。

◆ 想用 Dijkstra？需要「Johnson 势能」（选讲）
COMPLEXITY代价
每轮
SPFA O(nm) 最坏
轮数
最多 O(f) 次增广
合计
O(nmf)，f 是最大流
PITFALL三处易错
  • 反向边费用写成 +c（必须 −c）
  • 用 vis 判重入队漏了，SPFA 会卡死
  • 费用累加写成 cost += dist[t]（漏了 d）

二分图匹配与 König 定理

MAIN要解决的问题：网络流最经典的应用——匹配、覆盖、独立集是一家人。

FIG.22 · 匹配是「一对一」的最大数量
BUILD网络流建图
S → 左点    容量 1
左点 → 右点  容量 1   (仅合法)
右点 → T    容量 1

最大流 = 最大匹配

每条边容量 1 保证「一对一」。

KONIGKönig 定理（二分图专属）

最大匹配 = 最小点覆盖

即：用最少的点盖住所有边，这个数量等于最大匹配数。

推论：最大独立集 = n − 最大匹配。

这三件事在二分图上是一回事。

APPLY三类问法
最多配对
最大匹配
最少覆盖
最小点覆盖 = 最大匹配
最多不相邻
最大独立集 = n − 匹配
NOTE为什么只用二分图

一般图匹配要用带花树，不是网络流。

网络流只负责二分图匹配，别搞混。

最小路径覆盖：拆点 + 匹配

MAIN要解决的问题：用最少的不相交路径覆盖 DAG 上所有点。

FIG.23 · 拆点是路径覆盖的关键
BUILD建图

每个点 i 拆成 i_in 和 i_out。

每条有向边 u→v：
    u_out → v_in  容量 1

S → i_out  容量 1
i_in → T  容量 1

答案 = n − 最大匹配

INTUITION为什么

初始时 n 个点各自一条路径，共 n 条。

每匹配一条边，就把两条路径接在一起，路径总数减 1。

所以：最小路径数 = n − 最大匹配数。

APPLY常见问法
  • DAG 最少几条路径覆盖所有点
  • 最少几组串接（如零件装配顺序）
  • 序列分割的最少段数
PITFALL两处易错
  • 忘记「有向」，无向图要先定向
  • 图里有环，最路径覆盖不成立，要先判 DAG

★ 进阶一：上下界可行流

★ OPTIONAL要解决的问题：有些边「至少」要流 lo，「至多」流 hi。普通最大流只处理上界。

FIG.24 · 下界先扣掉，问题就归约到普通最大流
TRANSFORM变换三步
  1. 先把每条边的下界 lo 扣掉：容量变为 hi − lo
  2. 算每个点的净流入 dᵢ：Σlo_in − Σlo_out
  3. dᵢ > 0（入多）：加 SS → i 容量 dᵢ
    dᵢ < 0（出多）：加 i → TT 容量 −dᵢ

WHY为什么这样就对

每条边的「下界」已经被虚拟边补平。

剩下的容量就是「可自由调节的量」。

若连虚拟边都补不满，说明不存在可行流。

★ 进阶二：有源汇上下界最大 / 最小流

★ OPTIONAL要解决的问题：原图没有循环流，但有源 S 和汇 T。先把它变成循环流。

FIG.25 · 加一条回边，有源汇 → 无源汇
MAX FLOW有源汇上下界最大流
  1. 先按第 24 页方法求可行流（存在即继续）
  2. 记录此时的 T→S 流量 f₀，然后把这条回边删掉
  3. 在残量网络上，跑一次 S→T 最大流 f₁
  4. 答案 = f₀ + f₁
MIN FLOW有源汇上下界最小流
  1. 同样先求可行流，记录 T→S 流量 f₀
  2. 删掉回边，在反向残量图上跑 T→S 最大流 f₁
  3. 答案 = f₀ − f₁

最大流用 S→T，最小流用 T→S，方向别搞反。

WHY为什么要「先可行再调节」

原图没可行流时，直接跑最大流没意义。

所以第一步永远是判可行。

PITFALL三处易错
  • 忘了先判可行性，直接算最大流
  • 回边容量写成 ∞ 而非 INF，溢出
  • 最大 / 最小流的调节方向搞反

★ 上下界应用：清理雪道

★ OPTIONAL要解决的问题：有向图，从任意点出发，每条边至少走一次，最少总步数。

FIG.26 · 每条边「必须走」= 下界 1
BUILD建图
  1. 原图每条边容量 [1, INF]
  2. 加超级源 S、超级汇 T
  3. S → 每个点容量 [0, INF]（可以从任意点开始）
  4. 每个点 → T容量 [0, INF]（可以停在任意点）
  5. 加回边 T → S 容量 [0, INF]
  6. 求有源汇上下界最小流
INSIGHT为什么这样对

每条边至少走一次 = 流量下界 1。

「可以从任意点出发 / 任意点结束」= S / T 与每个点都连通。

「最少总步数」= 最小流（总流量 = 走过的边数）。

PATTERN这一类题的共性

下界 = 1
可以重复走
上界 = INF
起点终点自由
S / T 连所有点

TLE会超时的四处

  • Dinic 没有当前弧优化
  • Python 大图没用 sys.stdin
  • 费用流 SPFA 被卡（考虑势能 Dijkstra）
SEMANTIC语义上的四处错
  • 最大流唯一（错，方案很多）
  • 把「最小割」当成「最少边数的割」（割论容量）
  • 无向图当有向处理（要加两条边）
  • 重边当成两条独立边（多数题要合并）
HABITS四个好习惯
  • INF 统一 10¹⁸，别和容量相加溢出
  • 先跑小样例，再跑手算（n=2 / 重边 / 无解）
  • 不确定稠稀时，默认 Dinic + 边表
  • 看到「至少」立刻想上下界
DEBUG答案不对，按顺序查
  1. 图建对了吗？（有向 / 无向，容量对没对）
