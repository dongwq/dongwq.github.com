RELAX「松弛」的正式定义

这个词听上去吓人，本质就是比较 + 取小：

if dist[u] + w(u,v) < dist[v]:
    dist[v] = dist[u] + w(u,v)

所有最短路算法都在做这一件事，只是「谁来松弛、松弛几次」不同。

阶梯一 · BFS：边权全是 1 时怎么办

MAIN要解决的问题：每一步代价都一样时，怎么用最少时间算出最短距离。

FIG.07 · 层 = 距离，前提是等权
THE IDEA核心：按层访问

用队列维持顺序：先被发现的，先被处理。

于是访问顺序就是距离递增的顺序。

from collections import deque
WHY CORRECT为什么第一次访问就是最短

因为 BFS 严格按层出队。

若某点在第 k 层被首次访问，那它不可能有 < k 的路——

更短的路会让它更早被访问。

LIMIT它只对「等权」有效

一旦边权不相等，「第几层」就不再等于「距离」。

那时 BFS 只保证「步数最少」，不保证「代价最小」。

BFS：代码与三个常用变体

MAIN要解决的问题：把思想变成可提交的程序，并应付题目常见的三种变形。

PYTHON · 无权图单源最短路
from collections import deque

def bfs_shortest(g, n, src):
    """g: 无权邻接表，g[u] = [v, ...]"""
    INF = 10**18
    dist = [INF] * n
    dist[src] = 0
    q = deque([src])

    while q:
        u = q.popleft()
        for v in g[u]:
            if dist[v] == INF:        # 第一次访问
                dist[v] = dist[u] + 1
                q.append(v)
    return dist
代价
时间 O(n + m) · 空间 O(n + m) · 所有最短路算法里最快
PITFALL两处易错
  • 入队 / 出队两边都判访问，条件写重复
  • 网格题把 4 方向 / 8 方向搞混
VARIANT 1多源 BFS

把所有起点一次性入队，答案是「离最近起点的距离」。

    q.append(s)

BFS 的正确性依赖一句话：「层数 = 距离」。

不能按「层」排，得按「当前已知距离」排。

距离小的先处理——这就是下一阶梯的入口。

阶梯二 · Dijkstra：贪心 + 松弛

MAIN要解决的问题：边权任意非负时，怎么安全地挑下一个点。整个算法只有两句口诀。

TWO LINES两句口诀
① 挑最近
→
在「还没确定」的点里挑距离最小的它现在的距离就是最终答案
② 松弛
→
用它更新邻居的距离走它更近，就改小记录
PROOF为什么贪心是安全的

因为所有边权 ≥ 0，绕路只会更贵。

一旦挑中最小的 u*，任何别的路径都要多付非负的代价，不可能更短。

◆ 前提是「边权非负」，缺一不可

挑谁

更新谁

Dijkstra：朴素版与瓶颈分析

MAIN要解决的问题：把思路写成代码，并找出慢在哪里，为下一页的优化铺路。

PYTHON · 朴素 Dijkstra（O(n²)）
def dijkstra_naive(g, n, src):
    """g[u] = [(v, w)]，w >= 0"""
    INF = 10**18
    dist = [INF] * n
    done = [False] * n
    dist[src] = 0

    for _ in range(n):            # 最多确定 n 个点
        # ① 挑最近的未确定点
        u = -1
        for i in range(n):
            if not done[i] and (u == -1 or dist[i] < dist[u]):
                u = i
        if u == -1 or dist[u] == INF:
            break                 # 剩下的都到不了

        # ② 标记确定
        done[u] = True

        # ③ 松弛邻居
        for v, w in g[u]:
            if dist[u] + w < dist[v]:
                dist[v] = dist[u] + w
    return dist
对照第 11 页
① 挑最小 → ② 标确定 → ③ 松弛，逐行对应
BOTTLENECK慢在哪
挑最小
每轮 O(n) 扫一遍 ← 就是它
松弛
总共 O(m)，本来就不是问题
合计
O(n² + m)

只要把「挑最小」降下来，整体就快了。

WHEN OK什么时候朴素版够用
  • n ≤ 5000 左右，完全够用
  • 图很稠密（m ≈ n²），朴素版反而更快
  • 初学时用它验证正确性，再换堆版
PITFALL三处易错
  • INF 取 10⁹，加法会溢出
  • 忘了 done 标记，重复确定
  • 图不连通时，到不了的点要输出 INF / −1

Dijkstra：堆优化版

MAIN要解决的问题：用最小堆替换「扫一遍找最小」，把复杂度降到 O(m log n)。

PYTHON · 堆优化 Dijkstra
import heapq

def dijkstra(g, n, src):
    """g[u] = [(v, w)]，w >= 0；返回 dist"""
    INF = 10**18
    dist = [INF] * n
    dist[src] = 0
    pq = [(0, src)]                # (距离, 点号)

    while pq:
        d, u = heapq.heappop(pq)
        if d > dist[u]:
            continue            # 过期记录，跳过

        for v, w in g[u]:
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))

    return dist
14 行
记住这一段，能应付大部分最短路题
LAZY为什么「多塞几条」也对

堆里可能有同一个点的好几条记录，我们只认最小的那条。

弹出时 d > dist[u] 就是过期，跳过即可。

这叫懒惰删除——省掉「在堆里改值」的麻烦。

Dijkstra 的四个变形

MAIN要解决的问题：题目不会只问距离。算法不变，只改「往哪记东西」。

V1最短路计数

问「有多少条最短路」。

cnt = [0]*n; cnt[src] = 1
if nd < dist[v]:
    dist[v] = nd;  cnt[v] = cnt[u]
elif nd == dist[v]:
    cnt[v] += cnt[u]        # 多一条等长路

记得取模（题目一般给 MOD）。

V2路径还原

问「具体怎么走」。

prev = [-1]*n
if nd < dist[v]:
    dist[v] = nd
    prev[v] = u            # ★ 记前驱
# 最后从 dst 往前回溯

要字典序最小时，等长情况下再比一次路径。

V3最大化版本（概率 / 乘积）

问「成功率最大」的路径。

# 用「负数」把最小堆变最大堆
pq = [(-1.0, src)]
prob = [0.0]*n; prob[src] = 1.0

if p > prob[v]:            # 反向比较
    prob[v] = p
    heapq.heappush(pq, (-p, v))

思想不变，只是「大小」和「运算」换了。

V4带约束的路径

问「最多走 k 条边」的最短路。

Dijkstra 不能直接用——距离最小的路可能超过 k 站。

解法：把状态扩成 dist[v][t]（已走 t 条边），或用分层图。

转折二：负权边让 Dijkstra 崩塌

TURNING POINT要解决的问题：负权在现实中真实存在（返现、优惠、负利率），不能假装没有。

FIG.15 · 「确定」不再安全
ROOT失败的根因

Dijkstra 依赖「绕路只会更贵」，负权让绕路能便宜。

于是已确定的点会被翻案，整个贪心逻辑塌掉。

NEG CYCLE更狠的：负环

环上边权和 < 0，每绕一圈就再减一点。

于是最短路 = −∞，根本不存在。

3 + (−7) + 2 = −2 < 0

算法必须能「判负环」，而不是硬算一个数。

NEW IDEA那怎么办

不能一次确定，那就反复更新，直到改不动为止。

这就是下一阶梯 Bellman-Ford 的思路。

SPECIAL无向图的特殊性

无向图只要有一条负权边，来回走就构成负环。

所以无向最短路边权必须非负。

WHY n-1为什么是 n−1 轮

任何简单路径（不重复走点）最多 n−1 条边。

这是 BF 相对 Dijkstra 的独特价值。

Bellman-Ford：代码与三个细节

MAIN要解决的问题：把思想变成可提交、能判负环的代码。

PYTHON · Bellman-Ford（含负环检测）
def bellman_ford(n, edges, src):
    """edges: [(u, v, w)]，可含负权
    返回 dist；有可达负环返回 None"""
    INF = 10**18
    dist = [INF] * n
    dist[src] = 0

    for _ in range(n - 1):
        upd = False
        for u, v, w in edges:
            if dist[u] != INF and dist[u] + w < dist[v]:
                dist[v] = dist[u] + w
                upd = True
        if not upd:
            break              # 已收敛，提前结束

    # 负环检测
    for u, v, w in edges:
        if dist[u] != INF and dist[u] + w < dist[v]:
            return None
    return dist
亮点
if not upd: break —— 大多数图远跑不满 n−1 轮
D1为什么要判 dist[u] != INF

u 到不了时 dist[u] 是 INF。

INF + 负数会让 v 「莫名其妙变近」。

这个判断必须有。

D2为什么可以提前 break

一轮下来没有任何距离变小 = 已收敛。

再刷也没用，省下大量时间（随机图常 3~5 轮就停）。

D3负环检测怎么写

最后再扫一遍所有边，还能松弛就说明有负环。

  • 循环写成 range(n) 而不是 range(n-1)，多跑一轮误判
  • 检测时忘判 INF，把到不了的点误判

SPFA：Bellman-Ford 的队列优化

MAIN要解决的问题：BF 每轮刷所有边，绝大多数是白刷。只让「有变化」的点去干活。

PYTHON · SPFA
from collections import deque

def spfa(g, n, src):
    """返回 dist；有可达负环返回 None"""
    INF = 10**18
    dist = [INF]*n; dist[src] = 0
    inq  = [False]*n
    cnt  = [0]*n            # 入队次数，用于判负环

    q = deque([src]); inq[src] = True; cnt[src] = 1

    while q:
        u = q.popleft(); inq[u] = False
        for v, w in g[u]:
            if dist[u] + w < dist[v]:
                dist[v] = dist[u] + w
                if not inq[v]:
                    q.append(v); inq[v] = True
                    cnt[v] += 1
                    if cnt[v] >= n:
                        return None   # 负环
    return dist
判负环
入队 ≥ n 次，说明在环上绕了不止一圈
FIG.18 · 只让「有变化」的点干活
WHY为什么安全

u 的距离没变时，它去松弛邻居不会有任何效果。

那就别浪费时间。

WARNINGSPFA 会被卡

最坏仍是 O(nm)，竞赛存在专门卡 SPFA 的数据。

边权非负时老实用 Dijkstra，别为省事用 SPFA。

NOTE怎么选（详见第 23 页）

一句话：非负 → Dijkstra；有负 → BF / SPFA。

要「最多 k 条边」→ BF（语义最清楚）。

★ 负环专题：从「判有无」到「找出来」

★ OPTIONAL要解决的问题：竞赛常问「哪些点的距离是 −∞」，光判有无不够。

PYTHON · 找出受负环影响的所有点
from collections import deque

def neg_cycle_nodes(g, n, edges, src):
    """返回受负环影响（距离可无限小）的点"""
    INF = 10**18
    dist = [INF]*n; dist[src] = 0
    for _ in range(n-1):
        for u, v, w in edges:
            if dist[u] != INF and dist[u]+w < dist[v]:
                dist[v] = dist[u] + w

    bad = [False]*n
    for u, v, w in edges:
        if dist[u] != INF and dist[u]+w < dist[v]:
            bad[v] = True       # v 在负环上或其后

    # 沿出边扩散，标记所有下游
    q = deque([i for i in range(n) if bad[i]])
    while q:
        u = q.popleft()
        for v, w in g[u]:
            if not bad[v]:
                bad[v] = True
                q.append(v)
    return bad
两步
先找还能被松弛的点，再沿出边扩散到所有下游
WHY SPREAD为什么要扩散

负环之后的点，距离也能无限小——它们同样没答案。

所以从负环出发能走到的点都要标掉。

ALTERNATIVE另一种写法

用 SPFA 判负环：某个点入队 ≥ n 次即有负环。

代码更短，但要小心被卡。

FLOYD多源时更简单

Floyd 跑完，若 存在 d[i][i] < 0，点 i 在负环上。

见第 21 页。

SCOPE问法要看清

最后扫一遍，有松弛就有负环
问哪些

阶梯四 · Floyd：所有点对最短路

MAIN要解决的问题：问「任意两点」时，跑 n 次单源太贵。能不能一次算完。

if d[i][k] + d[k][j] < d[i][j] → 更新 核心只有一行，剩下都是「枚举谁在外层」的问题
FIG.20 · 用中间点 k 更新 i→j
WHY为什么枚举中间点就够了

任何 i→j 的路径，中间一定经过某个点 k。

把「能不能经过 k 让它更短」问遍所有 k，答案就出来了。

THE CRUXk 为什么必须最外层

k 的语义是：「只允许经过 0..k 作为中间点」。

所以必须先把 k 及之前的点用完，再放开 k+1。

第 k 轮后：
d[i][j] = 只用 0..k 作中转的最短路

k 放里面就失去这个语义，结果会错。

COST代价
时间
O(n³)，n ≤ 400 左右
空间
O(n²)，邻接矩阵
优点
代码极短，可处理负权
TRAP三处易错
  • 忘了 d[i][i] = 0
  • 重边要取 min，不能直接覆盖
  • INF 加法会溢出，要判 d[i][k] == INF

Floyd：代码与负环判断

MAIN要解决的问题：写出高效且不易错的三重循环，并顺手解决负环。

PYTHON · Floyd-Warshall
def floyd(n, edges):
    """返回 d，d[i][j] = i 到 j 最短距离"""
    INF = 10**18
    d = [[INF]*n for _ in range(n)]
    for i in range(n):
        d[i][i] = 0
    for u, v, w in edges:
        if w < d[u][v]:            # 处理重边
            d[u][v] = w

    for k in range(n):          # ★ k 在最外层
        dk = d[k]
        for i in range(n):
            dik = d[i][k]
            if dik == INF:
                continue
            di = d[i]
            for j in range(n):
                nd = dik + dk[j]
                if nd < di[j]:
                    di[j] = nd
    return d
省时技巧
把 d[k]、d[i][k] 取到局部变量，Python 下能省 30%+
NEG CYCLE怎么判负环

跑完后若 存在 i 使 d[i][i] < 0，点 i 就在负环上。

any(d[i][i] < 0 for i in range(n))

比 BF 写法简洁得多，代价是 O(n³)。

UNREACHABLE怎么表示到不了

跑完还是 INF 就是不连通。

输出前先判断，别把 INF 直接打出来。

WHEN什么时候用 Floyd
  • 问「任意两点」或n ≤ 400
  • 图带负权但又要所有点对
  • 想要顺手判负环
  • 图会动态加边（重建成本高）

Floyd 的四种妙用

MAIN要解决的问题：它不只是最短路。换个「运算」和「比较」，就变成别的工具。

U1传递闭包（可达性）

+ 换成 「或」，min 换成 「与」。

for k in range(n):
    for i in range(n):
        if reach[i][k]:
            for j in range(n):
                reach[i][j] |= reach[k][j]

用处：判断谁是谁的后代、找入度为 0 的点。

U2求最小环

枚举到 k 时，在 d[i][j] 更新之前考察：

d[i][j] + w(i,k) + w(k,j)

拿到不含 k 之前点的最小环。

U3最大乘积 / 最大概率

+ 换成 *，min 换成 max。

d[i][j] = max(d[i][j], d[i][k] * d[k][j])

用处：货币兑换、可靠度、汇率套利。

LC 399 除法求值 ↗ LC 2976 ↗
U4路径还原

再开一张 nxt[i][j] 记「下一步走哪」。

# 松弛成功时
nxt[i][j] = nxt[i][k]

# 还原
def path(i, j):
    if nxt[i][j] == -1: return [i]
    return [i] + path(nxt[i][j], j)
TAKEAWAY一句话
Floyd = 「枚举中间点」的通用框架。
换掉 运算 和 比较，就是新算法。

★ 进阶二：0-1 BFS

★ OPTIONAL要解决的问题：边权只有 0 和 1 时，用堆太重，用普通 BFS 又不对。

PYTHON · 0-1 BFS
from collections import deque

def zero_one_bfs(g, n, src):
    """g[u] = [(v, w)]，w 只能是 0 或 1"""
    INF = 10**18
    dist = [INF]*n; dist[src] = 0
    dq = deque([src])

    while dq:
        u = dq.popleft()
        for v, w in g[u]:
            if dist[u] + w < dist[v]:
                dist[v] = dist[u] + w
                if w == 0:
                    dq.appendleft(v)   # 权 0：放左边，优先
                else:
                    dq.append(v)       # 权 1：放右边，延后
    return dist
识别信号
题目出现「改变一次方向」「翻转一次」「消除一堵墙」
FIG.27 · 队列里的距离只可能差 1
WHY为什么这样就对

队列中的距离只可能取两个值（差 1），简单分层就够。

不用堆 → O(n+m)，比 Dijkstra 快一大截。

PITFALL两处易错
  • appendleft / append 写反
  • 忘判 dist[u] + w < dist[v]，无限循环

常见坑汇总：一处看完

MAIN全文唯一的坑汇总页。代码不长，但坑很密。

WRONG ANSWER会直接出错的五处
  • 有负权却用了 Dijkstra
  • BF 循环写成 range(n)，多跑一轮
  • 松弛时忘判 dist[u] != INF
  • 忘设 dist[src] = 0 / d[i][i] = 0
  • Floyd 重边没取 min
TLE会超时的四处
  • INF 取 10⁹，加法溢出
  • Python 大图没用 sys.stdin
  • 用 dict 存图，常数巨大
  • 该用堆版却用朴素版（n > 5000）
SEMANTIC语义上的三处错
  • 用 Dijkstra 解「最多 k 站」
  • 问「哪些点」时只答了「有没有」
  • 到不了的点输出了 INF（应输出 −1）
HABITS四个好习惯
  • INF 统一 10¹⁸，加法前先判一下
  • 先跑样例，再跑边界（n=1 / 不连通 / 自环）
  • 不确定稠稀时，默认堆优化 Dijkstra
  • 看到「最多 k 次」立刻想分层图
DEBUG答案不对，按顺序查
  1. 图建对了吗？（有向 / 无向，方向反没反）
  2. 边权符号对吗？（负权 → 换算法）
  3. 起点设置对吗？
  4. 输出格式：到不了要输出 −1 还是 INF？
