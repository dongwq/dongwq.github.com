01 · IDEA

核心思想：把串当成 B 进制大整数

本页回答：为什么要多项式？
为什么必须取模。

多项式映射

f(s) = s₁·B^(n−1) + s₂·B^(n−2) + … + sₙ
相当于把 s 看成 B 进制数，s[i] 是"数位"

为什么取模

  • B 进制大整数会指数级溢出
  • 取模后值域固定，可做数组下标 / 字典键
  • 模数越大，碰撞越少
核心风险：取模是多对一映射 ⇒ 不同串可能同值（碰撞）。
为什么是多项式：它让前缀与子串之间有线性关系，才能 O(1) 相减。

01 · PREFIX

前缀哈希 + 幂预处理

本页回答：两个数组各存什么？
递推式怎么推。

递推式

h[i] = ( h[i−1] · B + s[i] ) mod M
p[i] = ( p[i−1] · B ) mod M,　p[0] = 1

展开看清楚

h[i] = s[1]·B^(i−1) + s[2]·B^(i−2) + … + s[i]
指数从 i−1 递减到 0：左端权重最大
方向不能反：若你把 h[i] 写成 Σ s[k]·B^(k−1)，子串公式要改成乘模逆元，完全不同。全篇统一用上面这个。

两个数组的含义

数组含义
h[i]前缀 s[1..i] 的哈希
p[i]B^i mod M（注意是 i 次方）

预处理

时间 O(n)，空间 O(n)
两个数组都要开到 n+1；p 用到下标 r−l+1 ≤ n
记忆：h 是"答案"，p 是"尺子"——相减时用它对齐位数。
01 · SUBSTRING

子串哈希：前缀相减

本页回答：为什么相减就能得到子串？
公式怎么来的。

公式

get(l, r) = ( h[r] − h[l−1] · p[r−l+1] ) mod M

推导

h[r] = Σ_{k=1..r} s[k]·B^(r−k)
h[l−1]·p[r−l+1] = Σ_{k=1..l−1} s[k]·B^(r−k)
相减 = Σ_{k=l..r} s[k]·B^(r−k)
易错：是 p[r−l+1]（长度），不是 p[r−l]。差一次方结果完全不同。
验证：当 l = 1 时 h[0] = 0，公式退化为 h[r] ✓；当 l = r 时得到 s[l] ✓。

01 · EDGE

字符映射与边界细节

本页回答：映射为什么必须非零？
还有哪些边界。

映射规则

小写字母：ord(c) − 96　→ 1..26
多字符集：ord(c)　→ ASCII
整数序列：直接用 v，保证 v ≥ 1

为什么不能用 0

映射 a→0：
s = "a"　→ h = 0
s = "aa" → h = (0·B + 0) = 0　← 撞了！

前导零会让不同长度的串同值。必须让每一位非零。

边界清单

  • l = 1：直接返回 h[r]
  • l = r：返回 s[l]
  • 空串：哈希为 0（约定）
  • 比较不同长度的串：先比长度，或直接比哈希（长度不同必然不同——因为有高位权重；但保险起见先比长度）
  • 下标越界：r > n 是高频 bug

容易忽略

  • 混合大小写：映射要覆盖 1..52，且 B > 52
  • 含数字/符号：映射范围更大，B 也要更大
  • 空串参与比较：统一约定"空串哈希 = 0"
01 · COMPLEXITY

复杂度：预处理 O(n)，查询 O(1)

本页回答：哈希到底多快？
和 KMP 比谁赢。

各项开销

操作复杂度
预处理 h / pO(n)
子串哈希O(1)
子串比较O(1)（双哈希 2 次）
LCP 二分O(log n)
空间O(n)

对比 KMP

KMP 模式匹配 O(n+m) 且确定性；哈希 Rabin-Karp 期望 O(n+m) 但可能误判。纯匹配题 KMP 更稳，但 KMP 不能做任意子串比较。

关键优势

比较 O(L) → O(1)
于是可以在长度上二分
LCP、最长公共子串、最长重复子串

可以"进集合"

  • 哈希值是整数，能作 dict/set 键
  • 不同子串去重、模式串去重
  • meet-in-the-middle 类问题
结论：哈希的价值不在"比 KMP 快"，而在「比较便宜到能二分 / 能进集合」。
01 · SPACE

空间、下标与容易翻车的细节

本页回答：数组开多大？
下标从 0 还是 1。

1数组清单

双哈希要 h1, h2, p1, p2 各 n+1；空间 O(n)。四倍于单哈希。

2下标约定

统一 1-indexed；h[0] = 0、p[0] = 1。两个初值错一个，全盘皆错。

3幂数组

p[i] = B^i，用到的最大下标是 n（当 l=1, r=n 时 p[n]）。开到 n+1。

4取模负数

Python % 自动非负；C++ 必须 +M，否则减法后为负。

5tuple 开销

Python 每次比较 tuple 有开销；可合成 (h1 << 32) ^ h2 作单值比较。

6预处理只做一次

多组数据时不要每次重建；若字符串不变，h/p 复用。

记忆：h[0]=0、p[0]=1、p[i]=B^i、p[r−l+1]、C++ 加 M。

02 · ATTACK

卡哈希：生日攻击与碰撞概率

本页回答：攻击者怎么做？
概率到底多大。

生日悖论

在 M 个可能值中随机取 ≈ √M 个，就有约 50% 概率出现一对碰撞。

M = 10⁹　→ √M ≈ 3×10⁴ 个候选
M = 2⁶⁴　→ √M ≈ 2³² 个候选

单哈希的碰撞概率

q 次比较的失败概率 ≈ q² / (2M)
q = 10⁵, M = 10⁹ ⇒ ≈ 5（完全不安全）

防御三招

  • 双哈希：两个独立 (B, M) 同时撞才误判
  • 随机进制：运行时随机 B，攻击者无法预知
  • 128 位 / 三哈希：极致保险
判断：q = 10⁵ 的题，单哈希 M = 10⁹ 的失败概率不可接受；双哈希是必要而非可选。

02 · EXTREME

三哈希、128 位 与模数对

本页回答：极致安全怎么做到？
各方案的代价。

1双哈希

两个独立 (B, M)，比较两个 tuple。

失败概率 ≈ 1/(M₁·M₂) ≈ 10⁻¹⁸。多数题的最优性价比。

2三哈希

三个独立模数；或用 __int128 打包两个 64 位。

失败概率 ≈ 10⁻²⁷。用于"明知会被卡"的题。

3大模数 / 128 位

用 2⁶¹−1（梅森素数）+ 快速取模，或 __int128 乘法。

速度快且安全，但写起来繁琐。

4随机模数

运行时随机选一个大质数（预生成质数表）。

防"预知模数"的定向攻击。

5模数对

常用 (10⁹+7, 10⁹+9)、(10⁹+7, 998244353)、(2⁶¹−1, 2⁶⁴ 自然溢出)。

6打包技巧

key = (h1 << 32) ^ h2
合成单值，dict/set 更快
实战建议：99% 的题用双哈希 + 随机进制即可；剩下 1% 上三哈希或 2⁶¹−1。
02 · COMPARE

比较的顺序与细节

本页回答：比较时最容易写错什么？
为什么这些错很隐蔽。

比较的正确姿势

  • 先比长度，再比双哈希
  • 两个哈希都相等才判相等
  • 比较对象是 tuple，不是单个整数
  • 不要"比第一个哈希，不同就返回"（会丢第二个的信息）

减法后取模

Python：(a - b) % M 自动非负 ✓
C++：((a - b) % M + M) % M 必须加 M

下标与幂

  • 幂下标是 r − l + 1（长度），不是 r − l
  • p[i] = B^i，不是 B^(i−1)
  • 1-indexed 混用 0-indexed 是灾难
  • 双哈希里 p1 用 M₁、p2 用 M₂，别写混

C++ 特有

  • unsigned long long 溢出是良定义（模 2⁶⁴）；int 不是
  • 有符号溢出是未定义行为，编译器可任意优化
  • 模数与 long long 乘法要防溢出

03 · LCP

最长公共前缀：二分长度

本页回答：为什么二分是对的？
复杂度多少。

单调性

若长度 L 的前缀相等，则长度 L−1 也相等。谓词单调 ⇒ 可二分。

这正是哈希能二分的根本原因。

复杂度

二分 O(log n) 次，每次 O(1) 比较
合计 O(log n)
对比：后缀数组 + RMQ 是 O(1)，但要 O(n log n) 预处理且代码长。

03 · LCS

最长公共子串：二分长度 + 集合

本页回答：两串的 LCS 怎么做？
为什么二分长度合法。

思路

  • 答案长度 L 有单调性：存在长 L 的 ⇒ 存在长 L−1 的
  • 二分 L，判定"是否存在公共子串长 ≥ L"
  • 判定：s 中长 L 的所有子串哈希入集合，看 t 有没有命中

复杂度

每次判定 O(n + m)
二分 O(log min(n,m))
合计 O((n+m)·log min(n,m))
小心：若"最长公共子串"要求不重复计数或输出所有，要换成 SAM / 后缀自动机。

判定函数骨架

def ok(L):
  S = set( H_s.get(i, i+L-1) for i in 1..n-L+1 )
  return any(H_t.get(j, j+L-1) in S for j in 1..m-L+1)

变体

  • 最长公共子序列 → 哈希不适用，用 DP
  • 最长公共回文子串 → 正反哈希 + 二分
  • k 个串的公共子串 → 集合求交
心法："二分 + 判定 + 哈希集合"是字符串题的通用三件套。
03 · PALINDROME

回文判定：正反双哈希

本页回答：怎么 O(1) 判回文？
反向哈希怎么建。

思路

  • 建两套哈希：正向 f、反向 r
  • s[l..r] 回文 ⇔ 它等于自己的反转
  • 反转串中的区间：[n−r+1, n−l+1]
  • 比较 f.get(l,r) 与 r.get(n−r+1, n−l+1)

下标推导

反转串 rs[k] = s[n−k+1]
s[l..r] 对应 rs[n−r+1 .. n−l+1]
对比：Manacher O(n) 求所有回文半径更专业；但判单个区间回文，哈希 O(1) 更方便。

03 · RADIUS

回文半径：逐中心二分

本页回答：最长回文子串怎么做？
奇偶怎么处理。

算法

  • 对每个中心 c，二分最大半径 R
  • 判定：is_pal(c−R+1, c+R−1)
  • 奇回文：2R−1 长；偶回文：2R 长
  • 总复杂度 O(n log n)

偶回文的中心

把中心看成"两个字符之间"，判定 is_pal(c−R+1, c+R)，得到 2R 长的偶回文。

若只求一个最长回文：Manacher 更快（O(n)）；哈希版胜在好写、能顺便回答区间回文询问。

骨架

for c in 1..n:
  二分最大 R 使 is_pal(c−R+1, c+R−1)
  更新答案
同理处理偶回文

常见变体

  • 回文子序列 → DP，不适用哈希
  • 回文划分的最少段数 → 哈希判回文 + DP
  • 加一个字符变成回文 → 最长回文前缀/后缀
LC 214 最短回文串：求最长回文前缀长度 L，把 s[L+1..] 反转后接到前面。
03 · ROLLING

Rabin-Karp：滚动哈希匹配

本页回答：滚动公式怎么推？
为什么要二次验证。

滚动公式

cur = ( cur·B − t[i−m]·B^m + t[i] ) mod M
窗口右移一位：去掉最左、加上最右

为什么要二次验证

哈希相等不代表真匹配。命中后必须逐字符比一次，否则会被卡哈希。

复杂度：期望 O(n + m)；最坏 O(nm)（被构造碰撞时）。

03 · DISTINCT

不同子串个数：哈希去重

本页回答：哈希去重可行吗？
什么时候必须换方法。

朴素做法

  • 枚举所有 (l, r)，哈希入 set
  • 复杂度 O(n²) 时间与空间
  • 适用于 n ≤ 2000 左右

缺陷

  • 结果是"哈希去重"，可能偏小（碰撞把不同串算成相同）
  • 内存 O(n²) 易炸
  • 要求精确答案时不可用
精确做法：后缀数组 Σ(n−sa[i]+1−lcp[i])，或 SAM O(n)。

03 · PERIOD

最小循环节：枚举周期 + O(1) 校验

本页回答：为什么不能二分 border？
正确的做法是什么。

周期判定

p 是周期 ⇔ hash(1, n−p) == hash(1+p, n)
即去掉前 p 位后与原串的前 n−p 位相同

最小循环节

枚举 p = 1..n−1，第一个满足的就是最小周期。总复杂度 O(n)（因为每次判定 O(1)）。

若 n % p == 0，则 s 由 s[1..p] 循环构成。

重要纠正："最长 border"的谓词不单调。反例：s = "abcdefabc" 的 border 只有 3，二分会返回 0。不能二分，要么枚举 p，要么用 KMP 的 π 数组。

04 · 2D HASH

二维哈希：子矩阵 O(1) 比较

本页回答：二维递推怎么写？
容斥怎么算。

递推式

h[i][j] = h[i−1][j]·B₁ + h[i][j−1]·B₂ − h[i−1][j−1]·B₁·B₂ + a[i][j]

子矩阵

get(x1,y1,x2,y2)：
  = h[x2][y2] − h[x1−1][y2]·B₁^dx
    − h[x2][y1−1]·B₂^dy
    + h[x1−1][y1−1]·B₁^dx·B₂^dy
dx = x2−x1+1, dy = y2−y1+1
容斥的加号不能漏；两个减法把左上角减了两次。

应用

  • 子矩阵相等判定
  • 最大全 1 子正方形（二分 + 判定）
  • 矩阵模式匹配
04 · PATTERN

哈希 + 二分：一个通用套路

本页回答：什么题能套这个？
前提条件是什么。

适用题型

  • 最长公共前缀 / 子串
  • 最长重复子串（LC 1044）
  • 最长回文子串 / 回文半径
  • 最小改动后相等的串
  • "是否存在长度 ≥ L 的公共子串"

前提条件

谓词 ok(L) 单调：
ok(L) ⇒ ok(L−1)

只要满足，就能二分 + 哈希判定。

三件套骨架

lo, hi = 0, n
while lo < hi:
  mid = (lo + hi + 1) // 2
  if ok(mid): lo = mid
  else: hi = mid - 1
答案 = lo

不能套的场景

  • 谓词不单调（如最长 border）
  • 需要输出方案而非长度
  • 需要精确答案（哈希有碰撞）
心法：看到"最长 / 最小 / 是否存在"就问一句：答案在长度上单调吗？
04 · TREE HASH

树上哈希：树同构的判定

本页回答：树怎么哈希？
子节点顺序怎么处理。

有根树哈希

  • 叶子哈希 = 常数
  • 节点哈希 = 子节点哈希排序后多项式合并
  • 排序是关键：无序树的子节点顺序不重要

无根树同构

先找树的中心（1 或 2 个），分别以它们为根算哈希，取较小的哈希（或有序对）作为整棵树的签名。

复杂度：每个节点的子节点排序 O(deg·log deg)，总计 O(n log n)。

05 · TUNING

常数与优化清单

本页回答：能再快一点吗？
按性价比排序。

1合成单值

(h1 << 32) ^ h2 作 dict/set 键，避免 tuple 比较开销。

2省掉取模

用 uint64 自然溢出 + 双 base；或用 2⁶¹−1 快速模。

3预处理一次

多组数据复用 h / p；勿每次重建。

4局部变量

把 self.M1, self.B 取到局部；热循环里别用 self.x。

5数组而非 dict

哈希值域大时用 set；要频查时用 dict；小规模用排序 + 二分。

6只比长度+首尾

比较前先比长度、首字符、末字符，能短路掉大部分不相等。

Python 特有

  • sys.stdin.buffer.read() 一次性读入
  • 大数组用 array 或 list，避免 dict
  • 双哈希比较用 tuple 或合成整数

C++ 特有

  • uint64_t 溢出良定义，自然溢出零成本
  • __int128 打包双哈希
  • 2⁶¹−1 的快速取模（乘完右移 + 减）

06 · PITFALLS

易错清单 Checklist

本页回答：提交前自检什么？
（每条都对应本讲义的坑）

公式与下标

  • 幂下标写成 r − l（应为 r − l + 1）
  • p[i] 误存成 B^(i−1)
  • h[0] ≠ 0 或 p[0] ≠ 1
  • 1-indexed 与 0-indexed 混用

  • 字符映射用了 0（"a" 与 "aa" 撞）
  • 双哈希只比较了一个
  • 比较前没比长度
  • 不同字符集没扩大 B
  • C++ 减法后忘 + M

算法与安全

  • 二分前没确认谓词单调（border 反例）
  • Rabin-Karp 命中后没二次逐字符验证
  • 用单哈希跑公开评测被卡
  • 不同子串个数用了哈希去重却要精确答案
  • 树上哈希忘了对子节点排序

06 · ADAPT

改一改就能用：四个改点

本页回答：换一道题要改哪里？
只有四处。

1映射函数

ord(c) − 96 换成你的编码（多字符集、整数序列、颜色…），必须 ≥ 1。

2进制与模数

默认随机奇数 + 双模；被卡就换三哈希或 2⁶¹−1。

3比较函数

加长度判断、加短路（首尾字符）；要"小于"就改二分 + LCP。

4查询

加 lcp、is_pal、get_reverse；二维换 Hash2D。

换题检查表

  • 需要比较子串吗？
  • 答案在长度上单调吗（能不能二分）？
  • 要求绝对正确吗？
  • 会不会被刻意卡哈希？

什么时候该放弃哈希

只要模式匹配 → KMP；要回文半径 → Manacher；要精确计数 / 字典序 → 后缀数组 / SAM。

别硬上：哈希的"可能撞车"在要求精确答案的题里是致命的。
06 · VERIFY

怎么验证答案是对的

本页回答：哈希怎么对拍？
边界用例有哪些。

1暴力对拍

写一个逐字符比较的 brute_equal(l1,r1,l2,r2)；随机小串 10⁵ 组，验证 equal() 与暴力完全一致。重点覆盖同长度、不同长度、相邻子串。

3边界用例

  • n = 1（单字符）
  • 全相同字符（aaaa…）
  • 长度 1 的子串比较
  • l = 1 与 l = r 两种退化
  • 整个串相等 / 只差最后一个字符
  • 多组数据复用 h / p

2不变量检查

  • get(l, l) == s[l]（单字符）
  • get(1, i) == h[i]（前缀）
  • get(l, r) == get(l', r') ⇔ 暴力相等（对拍）
  • 回文：is_pal(l, r) 与暴力反转一致
  • 双哈希：任一哈希不同 ⇒ 串必不同
小技巧：换 3 组随机 base 各跑一次，答案应完全一致；若不一致，说明代码有 bug（不是碰撞）。
防卡测试：用 "a"*n、"ab"*n、交替模式串测 Rabin-Karp 的最坏情况。

07 · SUMMARY

带走这 五句话

本页回答：如果只能记住一页，
就记这一页。
1
把串当 B 进制数：h[i] = h[i−1]·B + s[i]，取模后子串比较变 O(1)。
2
子串靠相减：get(l,r) = h[r] − h[l−1]·p[r−l+1]，幂下标是长度。
3
映射必须非零：否则 "a" 与 "aa" 同哈希。
4
双哈希 + 随机进制：把碰撞概率压到 10⁻¹⁸，公开评测必备。
5
能二分的前提是单调：LCP / 最长公共子串可以二分；最长 border 不行。
升华：哈希最值得学的不是模板，而是"用概率换常数"这种工程取舍——知道什么时候能接受不确定性，比记住公式更重要。
