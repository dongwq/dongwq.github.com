01 · HOOK

看似无关的四道题，同一个模型

本页回答：为什么值得单独学"并查集"？
它们只是同一个抽象的四种问法。

题 A

题意：若干亲戚关系，问两人是否属于同一亲戚圈。

→ 等价类查询。

题 B

题意：加若干条边，找出那条"多余"的边（成环）。

→ 合并时判同集合。

题 C

题意：依次摧毁节点，问每次摧毁后还剩几个连通块。

题 D

题意：若干"X 吃 Y / X 与 Y 同类"，判断哪句是假话。

★统一模型

并查集维护一个随时间变化的划分：支持两种操作 —— 合并两个集合、查询两个元素是否同类。所有花样（带权、种类、可撤销、离线）都是在这个骨架上加约束。

解题第一步永远是翻译：题面 → "谁和谁是一类"，再看这一类上有什么额外信息。

三个判断题

合并是否可逆（可撤销） 集合内是否有"关系"（带权） 查询是否可离线

三个答案直接决定用哪个变体 —— 就是第 42 页的速查表。

01 · MODEL

并查集：维护动态的等价类

本页回答：并查集到底维护什么？
为什么它天生适合"合并"而不是"删除"。

1被维护的对象

一个划分：把 1..n 分成若干互不相交的集合。每个集合有一个代表元（根）。

不变量：find(u) == find(v) ⟺ u 与 v 在同一集合

2两个基本操作

  • make-set(x)：自成一类
  • union(a, b)：把两类合并
  • find(x)：返回 x 的代表元

查询、计数、块大小都是 find 的衍生。

3天然的不对称

合并是不可逆的（除非专门做可撤销版）；所以"删除元素"无法直接支持，只能离线倒序或线段树分治。

一句话：并查集是"合并 + 查代表元"的专用数据结构；它的复杂度全部来自"怎么选代表元"与"怎么重排树形"。
01 · MAINLINE

一个不变量，三个旋钮

本页回答：写法上的自由度在哪？
为什么差一点就从 O(n) 到 O(α(n))。

A旋钮一：合并顺序

谁当根？随便 → 树可能退化成链；按大小/秩 → 树高 O(log n)。

决定了树的形状。

B旋钮二：找根时做什么

什么都不做 → 每次都爬一遍；路径压缩 → 把沿途节点直挂到根。

决定了下次找根的成本。

C旋钮三：额外信息

要不要记录 size / min / 关系 / 奇偶 / 顺序？路径压缩时必须同步更新。

决定能不能解决"关系类"题。

不变量（写完自查）

  • 每个集合恰有一个代表元：find(find(x)) == find(x)
  • 树内无环（合并只发生在不同集合之间）
  • 所有辅助信息在 find 后保持正确

心智模型

并查集是一棵不断被压扁的森林：按秩合并控制高度不涨，路径压缩把已走过的路铺平。两个一起用，才是 α(n)。

01 · API

先定接口：find / union / same

本页回答：一个标准并查集要暴露什么？
为什么要让 union 返回 bool？

最小接口

find(x) → x 所在集合的代表元
union(a, b) → 合并，返回是否真的发生
same(a, b) → 是否同类（衍生）
block_size(x) → x 所在集合大小（可选）

union 返回值的用途

  • 统计连通块数 = n − 成功合并次数
  • 判环：union 返回 False 说明两端已连通
  • 统计生成树边数、判断是否已连通

三种表达方式

  • 森林：数组 p[x] 存父指针（主流）
  • 等价类数组：存代表元 id（quick-find）
  • bitset / 链表：特定场景，一般不划算
下标约定：本讲义统一用 1..n（数组开 n+1）。若题目是 0..n-1，注意所有辅助数组同步。
多测题：每组数据重新初始化是 O(n)；大量小测试时可以用"清空访问过的点"技巧把初始化摊还掉。

01 · TOGETHER

两个优化合体：接近常数

本页回答：α(n) 是什么？
为什么说"几乎 O(1)"不算夸张？

Ackermann 函数与 α(n)

A(1, j) = 2^j
A(i, 1) = A(i−1, 2)
A(i, j) = A(i−1, A(i, j−1))
α(n) = min { k : A(k, 4) > log n }（一种常见定义）

增长极其惊人：A(4, 2) 已远超宇宙原子数。

实际数值

n ≤ 10⁶ → α(n) ≤ 4
n ≤ 10⁶⁰⁰ → α(n) ≤ 5

所以工程上把 α(n) 当常数是合理的。

结论

按秩合并 + 路径压缩
m 次操作 O(m · α(n))
（Tarjan & van Leeuwen, JACM 1984）

只有其一呢

  • 只按秩合并：单次 O(log n)
  • 只路径压缩：也是对数级
  • 两者合用才拿到 α(n)

严格界参见原文；本讲义只给直觉（第 39 页）。

实践结论：两个优化都写上，几乎零成本；只写一个是"白送复杂度"。
01 · AMORTIZED

小课：最坏 · 摊还 · 均摊

本页回答："O(m α(n))" 里的复杂度是什么概念？
为什么单次慢、整体快。
概念含义例子
最坏复杂度单次操作的最大代价未优化并查集单次 find 可达 O(n)
摊还复杂度一整串操作的总代价 / 次数并查集 m 次操作 O(m α(n))
均摊（随机）期望意义下的代价随机 pivot 的快排
势能法把"预付的便宜"记成势能，用它支付昂贵操作路径压缩让势能下降来付账
聚合分析直接算总代价栈的多次 push/pop 共 O(m)

并查集里的"账"

路径压缩会花一次时间把节点上提，换来后续 find 变快。把"每个点到根的距离"看成势能：压缩时势能下降，正好补偿刚才的花费。

对竞赛的意义

遇到"单次可能很慢但整体很快"的结构，不要只看单次最坏；写题解时说"摊还 O(...)" 才准确。

口诀：摊还分析回答的是"一整场操作的账单总额"，而不是"某一时刻的发票金额"。

02 · WHY

贪心为什么对：切割性质

本页回答：为什么"先选小的"不会错？
三种证明直觉。

A切割性质

对任意切割，跨越它的最小权边一定属于某棵最小生成树。Kruskal 处理边时，两端分属不同集合，正是一次切割。

B交换论证

若最优解没选当前最小的可行边，把它换进去只会更优或持平，且不影响后续可行性。

C环性质

加入边成环时，环上最大权边可以丢掉。Kruskal 跳过的边正是被更小边"顶掉"的。

推论一：最小瓶颈生成树

最小生成树同时是最小瓶颈生成树（最大边最小）。所以"两城之间最大边最小的路径" = MST 上的路径。

推论二：最小生成森林

图不连通时，Kruskal 自然产出森林；每块内部是该块的 MST。

常见变形："最小化最大边"的问题，既可二分答案 + 并查集，也可直接 MST（更省事）。
02 · VARIANTS

生成树的亲戚们

题型：求 u 到 v 的路径上"最大边"最小。做法：MST 后树上倍增求路径最大边。

倒序排边即可；用于"最大化最小边"或"瓶颈"类问题。

题型："最大代价最小 / 最小代价最大"。check(mid) 就是只连权值满足条件的边，看是否连通。

03 · WEIGHTED

带权并查集：边权 = 到根的关系

本页回答：权值到底表示什么？
union 的公式为什么是那样？

设定

d[x] = kind[x] − kind[find(x)]（mod m）
kind 是未知的"类别"，d 是相对关系

两个公式（已核对）

find 压缩：d[x] = d[x] + d[父]（再挂到根）
union：d[ra] = r − d[a] + d[b]（mod m）

其中约束是 kind[a] − kind[b] ≡ r。

一致性检查：若 find(a) == find(b)，检查 (d[a] − d[b]) mod m == r；不成立即矛盾。
能"带"的信息：模 m 的差（食物链）、奇偶（二分图）、大小顺序（银河英雄传说）、向量偏移（网格）。

03 · 2N TRICK

种类并查集：复制一份表示"敌人"

本页回答：2n 技巧怎么做？
与带权并查集怎么选？

做法

  • 每个元素 x 有两个身份：x（本组）与 x + n（敌方组）
  • a 与 b 敌对 ⇒ union(a, b+n) 且 union(a+n, b)
  • a 与 b 同类 ⇒ union(a, b) 且 union(a+n, b+n)

适用

只有"同类 / 异类"两种关系，没有"谁吃谁"的循环。比带权版更短、更不易错。

边界：数组要开 2n+1；编号从 1 开始时 x + n 不会与本体冲突。

04 · ROLLBACK

可撤销并查集：放弃压缩，换回撤销

本页回答：为什么不能路径压缩？
为什么还要按大小合并？

取舍

  • 路径压缩不可逆：它改变多个节点的父亲，无法只用 O(1) 记录回滚
  • 只保留按大小合并：树高 O(log n)
  • 每次合并记录"被挂上去的儿子"，撤销时改回

复杂度

单次 O(log n) · 撤销 O(1) · 支持快照/回滚
签名：要让"没有发生合并"也占用一个历史位（占位 None），否则撤销会错位。

05 · PROOF 1

按大小合并 ⇒ 树高 ≤ log₂ n

本页回答：怎么证明树高对数？
按秩版本怎么对应？

命题

若合并时总是小树挂大树，则任意节点 x 的深度 ≤ log₂ n。

证明（size 翻倍论证）

  • 节点 x 深度 +1，仅当 x 所在树被并入另一棵
  • 因为是"小挂大"，另一棵树 ≥ 当前树
  • 所以 x 所在集合的 size 至少翻倍
  • size ≤ n ⇒ 翻倍至多 log₂ n 次

rank 版本

rank 定义为高度上界：只有当两棵树 rank 相同时新根 rank + 1。rank = r 的树至少有 2^r 个节点（同样归纳），故 rank ≤ log₂ n。

推论

只用按秩合并：m 次操作 O(m log n)
适用于可撤销版本（不能压缩）
考试答法：用"每合并一次集合规模至少翻倍"这一句话给出上界即可。
05 · PROOF 2

两个优化合用 ⇒ α(n) 的直觉

本页回答：路径压缩为什么"划算"？
势能法怎么算这笔账？

关键观察

  • 按秩合并保证：节点的秩单调不降且 ≤ log n
  • 路径压缩让节点的"到根距离"大幅下降
  • 一次 find 会访问一条路径；压缩后这些点下次近似 O(1)

势能法的账

取势能 Φ = 各节点"秩的某个分层函数"之和。压缩时 Φ 下降，下降量 ≥ 本次操作的实际代价 ⇒ 摊还代价受控。

结论（记忆用）

总代价 = O(m α(n))
严格证明：Tarjan & van Leeuwen (JACM 1984)

竞赛中的表述

"每个点的秩至多 log n，且被抬升的次数有限；路径压缩把访问过的点直接挂根，因此总操作量与 m 成正比乘一个反阿克曼因子。"

提醒：α(n) 不是 O(1)，只是"实际可当常数"。写严谨结论时保留 α(n) 更稳。

06 · VERIFY

怎么验证答案是对的

本页回答：写完怎么自查？
暴力对拍、不变量、边界用例。

1暴力对拍

用邻接表 BFS 染色写参照实现求连通块；带权题用DFS 染色枚举（n ≤ 8）验证。在随机小数据上对拍 1 万组。

3边界用例

  • n = 1、无任何合并
  • 全成一块
  • 始终保持 n 块
  • 自环 / 重复边
  • 极端顺序（1 2 3…）构造退化
  • 大量小测试

2不变量检查

  • find(find(x)) == find(x)（代表元稳定）
  • 所有 size 之和 = n
  • count == 从 1..n 数出的不同代表元个数
  • 带权：抽样验证 (d[a] − d[b]) mod m 与建模一致
  • 可撤销：rollback 后 p 数组与快照一致
好习惯：把 DSU 写成类后加一个 self_check()（对拍脚本里调用），第一版就跑。

07 · SUMMARY

带走这 五句话

本页回答：如果只能记住一页，
就记这一页。
1
并查集维护的是动态划分。两个操作：合并、查代表元；一切花活都是它的变形。
2
两个优化缺一不可：按大小合并控制树高，路径压缩摊平历史；合用才 O(m α(n))。
3
集合内的关系用"带权"表达：压缩时同步权值，union 公式 d[ra] = r − d[a] + d[b]。
4
删除不是原生能力：离线倒序、线段树分治 + 可撤销并查集是两条标准路。
5
写完必查三件事：下标范围、辅助信息同步、多测清空。
升华：并查集的精髓不是那十行代码，而是"什么时候能把问题化成合并与查询" —— 会翻译题面，才谈得上用它。
