01 · PROBLEM

先把概念说清楚

本页回答：二分图、匹配、增广路各是什么？
求的是什么量。
概念定义复杂度说明
二分图顶点可分两部 X, Y，边只在 X–Y 之间判定 O(n+m)等价于无奇环
匹配 M边集，任意两边不共顶点—覆盖点数 = 2|M|
最大匹配|M| 最大的匹配O(m√n)核心问题
完美匹配|M| = min(|X|,|Y|)判定同上所有点都被覆盖
交错路边交替属于 M / 不属于 M—路径定义
增广路起止都不在 M 中的交错路O(m√n)翻转后 |M| + 1
最小点覆盖最少的点覆盖所有边= 最大匹配König 定理
最大独立集最多的点两两无边= n − 最大匹配二分图专用
带权最大匹配权和最大的匹配O(n³)KM 算法
最小路径覆盖DAG 点不相交路径最少条数= n − 最大匹配拆点建图

核心观察

所有"对偶量"（点覆盖 / 独立集 / 路径覆盖）都归约到同一个最大匹配。

不适用

图有奇环、边权重负数且要最小、要求所有匹配 → 换一般图匹配 / 费用流。

01 · DEFINITION

二分图：两部划分 · 无奇环

本页回答：怎么判断一个图是二分图？
两个等价条件。

定义

V = X ∪ Y，X ∩ Y = ∅
所有边 (u,v) 满足 u ∈ X, v ∈ Y
同一部内部无边

等价条件

  • 顶点可 2-染色，相邻点不同色
  • 图中不含奇环
  • 每个连通分量都是二部的
常见误判："无环" ≠ 二分图。二分图可以有偶环（如 4 元环）。

怎么建两部

  • 先染色，颜色 0 → X，颜色 1 → Y
  • 或由题意天然给出（工人/任务、行/列）
  • 染色失败 ⇒ 不是二分图 ⇒ 不能用本讲义的算法

01 · AUGMENT

交错路 · 增广路 · 翻转

本页回答：为什么翻转增广路能让匹配 +1？
三个定义。

三个定义

  • 交错路：边交替 ∈ M / ∉ M
  • 增广路：起止都是非匹配点的交错路
  • 翻转：把路径上匹配边与非匹配边互换

为什么 +1

路径 P = v₀–e₁–v₁–e₂–v₂ … v_k
k+1 个顶点、k 条边，其中 ⌈k/2⌉ 条非匹配边
翻转后 |M| ← |M| + 1
关键：翻转不破坏匹配性质——因为两端本来就未匹配。
记忆：增广路的两个端点都是自由点——这就是"能再塞一条边进去"的含义。
01 · BERGE

Berge 定理：最大 ⇔ 无增广路

本页回答：算法凭什么停止？
终止条件的正确性。

定理

M 是最大匹配
⇔ 不存在关于 M 的增广路

两个方向

  • (⇒) 有增广路 ⇒ 翻转 ⇒ |M|+1 ⇒ M 不是最大
  • (⇐) 若 M 非最大，存在更大的 M'，则 M ⊕ M' 由交错路/圈组成，必含一条增广路
推论：所有最大匹配算法都等价于"反复找增广路直到找不到"。

算法骨架（通用）

while 存在增广路 P:
  翻转 P　　# |M| ← |M| + 1
return |M|

不同算法的差异

  • 匈牙利：一次找一条，DFS 回溯
  • Hopcroft-Karp：一次找一组最短增广路
  • 网络流：把增广路问题转成残量网络最短路
  • 带花树：允许奇环收缩
心法：学算法时永远问一句："它在找哪一种增广路？"

01 · TRACE

手算：一次完整的增广

本页回答：增广路怎么找？
逐轮对照。

图

X = {x₁,x₂,x₃}，Y = {y₁,y₂,y₃}
边：x₁-y₁, x₁-y₃, x₂-y₁, x₂-y₂, x₃-y₂

轮次尝试增广路结果 M
1x₁ → y₁ 空闲x₁–y₁{(x₁,y₁)}
2x₂ → y₁ 被占x₂–y₁–x₁–y₃{(x₂,y₁),(x₁,y₃)}
3x₃ → y₂ 空闲x₃–y₂三对全部匹配

第 2 轮细节

x₂ 试 y₁ → 被 x₁ 占
回溯 x₁，x₁ 的另一个邻居 y₃ 空闲
x₁ 改投 y₃，x₂ 拿下 y₁

观察

  • 每轮恰好一条增广路
  • 找不到增广路时立即停止（Berge 定理）
  • 回溯是关键：把已匹配的点"让"出去
01 · HUNGARIAN

匈牙利 DFS：让位 + 递归

本页回答：回溯"让位"怎么实现？
vis 数组是干什么的。

核心动作

  • 对左部 u，遍历它的邻居 v
  • v 空闲 ⇒ 直接配对，成功
  • v 被 w 占 ⇒ 递归尝试让 w 换个搭档
  • w 换成功 ⇒ u 拿下 v，成功

vis 数组的作用

vis[v]：本轮增广中 v 已被尝试过
防止同一右点被反复试探 → 保证 O(n·m)

注意 vis 作用于右部，每轮重置一次。

复杂度

外层 O(nL) 个左点
每次 DFS O(m)（vis 保证不重复）
合计 O(nL · m)

易错

  • vis 不重置 → 结果偏小
  • vis 作用在左部 → 重复访问
  • 递归深度过大 → 栈溢出（n > 10⁴ 时改迭代）
  • 只增广一次 → 只算出部分匹配
记忆：if matchR[v] == -1 or dfs(matchR[v])——先试空闲，再试让位。

02 · HOPCROFT-KARP

Hopcroft-Karp：分层 + 多路增广

本页回答：为什么分层能加速？
BFS/DFS 各干什么。

BFS：建分层图

  • 所有未匹配左点入队，dist = 0
  • 沿非匹配边到右点，再沿匹配边回左点
  • 记录每个左点的层号 dist[u]
  • 若碰到未匹配右点 ⇒ 存在增广路

DFS：多路增广

  • 只沿 dist[pu] == dist[u] + 1 的边走
  • 成功一条就标记，下一条不再用这些边
  • 一轮 BFS + 多次 DFS = 一次"层内穷尽"

正确性

最短增广路长度单调不减；一轮内穷尽当前最短长度的所有增广路，故每轮至少增加 √n 量级。

02 · KM

KM 算法：顶标与相等子图

本页回答：顶标是什么？
为什么调整就能变最优。

顶标

左顶标 lx[i]，右顶标 ly[j]
可行性：lx[i] + ly[j] ≥ w[i][j]
相等子图：lx[i] + ly[j] == w[i][j] 的边

流程

  • 初始化 lx[i] = max(w[i])，ly[j] = 0
  • 在相等子图上找完美匹配
  • 找不到 ⇒ 算 δ，调整顶标
  • 调整后相等子图扩大，重试
关键定理：在相等子图上的完美匹配，就是原图的最大权匹配。

调整公式

S = 本轮访问过的左点，T = 访问过的右点
δ = min{ lx[a] + ly[b] − w[a][b] : a∈S, b∉T }
lx[a] -= δ（a ∈ S）
ly[b] += δ（b ∈ T）

前提

  • 必须是完全二分图（缺边用极小值填充）
  • 通常假定 nL == nR，否则补虚点
  • 要求最大权；最小权取负或用 −w
复杂度：朴素 O(n⁴)；用 slack 优化到 O(n³)。本讲义给朴素版，好懂好验。

02 · FLOW

网络流建模：匹配 = 最大流

本页回答：怎么把匹配转成流？
为什么需要反向边。

建图

S → u ∈ X（容量 1）
u → v，若 (u,v) ∈ E（容量 1）
v ∈ Y → T（容量 1）

为什么反向边必须有

反向边提供"撤销"能力，等价于翻转增广路。没有反向边，算法只能贪心，结果偏小。

结论：最大流 = 最大匹配；在二分图上 Dinic 也是 O(m√n)。

什么时候必须用流

  • 左点/右点有容量限制（一人多任务）
  • 多源多汇、有额外约束
  • 需要最小割给出的具体方案

03 · KÖNIG

König 定理：最小点覆盖 = 最大匹配

本页回答：构造怎么做？
定向规则为什么这样定。

定理

二分图 G：最小点覆盖 = 最大匹配

只对二分图成立；一般图是 点覆盖 ≥ 最大匹配。

构造（关键）

  • 建有向图：匹配边 右→左，非匹配边 左→右
  • 从所有未匹配左点出发 BFS，得可达集 Z
  • 覆盖 C = (L \ Z) ∪ (R ∩ Z)
方向搞反就全错：匹配边要反着指（右→左），因为增广时要"让位"。

本例

Z = {x₁, x₂, y₂}；C = (L\Z) ∪ (R∩Z) = {x₃} ∪ {y₂} = {x₃, y₂}。
验证：所有边至少一端在 C 中 ✓

03 · INDEPENDENT SET

最大独立集：|V| − 最大匹配

本页回答：独立集与覆盖什么关系？
公式成立的前提。

定义

  • 独立集：两两无边的顶点集合
  • 最大独立集：顶点数最多的独立集

公式推导

最大独立集 = |V| − 最小点覆盖
由 König：= |V| − 最大匹配
只对二分图成立。一般图的最小点覆盖是 NP-hard，公式不适用。

为什么互补

若 C 是最小点覆盖，则 V \ C 必为独立集（否则存在边两端都不在 C，C 就没覆盖住）。反过来亦然。

C 覆盖 ⇔ V\C 独立
|C| + |V\C| = |V|，故一个最小则另一个最大

常见问法

  • 最多选多少个互不冲突的项目
  • 最多放多少个互不攻击的棋子
  • 最大团（补图的最大独立集）
一句话：求最大独立集 = 求最大匹配，不要重新建模。
03 · PATH COVER

最小路径覆盖：拆点 + 最大匹配

本页回答：为什么要拆点？
公式怎么来的。

问题

给 DAG，用最少的点不相交路径覆盖所有顶点。

建图

  • 每个点拆成 u_out 与 u_in
  • 对 DAG 边 u→v，连 u_out → v_in
  • 求最大匹配 m
  • 最小路径覆盖 = n − m
直觉：一条匹配边把两条路径接起来，减少一条；n 个点独立时需 n 条。

区分两种"覆盖"

  • 点不相交（本页）：n − 最大匹配
  • 可重复经过（最小链覆盖）：需传递闭包后再匹配
03 · HALL

Hall 定理：完美匹配的充要条件

本页回答：什么时候存在完美匹配？
怎么找反例。

定理

二分图 G = (X ∪ Y, E) 存在覆盖 X 全部的匹配
⇔ ∀S ⊆ X, |N(S)| ≥ |S|
N(S) = S 的邻居集合

怎么用

  • 判存在性：直接跑最大匹配更快
  • 找反例：最小的 S 使 |N(S)| < |S|
  • 证明题 / 构造题常用
推论：若 |X| = |Y| 且每个点度数 ≥ |X|/2，则必有完美匹配。

反例示例

X = {x₁,x₂,x₃}, Y = {y₁,y₂}
边：x₁-y₁, x₂-y₁, x₃-y₁
取 S = X：|N(S)| = 1 < 3
⇒ 不存在覆盖 X 的匹配

易混

  • Hall 是存在性条件，不是求最大匹配的算法
  • 只对"覆盖 X 全部"不对称；覆盖 Y 需另一条
  • 一般图没有 Hall 定理的对应形式
实战：主要用来理解为什么匹配会失败，真正求解用匈牙利/HK。

四个建模套路

本页回答：拿到题怎么拆成二分图？
每条都配了题型。

1天然两部

工人/任务、学生/志愿、题目/人。题面直接给，照抄建图。

2染色分部

识别信号

  • "每个 X 至多配一个 Y"、"互不冲突"

  • "能否全覆盖"（Hall / 完美匹配）

识别陷阱

  • 一个 X 能配多个 Y → 转网络流（容量 > 1）
  • 有先后顺序约束 → 加拓扑 / 费用流

04 · SPLIT

拆点与容量限制

本页回答：一人能做多个任务怎么办？
怎么把"容量"塞进匹配。

三种扩展

  • 容量 > 1：把左点复制 c 份
  • 多个搭档：转网络流，边容量 = 上限
  • 有先后顺序：DAG + 路径覆盖 / 费用流

复制法示例

工人 i 最多做 c_i 个任务
拆成 c_i 个左点，每个都能连到原邻居
总左点数 = Σc_i，注意规模爆炸
规模提醒：复制法只在 Σc_i 较小时可行；大了必须用网络流。

为什么网络流更好

S → u 容量 c_u
u → v 容量 1
v → T 容量 1

同一张图直接表达"一个人最多接 c 个任务"。

典型变形

  • 一个任务可由多人做 → 右点容量 > 1
  • 需要最少人数 → 最小点覆盖
  • 要总收益最大 → 费用流（每条边带费用）
心法：匹配是网络流的特例；一旦有容量或费用，直接升级到流。

05 · BLOSSOM

带花树：一般图最大匹配

本页回答：奇环为什么麻烦？
收缩是怎么做的。

难点

  • 一般图可能有奇环，无法 2-染色

05 · COMPARE

匹配 / 流 / 费用流对比

本页回答：同一批问题，三种框架都能解？
各自的甜点区。
框架最大匹配带权容量限制最小割/方案代码量推荐

06 · ADAPT

改一改就能用：四个改点

本页回答：换一道题要改哪里？
只有四处。

1建图

决定谁是左部、谁是右部；边的含义是什么（可配对 / 可覆盖 / 可连接）。

2求解量

只要匹配数 → 匈牙利/HK；要方案 → 读 matchL/matchR；要对偶 → König。

3输出

匹配方案、最小点覆盖、最大独立集、路径覆盖——都是同一份匹配的不同视角。

4规模

看 n, m 决定用匈牙利、HK 还是网络流；带权换 KM。

换题检查表

  • 是二分图吗（无奇环）？
  • 边的含义搞对了吗？
  • 要的是匹配数还是具体方案？
  • 有没有容量 / 费用 / 顺序约束？

什么时候该换框架

有容量 → 网络流；有费用 → 费用流；有奇环 → 带花树；要绝对正确且规模大 → 优先 HK。

别硬上：把非二分图硬套二分图匹配，结果是错的而不是"略差"。
06 · VERIFY

怎么验证答案是对的

本页回答：四种算法怎么互相对拍？
边界用例有哪些。

1四算法对拍

暴力枚举所有匹配作基准，与匈牙利 / HK / 网络流比对。随机小图 2000 组，四个数必须完全相等。

3边界用例

  • 无边图（匹配 0）
  • 完全二分图（匹配 = min(nL,nR)）
  • 只有一条边
  • 左右点数不等
  • 有孤立点
  • 单点 / 空图

2不变量检查

  • 匹配数 = sum(1 for v in matchR if v != -1)
  • 匹配的边互不共点
  • |C| == 匹配数（König）
  • |独立集| + |覆盖| == n
  • 路径覆盖 + 匹配 == n
小技巧：随机打乱点编号重跑，答案应不变——能抓出下标类 bug。
König 自检：遍历所有边，确认至少一端在覆盖集中。

07 · SUMMARY

带走这 五句话

本页回答：如果只能记住一页，
就记这一页。
1
核心动作是"增广"：找到起止都自由的交错路，翻转它，匹配数 +1。
