01 · HOOK

三道"长得像"的题，三个模型

本页回答：为什么不能背模板？
因为选错模型 = 全错。

A分组

题意：n 个物品，有些必须一起拿，最少分几组？

→ 并查集，O(α(n)) 每次。
关系是"同类"，自反 / 对称 / 传递。

B配对

题意：n 个工人 m 个任务，每人最多做 1 个，最多配几对？

→ 二分图匹配，O(E√V)。
关系是"可以配对"，非传递。

C分配

题意：工人有工作上限，任务有权重，最小总代价？

→ 网络流 / 费用流，O(V²E)。
关系是"可以传输"，带容量与代价。

★共同点与差异

三者都是"把对象和关系编成图"，但关系的代数性质不同：等价关系可合并，配对关系不可传递，传输关系带容量。选错模型不是"略差"，而是答案就错。

一句话：建模的第一步不是画图，而是问清楚"关系"是什么。

三个判断题

必须同类吗 可以配对吗 有容量/代价吗

答对这三题，模型就定了一大半。

01 · PROBLEM

建模是什么：五个问题

本页回答：拿到题该问什么？
每一问都指向一个模型。
问题问的是答案指向典型陷阱
① 对象点代表什么？（人 / 任务 / 集合 / 位置）建图基础把"集合"当"元素"，重复建点
② 关系边代表什么？（同类 / 配对 / 传输）选模型的关键把"可以配对"当成"同类"，用并查集 → 全错
③ 等价有没有"必须同类"的传递闭包？→ 并查集漏掉传递性，少合并
④ 容量有没有"最多 / 至少"的限制？→ 网络流容量的语义是"限制"还是"代价"
⑤ 代价有没有"最小 / 最大"的总代价？→ 费用流 / KM求最大收益忘了取负
⑥ 方案只要数值还是要具体方案？决定怎么读残量割方向、匹配方案输出
⑦ 规模n、m、边数各多大？选算法用 O(V²E) 跑 n=10⁵
⑧ 动态边会不会删？查询在线吗？→ 离线倒序在线删边用并查集 → 错
⑨ 一般图图一定是二分图吗？→ 带花树有奇环还硬套二分图

三个最常见的错

  • 把"可以配对"当"同类" → 用并查集，答案必错
  • 把"不能同组"当"配对" → 用二分图匹配，答非所问
  • 忽略奇环 → 硬套二分图，染色冲突

好的建模长什么样

三句话说清：点是什么 → 边是什么 → 求什么。
说不出来 = 还没想清楚，先别写代码。

习惯：写题解时固定写"源/汇 → 容量 → 费用 → 为什么是流"或"等价类 → 代表元 → 合并规则"。

01 · FIVE QUESTIONS

五问逐条展开

本页回答：每一问具体怎么答？
答错了会怎样。

1关系是等价吗

  • 自反：A 和 A 同类 ✓
  • 对称：A 同 B ⇒ B 同 A
  • 传递：A 同 B、B 同 C ⇒ A 同 C

三性都满足 ⇒ 并查集。

2关系是配对吗

  • "A 可以和 B 配" ≠ 等价
  • 不对称（工人↔任务）
  • 不传递（A 配 B、B 配 C ≠ A 配 C）

⇒ 二分图匹配。

3关系带容量吗

  • "最多 k 个 / 至少 k 个"
  • "每条边能送 c"
  • "每单位有代价 w"

⇒ 网络流 / 费用流。

三问的"排他性"

一道题可以同时有等价 + 配对 + 容量（例如"先缩点，再匹配，再限流"），这时按顺序叠加模型，而不是三选一。

常见组合

  • 并查集缩点 → 二分图判定（关押罪犯）
  • 二分图匹配 → 网络流（带容量 / 费用的匹配）
  • 二分答案 → 网络流判定（最大值最小）
心法：模型是可叠加的积木，不是互斥的标签。

02 · EQUIVALENCE

并查集：等价关系的传递闭包

本页回答：并查集维护的是什么？
路径压缩为什么对。

三性质

  • 自反：A 与 A 同类
  • 对称：A 同 B ⇒ B 同 A
  • 传递：A 同 B、B 同 C ⇒ A 同 C

两个优化

  • 路径压缩：find 时把沿途点挂到根
  • 按秩合并：矮树挂到高树下
  • 两者同时用 ⇒ 单次 O(α(n))
边界：并查集不支持删边（在线）。要删边请离线倒序（第 16 页）。

为什么并查集做不了"配对"

"A 可以和 B 配"不是等价关系（不传递）。若强行 union(A,B)，会把所有可配对对象合并成一个集合，答案必错。

02 · WEIGHTED

带权并查集：关系偏移

本页回答：怎么维护"两点之间的关系"？
符号怎么推。

核心

d[x] = x 与父节点的关系
type[x] = (type[root] + d[x]) % 3
rel(x,y) = (d[y] − d[x]) % 3（同根时）

合并公式

想要 rel(x,y) = rel
d[ry] = (rel + d[x] − d[y]) % 3
由 type[y] − type[x] ≡ d[ry] + d[y] − d[x] 推出
符号最易写反：已从守恒式重新推导并逐句验证（见右下角）。

三种关系（食物链）

rel = (type[y] − type[x]) % 3
0 = 同类
1 = x 吃 y
2 = y 吃 x
约定 type i 吃 type (i+1)%3

逐句验证

  • union(0,1,1)：0 吃 1 → True
  • union(1,2,1)：1 吃 2 → True
  • union(2,0,1)：2 吃 0 → True（环形）
  • union(0,1,0)：0 与 1 同类 → False ✓
二元版本：把 % 3 换成 ^（异或），rel ∈ {0,1}，用于分队 / 关押罪犯。
02 · TEMPLATE

模板二：带权并查集

本页回答：三类关系的标准实现。
含逐句验证。

三个关键

  • find 递归压缩时累加 d
  • 压缩顺序：先递归，再更新 d[x]，最后改 p[x]
  • 同根时只做一致性检查，不合并

易错

  • d[ry] 公式符号写反 → 语句真假全错
  • 压缩时先改 p[x] 再读 d[p[x]] → 读到根的值
  • 把"必须同类"和"不能同队"混成一种 rel
用途：食物链、关押罪犯、奇偶并查集、银河英雄。

02 · CASES

并查集建模案例

本页回答：哪类题想到并查集？
四个典型。

A亲戚

题意：给出若干"X 与 Y 是亲戚"，判断两人是否亲戚。

建模：点 = 人，边 = "是亲戚"。
答案：same(x,y)。

B食物链

题意：三类动物，A 吃 B、B 吃 C、C 吃 A。统计假话数。

建模：带权并查集，rel ∈ {0,1,2}。
答案：矛盾即假话。

C关押罪犯

题意：n 个罪犯分两所监狱，某些人不能同监，最小化最大怨气。

建模：二分答案 + 奇偶并查集（rel ∈ {0,1}）。
答案：最小可行怨气。

D银河英雄

题意：战舰排成队列，合并队列、查询两舰间距。

建模：带权并查集 + 距离偏移 + 队列长度。
答案：两点间距 − 1。

共同结构

都是"给出若干约束，判断一致性 / 统计状态"。并查集把传递闭包压缩成 find，代价几乎为零。

什么时候不够用

  • 要配对（最多几对）→ 二分图
  • 要容量 / 代价 → 网络流
  • 要删边（在线）→ LCT 或离线倒序
心法：看到"必须 / 同类 / 亲戚 / 一起"这类传递性词，第一反应是并查集。
02 · REVERSE

并查集的反向运用

本页回答：正着做不出来时，
倒着做为什么就顺了。

两个经典

  • Kruskal：边按权排序，能连就连

为什么倒序有效

"删边"在并查集里不可撤销，但把时间倒过来，"删"就变成了"加"，而"加"正是并查集擅长的。

适用条件

  • 所有操作提前给出（离线）
  • 只问"连通性"，不问最短路
  • 要在线回答 → 需 LCT / 线段树分治

03 · BIPARTITE

二分图：判定与染色

本页回答：什么是二分图？
判定与匹配的区别。

定义

顶点可分为 X ∪ Y，每条边一端在 X、一端在 Y
⇔ 无奇环　（2-可着色）

判定 ≠ 匹配

  • 判定：能不能二染色？（可行性）
  • 匹配：最多配几对？（最优化）
  • 先判定再匹配，否则可能在非二分图上跑 HK
判别技巧：见到"不能同组 / 互斥 / 敌对"就是边，判定染色。

什么时候会误用

  • 图未必是二分图（题面没说）
  • 把容量塞进二分图 → 应该用网络流
  • 把一般图匹配硬当二分图 → 需带花树

03 · MATCHING

匹配模型：匈牙利 vs Hopcroft-Karp

本页回答：两种匹配算法怎么选？
各自的甜点区。
算法时间代码量思路推荐
匈牙利（DFS）O(V·E)25 行逐点找增广路教学 / n ≤ 500
Hopcroft-KarpO(E√V)50 行BFS 分层 + 多路增广默认
Dinic（容量 1）O(E√V)60 行网络流自动降级需要容量 / 费用扩展
一般图匹配（带花树）O(V³)200 行处理奇环非二分图时唯一解
KM（最大权匹配）O(V²E)120 行顶标 + 交错树有权配对

HK 与 Dinic 的关系

  • HK 就是"二分图上的 Dinic"
  • 两者都每轮 BFS 分层、多路增广
  • 网络流版更通用（可加容量 / 费用）
  • 纯匹配时 HK 代码更短、常数更小

三种问法的转换

最小点覆盖 = 最大匹配（König）
最大独立集 = n − 最大匹配
最小路径覆盖 = n − 最大匹配

求方案时用交替 BFS 输出（第 22 页）。

记忆：匹配三连问——最大匹配、最小点覆盖、最大独立集，数值互相可推。

03 · KÖNIG

König 定理：匹配 ↔ 覆盖

本页回答：怎么从匹配拿到最小点覆盖方案？
交替 BFS 怎么走。

三个量的关系

最小点覆盖 = 最大匹配
最大独立集 = n − 最大匹配
（n = 左 + 右总点数）

交替 BFS 口诀

  • 起点：未匹配左点
  • 左 → 右：走非匹配边
  • 右 → 左：走匹配边
  • 覆盖 = 左部未访问 ∪ 右部已访问
自检：|cover| == |匹配| 且 |indep| == n − |匹配|。

04 · FLOW

网络流：容量与代价

本页回答：网络流编码什么？
建模三问怎么答。

建模三问

  • 源 / 汇代表什么？（供给 / 需求）
  • 容量代表什么限制？
  • 费用代表什么代价？

两个对偶量

最大流 = 最小割
割 (S,T)：s ∈ S，t ∈ T
割容量 = Σ c(u,v)，u∈S, v∈T
增广：残量网络上找 s→t 路径，加 Δ（正减反加）。反向边 = 撤销能力。

三种建模模式

  • 选 / 不选：割 = 代价（闭合子图）
  • 分配：容量 = 限制（多重匹配）
  • 传输：费用 = 代价（MCMF）

什么时候网络流是"杀鸡用牛刀"

  • 只要连通块 → 并查集就够
  • 只要最大匹配 → HK 更短更快
  • 纯等价关系 → 并查集，不用流
但注意：一旦出现容量或代价，二分图就顶不住了，必须升级到网络流。

模板五：Dinic

本页回答：最大流的默认写法。
建议闭卷默写。

四个关键点

  • add 必须同时加反向边（容量 0）
  • bfs 建分层，返回能否到 t
  • it 每轮 BFS 后复位
  • level[v] == level[u]+1 保证最短

复杂度

一般 O(V²E)
单位容量 / 二分图 O(E√V)
用途：跑完后 dinIC.g 就是残量网络，可直接做最小割构造。

04 · MIN-CUT

最小割建模：选 / 不选

本页回答：割代表什么决策？
怎么把代价编码成割。

核心手法

  • S 侧 = 选，T 侧 = 不选
  • 割容量 = 付出的总代价
  • INF 依赖边 = 不许割（约束）
  • 答案 = 常数 − 最小割

三个典型

  • 闭合子图：选项目，有依赖
  • 方格取数：相邻不能同取
  • 黑白染色代价：二分图上的割

构造步骤

1) 跑 max_flow(s, t)
2) 残量上 s BFS → 可达集 S
3) 割 = (S, V\S)；方案 = S 中的点

易错

  • 割只算 S→T 方向的边
  • INF 不够大 → 依赖被误割
  • 忘了减 Σ正权 → 结果是割不是收益
  • 权可正可负 → 先判全负 / 全正
心法：把"选择的代价"编码成割，把"资源的限制"编码成容量。
04 · TEMPLATE

模板六：最大权闭合子图

本页回答：闭合子图怎么写？
为什么转成最小割。

关键点

  • 正权点接 s，负权点接 t
  • 依赖边容量 = INF
  • 答案 = 正权总和 − 最小割
  • 选中点 = 残量上 s 可达的点

验证样例

weight = [3, -1]，deps = [(0,1)]
选 0 必选 1 ⇒ 3−1 = 2
输出 (2, [0, 1])

04 · MCMF

费用流速查

本页回答：费用流和二分图有什么关系？
什么时候必须上费用流。

两种算法

  • SPFA 版：O(V·E·flow)，支持负权
  • Dijkstra + 势：O(E log V·flow)，默认
反向边费用 = −w（不是 +w）
cost += d * h[t]（不是 dist[t]）

与 KM 的等价

二分图最大权匹配 = 网络流费用流的特例。
KM 的顶标 ≈ MCMF 的势函数 h——两者都是"抬权使边非负"。

什么时候必须上费用流

  • 配对有权且要最大权 → KM / MCMF
  • 配对有容量（> 1）→ MCMF
  • 要最小总代价的流分配 → MCMF
  • 要最小割方案 → Dinic

易错清单

  • 反向边费用写成 +w
  • 求最大收益忘了取负
  • 势未对可达点更新 → Dijkstra 挂
  • 负环未处理 → 死循环
心法：费用流 = "Dinic 的思想 + 最短路的骨架"；KM = "费用流的特例"。

05 · CROSS B

同题三解 B：分队判定

本页回答：并查集怎么做二分图判定？
网络流为什么不适用。

题意

n 个人，must = [(a,b)] 必须同队，conflict = [(a,b)] 不能同队。能否分成两队？

三种建模

  • 奇偶并查集 ✅ rel ∈ {0,1}，O(α(n))
  • DSU 缩点 + 二分图判定 ✅ 概念清晰
  • 网络流 ❌ "不能同队"是非子模约束
为什么网络流不行："不能同队"的代价表 (0,0)=∞, (1,1)=∞, (0,1)=0, (1,0)=0 不满足子模性，无法规约到最小割。强行建模得到的是无意义解。

两种正确解法

解 1 奇偶并查集
  union(a, b, 0) 必须同队
  union(a, b, 1) 必须不同队
  矛盾 ⇒ False

解 2 DSU 缩点 + 二分图判定
  先按 must 合并
  再在缩点图上建 conflict 边
  is_bipartite 判染色

两者等价

奇偶并查集维护的 d[x] 就是到根的染色偏移；缩点 + 染色是它的图论视角。两者答案必然一致。

自检：用随机小图对拍两种写法，答案必须相同。

核心教训

不是所有约束都能进网络流。能进的是"子模"约束（同类、代价单调），不能进的是"互斥"类硬约束。

05 · REDUCTION

归约关系：谁是谁的特例

本页回答：三种模型能互相转化吗？
哪些不能。
归约方向说明
二分图最大匹配 → 网络最大流✅ 成立容量全设 1，s→左→右→t
二分图最大权独立集 → 最小割✅ 成立二分图上的割，闭合子图特例
二分图 2-着色 → 带权并查集✅ 成立奇偶并查集（rel ∈ {0,1}）
最小点覆盖 → 最大匹配✅ 成立König 定理
最小路径覆盖 → 最大匹配✅ 成立拆点，n − |匹配|
二分图最大权匹配 → 费用流✅ 成立KM ≡ MCMF（顶标 ≡ 势）
一般图匹配 → 网络流❌ 不成立需带花树（blossom）
"不能同队"约束 → 最小割❌ 不成立非子模约束
动态连通（在线删边）→ 并查集❌ 不成立需 LCT / 离线倒序
NP-hard（装箱 / 一般独立集）❌ 不成立无多项式模型

重要结论

  • 二分图匹配 ⊂ 网络流（容量 1 的特例）
  • 并查集 ⊂ 二分图判定（奇偶关系）
  • 但三者不可互相替代——各有失效区

为什么归约有用

把新问题归约到已知模型，就能直接复用代码与复杂度结论。
但要先确认归约条件成立（二分、子模、离线……）。

心法：归约前先问"这个转化保不保最优解"。

05 · IRREPLACEABLE

什么时候必须用哪个

本页回答：三个"不换不行"的场景。
以及换掉会怎样。

并查集

  • 动态连通性：O(α(n))，网络流是 O(V²E)
  • Kruskal：MST 唯一自然解
  • 离线删边：倒序 union
  • 等价闭包：连通块 / 代表元

换掉会：慢 4~5 个数量级，或直接错。

二分图

  • 2-着色判定：O(V+E)，最快
  • König 方案：交替 BFS 直出
  • 一般图匹配入口：判断是否需带花树
  • 纯匹配：HK 比 Dinic 短

换掉会：能做但更重、更易错。

网络流

  • 带容量的分配：HK 顶不住
  • 最小割方案：二分图做不到
  • 费用流：KM 是特例
  • 闭合子图：依赖 + 权

换掉会：问题无解（其他模型表达不了）。

三种"选错"的后果

  • 把配对当同类 → 并查集答案必错
  • 把互斥塞进最小割 → 无意义解
  • 在非二分图跑 HK → 漏匹配

决策口诀

先问关系是什么，再问有没有容量和代价。
关系定模型，容量代价定升级到网络流。

升华：建模能力 = "识别关系的代数性质"，而不是背模板。

带走这 五句话

本页回答：如果只能记住一页，
就记这一页。
1
先问关系是什么：等价 → 并查集；配对 → 二分图；传输 → 网络流。
2
等价关系可合并，配对关系不可传递。把"配对"当"同类"是最大坑。
3
容量与代价是升级信号。一出现就从二分图升到网络流。
4
模型可叠加：缩点 → 染色 → 匹配 → 限流，按顺序堆。
5
不是所有约束都能进网络流。互斥类硬约束是非子模，只能用并查集 / 染色。
升华：建模最值得学的不是模板，而是"识别关系的代数性质"——等价可合并、配对不传递、传输带容量。这一条判断力，比任何单个算法都值钱。
