01 · HOOK

三道"长得像"的题，三种结构

本页回答：为什么不能背模板？
选错不是"略慢"，是"TLE / WA"。

A单点改 + 区间和

题意：数组，单点加值、查询区间和。

→ 树状数组 O(log n)，30 行，常数极小。
用线段树也能做，但杀鸡用牛刀。

B区间改 + 区间 max

题意：区间加 / 区间赋值、查询区间最大值。

→ 线段树 O(log n)，双懒标记。
BIT 表达不了 max（不满足可差分性）。

C动态第 k 小 / 前驱

题意：插入 / 删除元素，求第 k 小、前驱、后继。

→ 平衡树 O(log n) 或值域线段树。
线段树能做但代码量翻倍。

★共同点与差异

三者都在做"把暴力的 O(n) 查询降到 log / √"。区别在操作语义——前缀和、区间、有序集。选错语义不是"略慢"，而是根本表达不了（BIT 做不了 max）或代码爆炸。

一句话：选型的第一问不是"复杂度多少"，而是"操作语义是什么"。

三个判断题

能差分 / 前缀吗 要区间改 + 区间查吗 要前驱 / 第 k 小吗

答对这三题，结构就定了。

问题问的是答案指向典型陷阱

好的选型长什么样

1操作语义

  • 能差分吗？→ BIT
  • 要区间改吗？→ 线段树

2复杂度形态

  • O(1)：前缀和 / ST 表 / 单调栈
  • O(α)：并查集
  • O(log)：BIT / 线段树 / 平衡树
  • O(√)：分块

⇒ 复杂度 = 操作次数 × 单次代价。

3常数与空间

  • BIT 常数 ~1/3 线段树
  • 线段树空间 4n，BIT n
  • 分块空间 n + 块数

⇒ n = 10⁷ 时，空间先于时间爆。

三问的"叠加性"

一道题可以同时要好语义、好复杂度、好常数。这时按顺序叠加，而不是三选一。最常见的顺序是：先定语义 → 写朴素 → 验证 → 再优化。

常见组合

  • 前缀语义 + 差分 + BIT（区间加区间和）
  • 区间语义 + 懒标记 + 线段树（区间改区间 max）
  • 有序语义 + 值域 + 平衡树 / 主席树（第 k 小）
  • 任意语义 + 分块（兜底）
心法：选型是可叠加的积木——语义、复杂度、常数三层各自独立，别一次写到底。

02 · FENWICK

树状数组：lowbit 是"前缀分解"

本页回答：BIT 的核心是什么？
为什么 i & -i 是关键。

核心原理

lowbit(i) = i & -i（i 的最低位 1）
节点 i 覆盖区间 (i - lowbit(i), i]

前缀和 sum(i) = Σ t[j]，j = i, i-lowbit(i), ...
每次跳跃至少减半 → O(log n)

四个关键点

  • 数组下标从 1 开始（lowbit(0)=0 死循环）
  • add(i, d) 向上跳：i += lowbit(i)
  • sum(i) 向下跳：i -= lowbit(i)
  • 本质是前缀和的树状分解，不是二叉树
失效：BIT 做不了 max / min（不满足可差分性）；做不了区间赋值。

三个易错

  • 数组从 0 开始 → lowbit(0) = 0 死循环
  • 写成 for i in range(n): add(i, ...) → 漏掉最后一个
  • BIT 试图做 max → 合并不可逆，直接 WA

02 · TEMPLATE

模板二：BIT 区间加区间和 · 二维

本页回答：差分怎么配两个 BIT？
二维怎么写。

四个关键点

  • 差分 b[i] = a[i] - a[i-1]，则 a[1..x] = Σ b[k]
  • 推得 Σa[1..x] = (x+1)·Σb - Σ(i·b[i])
  • 维护两个 BIT：B1 存 b[i]、B2 存 i·b[i]
  • 二维：rect_sum 用容斥四点

验证样例

a = [_, 3, 1, 4, 1, 5]
prefix_sum(5) = 14 · range_sum(2,4) = 6
range_add(2,4,10) 后 prefix_sum(5) = 44
二维：rect_sum(1,1,2,2) = 7
易错：_add(r+1, -delta) 在 r=n 时被 BIT 静默忽略——不影响任何 x ≤ n 的查询，但别把它当成 bug 反复调试。

02 · CASES

树状数组建模案例

本页回答：哪类题想到 BIT？
四个典型。

A逆序对

题意：求序列中逆序对数量。

建模：离散化 + BIT 计数。
答案：O(n log n)。

B动态区间和

题意：单点加、区间求和。

答案：O(log n) / 次。

C区间加区间和

题意：区间加、区间求和。

建模：差分 + 双 BIT。
答案：O(log n) / 次。

D二维偏序

共同结构

什么时候不够用

  • 要区间 max / min → 线段树 / ST 表
  • 要区间赋值 → 线段树（双懒）
  • 要前驱后继 / 插入删除 → 平衡树
心法：看到"能差分 / 能前缀 / 能计数"，第一反应是 BIT。

03 · SEGMENT TREE

线段树：懒标记是"延迟兑现"

本页回答：懒标记为什么对？
什么时候必须下推。

核心原理

区间 [l, r] 完全覆盖 → 直接更新并打懒
否则 _push 懒到子，再递归

lazy[u] 表示"u 的整段还没兑现的修改"
查询子区间前必须 _push，否则读到旧值

四个关键点

  • 递归版空间 4n，迭代版 2n
  • 只有当查询/修改穿过节点时才 _push
  • 双懒时 assign 优先于 add
  • sum[u] = sum[lc] + sum[rc]（pull）
复杂度：每次操作 O(log n)，空间 O(4n)。

三个易错

  • 查询子区间前忘了 _push → 读到旧值
  • 双懒时赋值后没清 add → 后续加错
  • 空间开 2n 而非 4n → 递归版 RE

04 · SQRT DECOMP

分块：根号是"万能兜底"

本页回答：分块的核心是什么？
为什么"几乎不会写错"。

核心原理

把数组切成 ⌈√n⌉ 块，块大小 B = ⌊√n⌋ + 1
整块：读块和 + 整块懒
零散：暴力改元素 + 同步块和

每次 O(B + n/B) = O(√n)

四个关键点

  • 块大小 B = int(n**0.5) + 1
  • 索引 (i-1) // B（不是 i // B）
  • 整块懒用 block_size[b] 而非 B
  • 零散修改前先 _push_block
优势：代码 ~50 行，几乎不会写错；任何操作都能做。

复杂度对照

操作BIT线段树分块
区间加区间和O(log n)O(log n)O(√n)
区间加区间 max不支持O(log n)O(√n)
区间赋值不支持O(log n)O(√n)
区间第 k 小O(log²)O(log n)O(√n log)
前驱后继O(log V)O(log n)O(√n log)
代码量30 行90 行55 行
写错概率低中极低

三个易错

  • 块索引用 i // B → 第 0 块含"幽灵元素 0"
  • 整块懒 += delta * B → 最后一块元素数不足
  • 零散修改没先 _push_block → 懒叠加错误
心法：分块是常数友好、几乎不会写错的兜底——√n 卡不掉时优先用。

套娃：BIT 套权值线段树

本页回答：套娃在解什么？
为什么是 O(log² n)。

核心思路

外层 BIT 维护前缀（位置）
内层 权值线段树 维护值域分布

修改：沿 BIT 链走 log n 棵内层树
查询：在 log n 棵树上同时二分

复杂度

  • 每次修改 O(log n · log V)
  • 每次查询 O(log n · log V)
  • 空间 O(n log n)（动态开点）
用途：动态区间第 k 小、动态逆序对、动态区间排名。

与单结构对照

方案查询修改空间
主席树O(log n)不支持O(n log n)
平衡树O(log n)O(log n)O(n)
套娃O(log² n)O(log² n)O(n log n)
分块O(√n)O(√n)O(n)

什么时候用

  • 平衡树就够 → 别上套娃（代码量大）
  • 只静态 → 主席树更快
  • √n 卡不掉 → 分块更简单

其它套娃

  • 线段树合并：树上问题合并 O(n log n)
  • 线段树分治：离线带撤销 O(n log² n)
  • 点分治：树上路径计数 O(n log² n)
心法：套娃是组合技——单结构不够时，用外层管位置、内层管值域的思路拆解。
05 · CASES

特殊结构建模案例

本页回答：哪类题想到特殊结构？
四个典型。

A静态 RMQ

题意：多次查询区间最小值，无修改。

建模：ST 表。
答案：O(n log n) 预处理 + O(1) 查询。

B最近更大元素

题意：每个元素右边第一个比它大的。

建模：单调栈。
答案：O(n) 均摊。

C最小生成树

题意：求连通图的最小生成树。

建模：Kruskal + 并查集。
答案：O(m log m)。

D动态第 k 小

题意：插入 / 删除，求第 k 小。

建模：平衡树或套娃。
答案：O(log n) 或 O(log² n)。

共同结构

都是"特定语义的专用解"。识别信号：静态 RMQ、单调性、连通性、有序集。

什么时候不够用

  • 语义不匹配 → 用通用结构（线段树 / 分块）
  • 要删边 → 并查集失效
  • 要非幂等 → ST 表失效
心法：特殊结构是专用工具——语义对上就快一个数量级。

06 · CROSS B

同题三解 B：区间第 k 小

本页回答：同一道题，三种建模怎么选？
甜点区在哪。

Q1主席树

题意：静态区间第 k 小。

  • 可持久化线段树
  • O(log n) 查询
  • O(n log n) 空间

甜点：q 大 + n 中等。
失效：要修改。

Q2分块 + 二分

题意：同上。

  • 块内排序 + 二分答案
  • O(√n log V) 查询
  • 代码 ~40 行

甜点：代码短、好调。
失效：n 大 + q 大。

Q3暴力排序

题意：同上。

  • 直接 sorted(a[L:R+1])[k-1]
  • O(n log n) 查询
  • 一行代码

甜点：正确性基准。
失效：任何大数据。

一句话对照

"怎么实现第 k 小"取决于规模与操作。静态用主席树，n 小用分块，动态用套娃 / 平衡树。三者必须一致。

一致性

三种建模答案必须一致——这是最强的正确性检查。cross_check_kth 会把三者对拍。

提醒：主席树必须离散化，否则值域开不下；分块的块内排序只在静态有效。
心法：第 k 小的本质是"值域上的秩"，实现方式取决于是否动态、规模多大。
06 · CROSS C

同题三解 C：动态前驱后继

本页回答："有序集"怎么实现？
三个层次。

Q1平衡树（Treap）

题意：插入 / 删除元素，求前驱、后继、第 k 小。

  • BST + 随机优先级
  • O(log n) 每次
  • 代码 ~140 行

甜点：值域大、n 大。
失效：写错难调。

Q2值域 BIT + 二分

题意：同上，但值域小。

  • BIT 维护计数
  • O(log V) 每次
  • 代码 ~40 行

甜点：值域 ≤ 10⁵。
失效：值域大。

Q3分块 + 块内排序

题意：同上。

  • 块内有序 + 二分
  • O(√n log n) 每次
  • 代码 ~60 行

甜点：√n 卡不掉。
失效：n、q 都大。

一句话对照

"有序集"的实现取决于值域大小与操作数。值域小用值域 BIT，值域大用平衡树，√n 卡不掉用分块。

规约关系

Q2 是 Q1 的值域特化——当值域 ≤ n 时，值域 BIT 等价于平衡树但常数小。这是"按规模选结构"的典范。

提醒：值域 BIT 不支持重复元素的"任意删除"（只能减计数），语义上要小心。
心法：看到"前驱 / 后继 / 第 k 小"，先问值域多大、操作多少，再选结构。
06 · REDUCTION

归约关系：谁是谁的特例

本页回答：四条主线能互相转化吗？
哪些不能。
归约方向说明
前缀和 → BIT✅ 成立BIT 是可修改的前缀和
BIT → 线段树✅ 成立BIT 是线段树的特例（只支持可差分聚合）
线段树 → 分块⚠️ 部分分块能做但慢；语义上通用
ST 表 → 线段树✅ 成立ST 表是静态线段树的 O(1) 优化
并查集 → 图连通✅ 成立并查集是只增不删的连通性
单调栈 → 线段树⚠️ 部分能做但慢一个数量级
平衡树 → 值域线段树⚠️ 部分值域小时更优
主席树 → 平衡树⚠️ 部分主席树静态，平衡树动态
套娃 → 单结构⚠️ 部分值域小时退化成 BIT
分块 → 任意结构✅ 成立分块是万能兜底（慢）
树链剖分 → 线段树✅ 成立HLD = 树上 dfs 序 + 线段树
BIT → 区间 max❌ 不成立max 不可差分
ST 表 → sum❌ 不成立sum 不幂等
并查集 → 删边❌ 不成立需 LCT / 可撤销
BIT → 可持久化❌ 不成立树结构固定，改主席树
单调栈 → 非单调问题❌ 不成立须单调性

重要结论

  • BIT ⊂ 线段树（可差分特例）
  • ST 表 = 静态线段树的 O(1) 化
  • 分块 ⊃ 一切（但慢）

为什么归约有用

把新问题归约到已知结构，就能直接复用复杂度结论。
但要先确认归约条件成立（可差分 / 幂等 / 无删边）。

心法：归约前先问"这个转化保不保语义"。

06 · IRREPLACEABLE

什么时候必须用哪个

本页回答：四个"不换不行"的场景。
以及换掉会怎样。

树状数组

  • 能差分问题的最小代码量
  • 常数是线段树的 1/3
  • 值域 BIT 做动态排名

换掉会：用线段树写 90 行，常数 ×3。

线段树

  • 区间改 + 区间查的唯一自然解
  • 懒标记 / 可持久化 / 合并的入口
  • 树链剖分的唯一载体

换掉会：BIT 表达不了 max / 赋值。

分块

  • 万能兜底，几乎不会写错
  • √n 卡不掉时的救命稻草
  • 莫队 / 根号分治的载体

换掉会：复杂操作写不动线段树时无解。

平衡树

  • 动态有序集的唯一 log 解
  • 前驱后继 / 第 k 小 / 排名
  • 文艺平衡树（区间翻转）

换掉会：值域大时值域结构失效。

三种"选错"的后果

  • 用 BIT 做区间 max → 直接 WA
  • 静态 RMQ 上线段树 → 常数 ×3、可能 MLE
  • √n 卡不掉时上分块 → TLE

决策口诀

先问语义，再问规模，最后问常数。三问定结构。

升华：数据结构选型能力 = "把操作语义翻译成复杂度形态"，而不是背模板。

07 · CORRECTNESS

正确性与复杂度

本页回答：数据结构为什么对？
怎么算复杂度。

复杂度怎么算

  • BIT：lowbit 每次至少减半 → O(log n)
  • 线段树：每次操作走 O(log n) 层
  • 分块：O(B + n/B)，B = √n 时最优
  • 并查集：路径压缩 + 按秩合并 → O(α(n))

正确性三问

  • 不变量：每个节点存的是它覆盖区间的真实值吗？
  • 懒标记：下推后子区间拿到正确值了吗？
  • 边界：空区间、单元素、越界处理对吗？

常见漏点

  • 线段树懒标记没下推
  • 分块块大小算错
  • BIT 下标从 0 开始 → 死循环

证明手法

  • 不变量归纳：操作后不变量仍成立
  • 对拍：小数据与暴力一致（最实用）
  • 边界用例：n=0/1/2、全相等、单元素区间
  • 随机化：随机数据跑 300 次

验证三层

  • 边界：空区间、单元素、块边界
  • 不变量：答案与暴力一致
  • 边界用例：n = 0 / 1、全 0、极值

优化前后的对拍

朴素版与优化版必须对拍——优化只改实现，不改语义。任何结构上线前都应通过 stress_ds()。

心法：数据结构的正确性是设计出来的——不变量写清，边界覆盖，对拍通过。
07 · PITFALLS

易错清单 Checklist

本页回答：提交前自检什么？
（每条都对应本讲义的坑）

BIT / 树状数组

  • 数组从 0 开始 → lowbit(0)=0 死循环
  • BIT 试图做 max（不可差分）
  • 区间加忘配第二个 BIT
  • 二维容斥符号写反
  • 离散化漏了重复元素
  • 倍增 kth 起点不是最大 2 的幂

线段树

  • 查询子区间前忘了 _push
  • 双懒时赋值后没清 add
  • 空间开 2n 而非 4n
  • pull 写漏（sum[u] = lc + rc）
  • 区间边界 ql ≤ l && r ≤ qr 写错
  • 递归 RE（n 大时栈溢出）

分块 / 特殊结构

  • 块索引 i // B → 含"幽灵元素 0"
  • 整块懒 += delta * B → 最后一块算多
  • 零散修改没先 _push_block
  • ST 表用在 sum 上（不幂等）
  • 并查集递归 find 爆栈
  • 单调栈相等元素处理不一致
  • Treap 旋转后忘了 pull
提交前 30 秒四连问：① 语义对吗（BIT 做不了 max） ② 边界对吗（块大小 / 空间 / 越界） ③ 懒标记下推了吗 ④ 对拍通过了吗。

07 · VERIFY

怎么验证结构选对了

本页回答：四种结构怎么互相对拍？
边界用例有哪些。

1跨结构对拍

能用两种结构解的题，必须对拍。brute / BIT / 线段树 / 分块 一致——这是最强的正确性检查。

3边界用例

  • n = 0 / 1 / 2
  • 全相等 / 全 0 / 极值
  • 块边界（l, r 恰在块交界）
  • 单元素区间（l == r）
  • 空区间（l > r）
  • 值域边界（最小 / 最大值）
  • 树形：单点 / 链 / 星

2不变量检查

  • BIT：与暴力前缀和一致
  • 线段树：与暴力区间和一致
  • 分块：与 BIT / 线段树一致
  • 主席树：与 sorted(a[L:R+1])[k-1] 一致
  • ST 表：与暴力 RMQ 一致
  • 并查集：与暴力 BFS 连通性一致
  • 单调栈：与暴力最近更大一致
  • Treap：与排序列表一致
小技巧：随机打乱输入顺序重跑，答案应不变（除非问题本身有序）。
最强自检：能用两种结构的题，一定对拍；不能的题，用暴力小数据对拍。
