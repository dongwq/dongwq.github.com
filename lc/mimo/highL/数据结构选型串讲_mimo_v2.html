01 · HOOK

一道题五种解法，选错 = TLE / WA

本页回答：选型错在哪？
不是"略慢"，是"根本不成立"。

A区间加 + 区间和

题意：数组，区间加值、查询区间和。n, q ≤ 10⁵

  • BIT 差分 ✅ O(log n)，30 行
  • 线段树 ✅ O(log n)，90 行
  • 分块 ✅ O(√n)，55 行

三者语义等价，选哪个看规模与常数。

B区间加 + 区间 max

题意：区间加、查询区间最大值。

  • 线段树 ✅ O(log n)
  • 分块 ✅ O(√n)
  • BIT ❌ 根本表达不了

max 不可差分，BIT 直接出局——这是语义错，不是复杂度错。

C动态第 k 小

题意：插入 / 删除元素，求第 k 小。

  • 平衡树 ✅ O(log n)
  • 值域 BIT ✅ O(log V)（值域小）
  • 分块 ⚠️ O(√n log)（勉强）

主席树 静态，动态下必须套娃或换结构。

★三道题的差别在哪

都在做"把暴力的 O(n) 查询降到 log / √"。差别是操作语义：可差分 / 区间聚合 / 有序集。选错语义不是"略慢"，是根本表达不了（BIT 做不了 max）或代码爆炸（线段树做有序集）。

一句话：选型的第一问不是"复杂度多少"，而是"操作语义是什么"。

三个判断题

能差分 / 前缀吗 要区间改 + 区间查吗 要前驱 / 第 k 小吗

答对这三题，结构就定了。剩下的只是常数与代码量。

⑩ 是否单调最近更大 / 滑动窗口？→ 单调栈 / 队列暴力 O(n²) 在 n = 10⁶ TLE

三个最常见的错

  • 用 BIT 做区间 max（不可差分）
  • 线段树懒标记没下推就查询子区间
  • 分块块大小算错，最后一块元素数 < B 时整块懒多算

好的选型长什么样

三句话说清：操作集是什么 → 复杂度落在哪档 → 为什么其它结构不合适。说不出来 = 还没想清楚。

习惯：写题解时固定写"操作集 → 结构 → 复杂度 → 空间"四行，一行不能少。

02 · MAINLINE 1

并查集：连通性的 α

本页回答：什么时候必须用并查集？
与其它三条的关系。

语义合并 + 查连通

  • 只回答"是否连通"，不回答"路径是什么"
  • 只增不删——删边直接失效
  • 路径压缩 + 按秩合并 → O(α(n))

带权扩展：种类 / 奇偶 / 敌人关系；可撤销扩展：线段树分治。

甜点区

  • 连通块数量 / 大小
  • Kruskal 最小生成树
  • 等价类划分、离线最近公共祖先
  • 动态连通（只加边）

失效区

  • 删边 → 需 LCT / 可撤销
  • 路径查询 → 树链剖分 + 线段树
  • 有序查询（前驱 / 第 k 小）→ 平衡树
  • 区间聚合 → 线段树

与其它三条的关系

对比结论
并查集 vs 树状数组正交：连通 vs 前缀
并查集 vs 线段树正交：连通 vs 区间
并查集 vs 分块正交：连通 vs 兜底
并查集 vs BFS 查连通并查集快 O(n) 倍
并查集 vs 树链剖分后者能查路径

建模案例

  • 亲戚：合并 + 查询是否亲戚 → 并查集
  • 最小生成树：边排序 + union
  • 种类并查集：带权 dist mod 2
  • 可撤销：线段树分治 + 栈
一句话：看到"合并 / 连通 / 等价类 / 最小生成树"，第一反应是并查集；要删边或查路径，立刻换。
02 · MAINLINE 2

树状数组：能差分就最快

本页回答：什么时候必须用 BIT？
与线段树 / 分块怎么取舍。

语义单点改 + 前缀查

  • 只支持可差分聚合：sum / xor / cnt
  • lowbit(i) = i & -i 前缀分解
  • O(log n)，常数是线段树的 1/3

扩展：双 BIT（区间加区间和）、二维 BIT、值域 BIT（第 k 小）。

甜点区

  • 单点改 + 区间和（最小代码量）
  • 逆序对、动态排名、二维偏序
  • 值域 BIT 做动态第 k 小（值域小时）
  • n 大、空间紧（O(n) 而非 4n）

失效区

  • max / min / gcd → 不可差分
  • 区间赋值 → 线段树（双懒）
  • 前驱后继（值域大）→ 平衡树
  • 可持久化 → 主席树

与其它三条的关系

复杂度阶梯的规律

复杂度越低，代码越长、前提越强。每升一级都是"上一级表达不了"才升。

交叉验证的价值

五个建模语义等价，答案必须一致——cross_all()（P45）会跑三方对拍。

心法：选型 = 在复杂度阶梯上找到"够用的最低档"，别越级也别降级。
04 · CONSISTENCY

一致性检查：最强的正确性验证

本页回答：怎么证明选型对了？
三关卡。

1跨结构对拍

同一语义用 N 种结构实现，答案必须一致。

  • BIT vs 线段树 vs 分块
  • 并查集 vs 暴力 BFS
  • 主席树 vs 分块 vs 暴力

一致 → 选型与实现都对；不一致 → 找出哪个错。

2结构 vs 暴力

随机小数据，结构答案 = 暴力答案。

  • 随机 n ≤ 15、q ≤ 30
  • 每组跑 200~300 次
  • 不一致立刻能定位

暴力是标尺——任何优化上线前必须过这一关。

3边界用例

特殊输入，确认边界处理。

  • n = 0 / 1 / 2
  • 全相等、全 0、极值
  • 单元素区间、块边界
  • 树形：单点 / 链 / 星

数据结构的 bug 八成在边界，不在核心逻辑。

三关卡的顺序

边界 → 暴力 → 跨结构。先确认边界没漏，再确认与暴力一致，最后确认多实现一致。三关全过，选型才算可信。

一致性检查的额外价值

跨结构对拍不仅验正确性，还验选型——如果三种结构答案不一致，说明至少有一个语义理解错了。

习惯：写完结构先写对拍脚本，再写主程序。对拍过了再优化。

05 · IRREPLACEABLE

什么时候必须用哪个

本页回答：四个"不换不行"的场景。
以及换掉会怎样。

并查集

  • 连通性的 α——唯一接近 O(1)
  • 等价类的唯一自然实现
  • Kruskal MST 的标配

换掉会：用 BFS 每次查连通 O(n+m)，慢一个量级。

树状数组

  • 能差分问题的最小代码量
  • 常数是线段树的 1/3
  • 值域 BIT 做动态排名

换掉会：用线段树写 90 行，常数 ×3。

线段树

  • 区间改 + 区间查的唯一自然解
  • 懒标记 / 可持久化 / 合并的入口
  • 树链剖分的唯一载体

换掉会：BIT 表达不了 max / 赋值。

分块

  • 万能兜底，几乎不会写错
  • √n 卡不掉时的救命稻草
  • 莫队 / 根号分治的载体

换掉会：复杂操作写不动线段树时无解。

三种"选错"的后果

  • 用 BIT 做区间 max → 直接 WA（语义错）
  • 静态 RMQ 上线段树 → 常数 ×3、可能 MLE（杀鸡用牛刀）
  • √n 卡不掉时上分块 → TLE（规模错）

决策口诀

先问语义，再问规模，最后问常数。三问定结构。

升华：数据结构选型能力 = "把操作语义翻译成复杂度形态"，而不是背模板。

07 · CORRECTNESS

正确性与复杂度

本页回答：数据结构为什么对？
怎么算复杂度。

复杂度怎么算

  • 并查集：路径压缩 + 按秩 → O(α(n))
  • BIT：lowbit 每次至少减半 → O(log n)
  • 线段树：每次操作走 O(log n) 层
  • 分块：O(B + n/B)，B = √n 时最优

正确性三问

  • 不变量：每个节点存的是它覆盖区间的真实值吗？
  • 懒标记：下推后子区间拿到正确值了吗？
  • 边界：空区间、单元素、越界处理对吗？

常见漏点

  • 线段树懒标记没下推
  • 分块块大小算错
  • BIT 下标从 0 开始 → 死循环
  • 并查集递归 find 爆栈

证明手法

  • 不变量归纳：操作后不变量仍成立
  • 对拍：小数据与暴力一致（最实用）
  • 边界用例：n = 0 / 1 / 2、全相等、单元素区间
  • 随机化：随机数据跑 300 次

验证三层

  • 边界：空区间、单元素、块边界
  • 不变量：答案与暴力一致
  • 跨结构：N 种实现答案一致

优化前后的对拍

朴素版与优化版必须对拍——优化只改实现，不改语义。任何结构上线前都应通过 stress() 与 cross_all()。

心法：数据结构的正确性是设计出来的——不变量写清，边界覆盖，对拍通过。
