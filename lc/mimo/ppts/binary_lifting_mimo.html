从零开始 · 算法入门系列 · 第 04 讲

倍 增

用二进制拆掉 k

跳 k 步，本来要k 次。
把 k 拆成 2^a + 2^b + 2^c …， 只要 log k 次。

LIFT
倍增 = 用「指数级」的跳板拼出任意步
Q1

朴素跳 k 步，慢在哪？

一步一步往上走，一次是 O(k)。
k 和 n 同量级时就是 O(n)，
做 n 次询问就变 O(n²)。

→ 每一步都重新走，浪费

Q2

怎么把 k 次压成 log k 次？

任何整数都能写成 若干个 2 的幂之和。
跳 k 步 = 跳 2^a 步 + 跳 2^b 步 + …

→ 二进制拆分

Q3

倍增能用在哪？

树上第 k 级祖先、LCA、
路径最值、ST 表、序列迭代。
只要能预处理「跳 2^j 步」就能用。

→ 四大场景

一句话
倍增不是一种题型，而是一种加速手段： 把「线性枚举」换成「二进制枚举」，再用预处理把每一步变成 O(1)。
它是「手段」不是「题型」，先认清

问题：树上第 k 级祖先是谁？

给定一棵树和节点 u，
问 u 往上数第 k 个祖先是谁。

朴素做法
for _ in range(k): u = parent[u]
时间 O(k)，最坏 O(n)。
慢在哪？
跳 10 步 = 走 10 次 parent。
但中间每一步的结果都没被记住，下次还得从头走。
时间 O(nq)
空间 O(n)
每步的结果都扔掉了，太可惜

任意整数都是 2 的幂之和

13 = 8 + 4 + 1
   = 2³ + 2² + 2⁰
   = 1101(2)

所以：跳 13 步
= 跳 8 步 → 再跳 4 步 → 再跳 1 步。

效果：13 次操作 → 3 次。
一般来说，k 的二进制位数就是 ⌊log₂ k⌋ + 1， 所以最多 log k 次。
k 越大，省得越多

每个节点，预存 log n 个「跳板」

up[u][j] = 从 u 往上走 2j 步
到达的祖先节点

j = 0 → 走 1 步（就是父亲）
j = 1 → 走 2 步（祖父）
j = 2 → 走 4 步
j = 3 → 走 8 步，…

一共要存几层？
n 个节点最多跳 n-1 步， 所以 LOG = ⌈log₂ n⌉。
n = 10⁵ → LOG ≈ 17；n = 10⁶ → LOG ≈ 20。
空间 O(n log n)
n = 10⁵ 约 170 万格
「一倍一倍往上长」，这就是倍增的名字

为什么要「跳两次一半」？

up[u][j] = up[ up[u][j-1] ][j-1]
一句话记忆： 先跳一半到 mid，再从 mid 跳一半。
中间点就是 up[u][j-1]。
转移式天然「自下而上」填表
up 表 · −1 表示「没有了」
u \ j2⁰ = 12¹ = 22² = 4

验证第 7 行：
up[7][0] = 5（父亲）
up[7][1] = up[ up[7][0] ][0] = up[5][0] = 2
up[7][2] = up[ up[7][1] ][1] = up[2][1] = 1 ✓
第 7 行：5 → 2 → 1，正好 4 步到根
build_lifting.py
  1. import sys
  2. sys.setrecursionlimit(10 ** 6)
  3. input = sys.stdin.readline
  4.  
  5. n = int(input())
  6. g = [[] for _ in range(n + 1)]
  7. for _ in range(n - 1):
  8. a, b = map(int, input().split())
  9. g[a].append(b); g[b].append(a)
  10.  
  11. LOG = (n + 1).bit_length()
  12. up = [[0] * LOG for _ in range(n + 1)]
  13. depth = [0] * (n + 1)
  14.  
  15. from collections import deque
  16. q = deque([1]) # 1 号当根
  17. depth[1] = 0
  18. up[1][0] = 0 # 0 表示「没有祖先」
  19. while q:
  20. u = q.popleft()
  21. for j in range(1, LOG):
  22. up[u][j] = up[up[u][j - 1]][j - 1]
  23. for v in g[u]:
  24. if v == up[u][0]: continue
  25. depth[v] = depth[u] + 1
  26. up[v][0] = u
  27. q.append(v)
四步法 · 模板的骨架
步骤做什么
① 定状态up[u][j] = 往上 2j 步的祖先
② 定边界up[u][0] = parent，根设 0 / −1
③ 定转移up[u][j] = up[up[u][j-1]][j-1]
④ 定顺序j 从小到大（层序填）
为什么 j 要从小到大？
因为 up[u][j] 依赖 up[u][j-1] 和 up[mid][j-1]， 都是「更小的 j」。
这就是「层序填表」，和区间 DP 的「按长度」是同一件事。
用 0 还是 -1 当哨兵？
Python 里 up[0][j] 必须先建好（全 0）， 否则会 IndexError。
建议 0 行全填 0，最省事。
用 bit_length，绝不会把 LOG 取小
LeetCode 1483 · Kth Ancestor of a Tree Node

查询：k = 5, node = 7

跳法：按二进制位走

k = 5 = 101(2)

j=0：k 的第 0 位 = 1 → 跳 1 步
j=1：k 的第 1 位 = 0 → 跳过
j=2：k 的第 2 位 = 1 → 跳 4 步
关键点：每一位单独看，互不干扰。
因为 2 的幂之和不会重复也不会遗漏， 所以顺序（高位→低位 / 低位→高位）都对，结果一样。
时间 O(log k)
预处理 O(n log n)
空间 O(n log n)

kth_ancestor.py
  1. class TreeAncestor:
  2. def __init__(self, n, parent):
  3. self.LOG = (n + 1).bit_length()
  4. up = [[0] * self.LOG for _ in range(n)]
  5. for i in range(n):
  6. up[i][0] = parent[i] if parent[i] != -1 else 0
  7. for j in range(1, self.LOG):
  8. for i in range(n):
  9. up[i][j] = up[up[i][j - 1]][j - 1]
  10. self.up = up
  11.  
  12. def getKthAncestor(self, node, k):
  13. u = node
  14. for j in range(self.LOG):
  15. if (k >> j) & 1:
  16. u = self.up[u][j]
  17. if u == 0:
  18. return -1
  19. return u

树上「两点之间的路径」怎么描述？

树上任意两点之间只有一条路径。
而这条路径一定经过它们的最近公共祖先（LCA）。

有了 LCA，能干一堆事

想求的东西怎么用 LCA
路径长度depth[u] + depth[v] − 2·depth[lca]
路径最值u → lca 与 v → lca 两段合并
路径和前缀和相减
路径异或异或前缀和相减
第 k 级祖先倍增模板直接用
为什么说 LCA 是树上问题的「万能钥匙」？
因为树上两点路径的问题，几乎都能拆成「两段向上的路径」。
而「向上走」正是倍增最擅长的事。
所以这一讲的主线是：
倍增 → 第 k 级祖先 → LCA → 路径问题，一条链走到底。
树上路径 = 两段「向上走」

朴素思路：让它们「会合」

# 1. 把更深的那个抬上来
while depth[u] > depth[v]: u = parent(u)
while depth[v] > depth[u]: v = parent(v)

# 2. 一起往上走，直到相遇
while u != v:
    u = parent(u)
    v = parent(v)
return u

它对，但太慢

最坏情况：树退化成一条链。
u 在链尾，v 在链头 → 要走 O(n) 步。

做 q 次查询 → O(nq)。
n = q = 10⁵ 时是 10¹⁰ 次操作，必然超时。
问题的根源：
「一步一步往上跳」这件事本身太慢。

怎么办？用倍增：
· 第 1 步的「抬升深度」→ 二进制拆分，O(log)
· 第 2 步的「一起走」→ 从高到低试跳，O(log)
朴素做法也有用武之地：
树小（n ≤ 2000）、查询少（q ≤ 2000）时，
朴素写法更快写完，先拿部分分。
卡住的永远是「一步一步跳」

目标：把 u 抬到和 v 同一深度

设 u 更深。
需要往上走 diff = depth[u] − depth[v] 步。

倍增抬升（和第 k 级祖先完全一样）
u = kth_ancestor(u, diff)
抬起之后：
· 如果 u == v，那 v 本来就是 u 的祖先，直接返回。
· 否则，u 和 v 现在在同一层，但还不是同一个点。
对齐 O(log n)
抬升这一步，就是第 k 级祖先

核心想法：从大跳板开始试

从 j = LOG-1 到 0，从高到低：

如果 up[u][j] != up[v][j]
→ 说明跳 2j 步还不会碰到一起，那就放心跳：
  u = up[u][j]; v = up[v][j]

否则，不敢跳，换小一点的跳板。
为什么不直接跳到 LCA？
因为跳过头就丢答案了。
我们只是逼近——跳到 LCA 下面一层就停。
最后一步：
循环结束后 u 和 v 是 LCA 的两个孩子。
所以 LCA = up[u][0]（它们的父亲）。
大跳板先试，跳不过去就换小的
lca.py
  1. def lca(u, v):
  2. if depth[u] < depth[v]: u, v = v, u
  3. diff = depth[u] - depth[v]
  4. j = 0
  5. while diff:
  6. if diff & 1:
  7. u = up[u][j]
  8. diff >>= 1
  9. j += 1
  10.  
  11. if u == v: return u
  12.  
  13. for j in range(LOG - 1, -1, -1):
  14. if up[u][j] != up[v][j]:
  15. u = up[u][j]
  16. v = up[v][j]
  17.  
  18. return up[u][0]
三个细节
细节说明
先抬升深度不同时 必须 先对齐，否则跳板方向不对
j 从高到低「二分逼近」的标准姿势，越先跳大的越省
最后返 up[u][0]循环结束时 u、v 是 LCA 的两个孩子
一个常见错： 把 up[u][j] != up[v][j] 写成 depth[u] != depth[v]。
那样跳过去后又得重新对齐深度，而且会跳过头。
复杂度： 预处理 O(n log n)， 每次查询 O(log n)。
n = q = 10⁵ 时约 1.7×10⁶ 次操作，非常快。

三段：对齐 → 逼近 → 收尾

公式只要一行

dist(u, v) =
  depth[u] + depth[v]
  − 2 × depth[lca(u, v)]

为什么？
· u 到 LCA：depth[u] − depth[lca]
· v 到 LCA：depth[v] − depth[lca]
· 两段相加，depth[lca] 被减了两次。

要记住：深度是节点数还是边数？
本讲用「边数」：depth[root] = 0。
如果题目要「节点数」，答案再 +1。
有了 LCA，距离就一行公式

升级：跳板不只是「到哪」，还有「路上看到什么」

up[u][j] = 往上 2j 步到的点
mx[u][j] = 这段路上边权的最大值
边界：
mx[u][0] = weight(u, parent(u))
——就是 u 到父亲那条边的权。
转移：两半取 max
mx[u][j] = max(mx[u][j-1], mx[mid][j-1])
其中 mid = up[u][j-1]。
套路：只要合并规则是可结合的 （max / min / sum / xor …）， 都能这样带上。
不可结合的（比如「乘积取模」）就要小心。
跳板带信息，就能答「路径最值」

思路：和 LCA 一样，只是「顺便」更新答案

① 抬升 u 到同深度时，
  每跳一次就 ans = max(ans, mx[u][j])

② 一起跳时，
  u 侧和 v 侧的跳板都更新答案

③ 最后，u、v 到 LCA 还差一条边，
  用 mx[u][0]、mx[v][0] 收尾。
共性：「在跳的过程中顺手合并」。
只要合并是可结合的，这一招都管用。
path_max.py
  1. def path_max(u, v):
  2. ans = -10 ** 9
  3. if depth[u] < depth[v]: u, v = v, u
  4. diff = depth[u] - depth[v]
  5. j = 0
  6. while diff:
  7. if diff & 1:
  8. ans = max(ans, mx[u][j])
  9. u = up[u][j]
  10. diff >>= 1
  11. j += 1
  12. if u == v: return ans
  13. for j in range(LOG - 1, -1, -1):
  14. if up[u][j] != up[v][j]:
  15. ans = max(ans, mx[u][j], mx[v][j])
  16. u = up[u][j]; v = up[v][j]
  17. ans = max(ans, mx[u][0], mx[v][0])
  18. return ans
查询 O(log n)

洛谷 P1967 · 货车运输

题意速读

· 一张无向图，每条路有限重。
· 问：从 a 到 b，能通行的最大限重是多少？
· 也就是说，所有路径里，取「最小边权最大」的那条。

三步走
① 最大生成树：Kruskal，边按权从大到小
② 倍增：预处理 up 与 mn[u][j]（最小边权）
③ 查询：LCA 风格，跳的时候 ans = min(ans, mn[…])

为什么必须是「最大生成树」？

因为我们的目标是让「路径上最小的那条边尽量大」。
树上两点路径唯一，所以只要在树上答即可。

核心洞察：
图上问题 → 最大生成树 → 树上问题 → 倍增。
这条转化链本身比倍增本身更值得学。
和上一页的差别：
这里是 min 不是 max；
起点是图不是树；
其余代码一行都不用改，只换合并函数。

P2680 运输计划
图 → 树 → 倍增，这链子很值钱

同样是「跳板」，只是跳的是区间长度

st[i][j] = 从 i 开始、长度 2j
          的区间最值
例：st[2][3] = 区间 [2, 9] 的最值
转移：两半合并
st[i][j] = min(st[i][j-1], st[i + 2^(j-1)][j-1])

和树上的 up[u][j] = up[up[u][j-1]][j-1] 是同一件事：跳两段一半的。
重叠没关系，最值不怕重复算
sparse_table.py
  1. def build(arr, f=min):
  2. n = len(arr)
  3. LOG = n.bit_length()
  4. st = [arr[:]] # j = 0：长度 1
  5. for j in range(1, LOG):
  6. prev = st[-1]
  7. m = n - (1 << j) + 1
  8. if m <= 0: break
  9. st.append([f(prev[i], prev[i + (1 << (j - 1))])
  10. for i in range(m)])
  11. return st
  12.  
  13. def query(st, l, r): # 闭区间 [l, r]
  14. k = (r - l + 1).bit_length() - 1
  15. return min(st[k][l], st[k][r - (1 << k) + 1])
ST 表的三个细节
细节说明
k 怎么算bit_length()-1 = ⌊log₂(len)⌋，比 log2 快
允许重叠最值不怕重复；求 gcd、and、or 也一样
只适合静态数组一改就得重建，O(n log n)
能用 ST 表的运算：
min / max / gcd / and / or / xor
——只要幂等（重复算不亏）或可结合。
不能用的： sum（重叠会多算）、乘积。
这些要用前缀和或线段树。

树换成了「函数」，套路照搬

f[i][j] = 从 i 走 2j 步到的位置
d[i][j] = 走这 2j 步累计的代价

f[i][0] = next[i]
d[i][0] = cost[i]
f[i][j] = f[ f[i][j-1] ][j-1]
d[i][j] = d[i][j-1] + d[ f[i][j-1] ][j-1]
和 up[u][j] 对比：
「父亲」→「下一步」；
「树」→「任意函数 f」。
只要「下一步」是确定的，就能倍增。
把「父亲」换成「下一步」，套路不变

倍增常和「贪心」「二分」连用

组合长什么样
倍增 + 贪心 从大跳板往小试，能跳就跳（凑出最小步数）
倍增 + 二分 问「最少几次能到达」，先倍增预处理，再二分答案
倍增 + 差分 路径上的信息叠加（P2680 运输计划）
倍增 + 哈希 字符串 2^j 长度的哈希（Rabin-Karp 倍增）
判断标准：
如果一个答案可以写成 k = 2^a + 2^b + …， 或者「跳 k 步」这个动作能被拆成幂次， 就能用倍增。

贪心拼法（最小步数）

目标：用最少的跳板次数凑出 k。

做法：从 j = LOG-1 往下试：
如果「跳 2^j 步之后还 ≤ 目标」就跳。

这正是 LCA 里「从高到低试跳」的同一个动作。
「从大到小试」是倍增的标志性动作
✓

适用

① 「跳 k 步 / 第 k 个」
② 静态的结构，反复询问
③ 跳转规则固定（next / parent）
④ 合并规则可结合

典型：第 k 级祖先、LCA、
路径最值、ST 表、序列迭代。

✗

不适用

① 要修改数据
② 答案在最差路径上（要路径条数）
③ 跳转规则会变
④ 合并不可结合（比如求平均）

这些改用线段树、树链剖分、树形 DP。

错误症状对策检验
① LOG 取小了 n = 10⁵ 却写 LOG = 16，最深的链跳不完。 用 n.bit_length()，宁大勿小。 造一条 n = 2¹⁶ 的链。
② 哨兵越界 up[0][j] 报 IndexError。 0 号行先填好，或用 -1 并检查。 输入 n = 1。
③ j 的循环顺序错 填表时 j 从大到小，结果全是 0。 建表 小→大；查询 大→小。 打印 up 表逐行核对。
④ LCA 最后一步 返回 u 而不是 up[u][0]。 循环结束 u、v 是 LCA 的孩子，再上一层。 手推 u = v 的孩子。
⑤ 深度没对齐 u、v 深度不同却直接一起跳，跳到错的点。 先抬升再同时跳。 造 u 深 v 浅的查询。
⑥ 混淆「边数/节点数」 距离答案差 1。 看清题目，统一 depth[root]=0。 单边两节点手算。
!
倍增的 bug 多数出在「边界与顺序」，不是转移式。
最有效的一招：拿 n = 1、n = 2、链、星形各测一遍。

常见优化：
· 查询时 while diff 比 for j in range(LOG) 更快（跳过的位直接略过）
· LOG 只取到 depth 的最大值即可

术语英文一句话
倍增binary lifting用 2 的幂做「跳板」，把 k 次压成 log k 次。
二进制拆分binary decomposition把 k 写成 2 的幂之和，如 13 = 8+4+1。
跳板jump pointer预存「走 2j 步到哪」的表。
哨兵sentinel「不存在」的统一表示，0 或 −1。
LOG⌈log₂ n⌉跳板层数，n = 10⁵ 时约 17。
术语英文一句话
LCALowest Common Ancestor两点最近的公共祖先。
RMQRange Minimum Query静态区间最值查询。
ST 表Sparse Table倍增思想解 RMQ 的经典结构。
欧拉序Euler Tour把树拍成序列，LCA 可化为 RMQ。
可结合associative能拆成两半合并的运算，如 max / min。

四步法 · 每次都问

步骤倍增版本
① 存什么up[u][j] = 从 u 走 2j 步到的点
② 怎么转up[u][j] = up[up[u][j-1]][j-1]
③ 从哪起up[u][0] = parent(u)；根设哨兵
④ 顺序建表 j 小→大；查询 j 大→小

三问 · 决定用不用

1
能不能预处理「跳 2^j 步」？
不能 → 用线段树 / 树形 DP。
2
能不能「从大到小试跳」？
不能 → 可能不适合倍增。
3
只需 log 次就能拼出答案？
是 → 复杂度稳稳 O(log n)。

结语

倍增就是
用二进制拆掉 k。

今天你只需要记住四句话：
① k 一定写得成 2 的幂之和；
② 预处理 up[u][j]，一次跳 2j；
③ 转移是 「先跳一半，再跳一半」；
④ 查询时 从大跳板开始试。

倍增不是题型，是加速手段。
认出「跳 k 步」这种形状，你就比别人快一步。
