从零开始 · 算法入门系列 · 第 02 讲

区间 DP

从「切一刀」开始

状态从「前 i 个」变成「i 到 j 这一段」，
转移就变成「在这一段里切一刀」。

DP
这一刀落在哪，就是区间 DP 的全部
Q1

为什么线性 DP 不够用？

当最优解取决于「这一段从哪开始、到哪结束」时， 只记一个下标就不够了。

→ 状态要变成 dp[i][j]

Q2

转移要枚举什么？

枚举「最后一刀切在哪里」。
这一刀把区间分成左右两半，两半各自最优。

→ 枚举分界点 k

Q3

表要按什么顺序填？

不能按 i、j 两层循环填——会用到还没算的格子。

→ 按区间长度从小到大

洛谷 P1775 石子合并

4 堆石子：4   5   9   4

每次只能合并相邻两堆，代价 = 两堆石子数之和。
合并完就变成新的一堆，再继续。求最小总代价。

总代价 9 + 13 + 22 = 44
换一种顺序 = 54

先问自己一个问题

「第一次合并哪两堆？」

选了 4、5，右边就变成 [9, 9, 4]；
选了 9、4，左边就变成 [4, 5, 13]。

第一次的选择，决定了后面所有的事情。

这类问题叫「决策相互牵连」：
你不能先贪心地合最小的两堆，然后以为结束了。
贪心在这里是错的。必须把「所有可能的合并顺序」都考虑进来—— 这正是 DP 要做的事。
第一次合哪里，牵一发动全身

试着写 dp[i]，会卡在哪？

想写 dp[i] = 前 i 堆合并的最小代价。

那「最后一堆是怎么来的」？
——不知道。可能是 [1..i] 一次合出来的，
也可能是 [1..k] 与 [k+1..i] 合出来的。

问题：你不知道这一段从哪开始。
于是状态里必须写上起点。
起点也是信息，丢不得
①

存什么？

dp[i][j] ＝ 区间 [i, j] 的最优值。

石子：dp[i][j] = 合并 i..j 的最小代价
回文：dp[i][j] = i..j 是否回文
戳气球：dp[i][j] = (i,j) 内的最大金币

两个下标，永远是 起点 与 终点。
②

怎么转？

枚举分界点 k：最后一刀 / 最后一次合并。

dp[i][j] = ⊕ dp[i][k] + dp[k+1][j]
dp[i][j] = ⊕ dp[i][k] + dp[k][j]
dp[i][j] = dp[i+1][j-1] + 两端

⊕ 表示 min / max / +，看题意。
③

从哪开始？

长度为 1 的区间。

dp[i][i] = 0（合并代价）
dp[i][i] = True（回文）
dp[i][i] = 1（长度）

答案一般是 dp[1][n] 或 dp[0][n-1]。
② 是最难的一步，多花时间

最后一刀，切在 k 和 k+1 之间

大区间 [i, j] 被切成两半：
[i, k] 与 [k+1, j]。

两半各自独立做最优，再把结果合起来。

为什么可以各做各的？
因为切完之后，左半的操作不会影响右半—— 这就是「最优子结构」在区间上的版本。
枚举量：i、j 各 O(n)，k 又 O(n) → 总共 O(n³)。这就是区间 DP 的标准开销。
一刀 → 两半 → 各自最优 → 合起来

四步法 · 第 1 步

dp[i][j] 到底是什么？

dp[i][j] = 字符串 s 从第 i 位到第 j 位

换成求长度就是 最值型；换成求方案数就是 计数型。

这一段什么时候是回文？

两个条件同时成立：
① 首尾字符 相等：s[i] == s[j]
② 掐掉首尾之后那一段也是回文：dp[i+1][j-1]

if s[i] != s[j]:  dp[i][j] = False
else:  dp[i][j] = dp[i+1][j-1]
这就是「两端型」转移：
新的一层答案，建立在「掐掉两头」的更小区间上。
注意：这里没有枚举 k，因为「最后一步」只有一种——两端各去掉一个字符。
掐掉两头，问题就短了一圈

看依赖关系，别看下标

dp[i][j] 依赖 dp[i+1][j-1]。
后者的长度是 j-1 - (i+1) + 1 = j-i-1，
比前者短 2。

所以填表顺序应该是：
先把所有长度 1 的填好 → 再长度 2 → 长度 3 → …
这样每填一格，它依赖的格子一定已经算好。
反例：如果你写成 for i: for j:（按行扫），
算 dp[0][4] 时，dp[1][3] 还没算 → 用的是初值，答案就错了。
j=0j=1j=2 j=3j=4
i=0 L1L2 L3L4L5
i=1 L1 L2L3L4
i=2 L1 L2L3
i=3 L1L2
i=4 L1
同一条斜线 = 同一个长度
L 就是区间长度
标出的箭头关系：dp[0][2] ← dp[1][1]（长 3 依赖长 1）
外层循环 = 长度，这是本讲最重要的一句
第 3 步 · 初始条件

长度 1 与长度 2 要单写

长度 1：dp[i][i] = True  （单字符天然回文）
长度 2：dp[i][i+1] = (s[i] == s[i+1])
            不需要看中间
为什么长度 2 要单写？
转移式里的 dp[i+1][j-1] 在 j = i+1 时会变成 dp[i+1][i] —— 下标反了，属于非法格子。
所以要用边界把它挡住。
另一招：在转移里写 j - i <= 1 时直接 True， 效果一样。

longest_palindrome.py
  1. def longest_palindrome(s):
  2. n = len(s)
  3. if n < 2:
  4. return s
  5. dp = [[False] * n for _ in range(n)]
  6. start, mx = 0, 1
  7. for i in range(n):
  8. dp[i][i] = True
  9. for L in range(2, n + 1):
  10. for i in range(n - L + 1):
  11. j = i + L - 1
  12. if s[i] != s[j]:
  13. dp[i][j] = False
  14. elif L <= 2:
  15. dp[i][j] = True
  16. else:
  17. dp[i][j] = dp[i + 1][j - 1]
  18. if dp[i][j] and L > mx:
  19. mx, start = L, i
  20. return s[start:start + mx]
三处细节
位置为什么这么写
range(n-L+1)保证 j = i+L-1 < n 不越界
L <= 2挡掉 dp[i+1][j-1] 的非法下标
顺手记录边填边更新，省一次遍历
还有一种写法：枚举回文中心向两边扩展，O(n²)、 空间 O(1)。工程上更快，但换一道题就不好用了—— 区间 DP 的方法是通用的。

步骤做法本题
① 状态用一句话说明 dp[i][j] dp[i][j] = 把第 i 堆到第 j 堆合并成一堆的最小代价
② 转移枚举「最后一步在哪」 最后一次合并，是把 [i,k] 与 [k+1,j] 合起来
dp[i][j] = mink ( dp[i][k] + dp[k+1][j] ) + sum(i..j)
③ 初始最短的区间 dp[i][i] = 0（一堆石子不用合并，代价 0）
④ 答案答案在哪 dp[1][n]（把 1..n 合成一堆）
关键一步想清楚：「最后一次合并」是什么？
—— 是哪两段合起来的。把它枚举出来，就得到分界点 k。
另一个问题：为什么答案要加 sum(i..j)？
因为最后一次把两堆合成一堆，代价就是这一段的总重量。
「最后一步」永远是突破口

把式子拆成三段看

dp[i][k]         左半合并成一堆的代价
+ dp[k+1][j]   右半合并成一堆的代价
+ sum(i..j)    最后这一步的代价
为什么最后一步是 sum(i..j)？
因为合并代价定义为「两堆石子数之和」。
两堆加起来正好是 [i..j] 的总重量。
所以整个转移是「先各合并好，最后再合一次」。
如果题目把代价改成「较大那一堆的重量」或「两堆乘积」， 只需要换掉这一项，前面两段完全不变。

merge_stones.py
  1. def merge_stones(a):
  2. n = len(a)
  3. s = [0] * (n + 1)
  4. for i in range(1, n + 1):
  5. s[i] = s[i - 1] + a[i - 1]
  6. dp = [[0] * (n + 1) for _ in range(n + 1)]
  7. for L in range(2, n + 1):
  8. for i in range(1, n - L + 2):
  9. j = i + L - 1
  10. best = float('inf')
  11. w = s[j] - s[i - 1]
  12. for k in range(i, j):
  13. best = min(best, dp[i][k] + dp[k + 1][j] + w)
  14. dp[i][j] = best
  15. return dp[1][n]
三个细节
位置说明
前缀和sum(i,j) = s[j] - s[i-1]，省掉一层
k 的范围i ≤ k < j，切点在两段之间
inf求最小要从 ∞ 起步
复杂度：O(n³) 时间、O(n²) 空间。
n ≤ 300 还行，n = 3000 就要上「四边形不等式」优化。

洛谷 P1880 · 石子合并（环形）

石子围成一圈，首尾也算相邻。
那第一次合并就有 n 种可能，而不是 n−1 种。

解法 · 断环成链
把数组复制一倍接在后面：b = a + a
然后在长度 2n 的链上，枚举起点取最优。

原因：环上的任意一段连续区间，在链上都对应一条长度 ≤ n 的连续段。

LeetCode 312 戳气球

nums = [3, 1, 5, 8]

戳破第 i 个气球，得到金币：
nums[left] × nums[i] × nums[right]
（边界两侧视为 1）。求最大金币。

难点在哪？

戳破一个气球后，它两边的气球变成新的邻居。
也就是说：你先戳谁，会改变后面每一次的收益。

如果按「戳破顺序」来定义状态：
dp[k] = 戳了 k 个气球的最大金币 —— 不够， 因为不知道剩下的是哪些。

状态里还得记下「还剩哪些」，那就变成 2ⁿ 了。
出路：换个角度——不问「先戳谁」，
而问「最后戳谁」。
最后戳的那个气球，它的两个邻居在整个过程中一直存在，是稳定边界。

答案 167
顺推卡住，就试试倒推

如果我知道最后戳的是 k，会发生什么？

那 k 的两个邻居（左边是 i，右边是 j）从头到尾都没动。
于是 k 被戳时拿到金币：a[i] × a[k] × a[j]。

状态定义：
dp[i][j] = 在开区间 (i, j) 内（不含 i、j）， 把所有气球都戳掉的最大金币。

注意是开区间——i 和 j 是稳定边界，不戳。
这一步叫「换个方向看决策」：
从「第一步做什么」改成「最后一步做什么」。
很多区间 DP 都靠这一招化繁为简。
「最后一步」把边界变成了常量
burst_balloons.py
  1. def maxCoins(nums):
  2. a = [1] + nums + [1] # 两侧补虚拟边界
  3. n = len(a)
  4. dp = [[0] * n for _ in range(n)]
  5. for L in range(2, n):
  6. for i in range(n - L):
  7. j = i + L
  8. best = 0
  9. for k in range(i + 1, j):
  10. best = max(best,
  11. dp[i][k] + dp[k][j] + a[i] * a[k] * a[j])
  12. dp[i][j] = best
  13. return dp[0][n - 1]

位置说明
a = [1]+nums+[1]边界是 1，直接写进数组最省事
range(i+1,j)k 取不到 i、j —— 开区间
dp[0][n-1]整段区间，边界不动

石子：dp[i][k] + dp[k+1][j]（闭区间切开）
气球：dp[i][k] + dp[k][j]（开区间，k 是共用的边界）

差一个 +1，含义完全不同。

结语

区间 DP 就是
四步法 + 两个下标。

今天你只需要记住三句话：
① 状态是 dp[i][j]；
② 转移靠 切一刀（或问「最后一步是什么」）；
③ 填表按 长度从小到大。

接下来的树形 DP、状态压缩 DP、数位 DP，
依然是这四步，只是状态的形状变了。
