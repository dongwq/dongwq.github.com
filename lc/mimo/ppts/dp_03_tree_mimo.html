树形 DP

从「父子」开始

状态从「前 i 个」变成「以 u 为根的子树」，
转移从「切一刀」变成「把子节点的答案合起来」。

TREE
从叶子往根，一次走完
Q1

状态要存成什么样？

线性 DP 是「前 i 个」，区间 DP 是「[i,j]」。
树上没有「位置」，只有「以某个节点为根的子树」。

→ dp[u][k]，u 是节点，k 是 u 自己的状态

Q2

转移要枚举什么？

枚举每个子节点在「u 的状态约束下」的选择，
然后把结果累加到 u 身上。

→ 合并所有子节点

Q3

表要按什么顺序填？

父节点要等所有子节点算完。
所以顺序是从叶子到根——也就是后序遍历。

→ 一次 DFS 就够了

四个案例
① 最大深度 / 直径（入门）  ② 打家劫舍 III（经典二选）  ③ 最大路径和（两线分离）  ④ 树中距离之和（换根）
和前两讲一样：三个问题，三步走

链，是树的特例

线性 DP：每个点只有一个前驱。
区间 DP：只是把「一段链」当成主角。

树形 DP：一个点可能有多个孩子。

所以不用从零学起。
只要把「向左/向右取一个」换成「向每个孩子各取一个，再合起来」， 其它套路（定义状态、写转移、定边界、定顺序）一模一样。

① 存什么 ② 怎么转 ③ 从哪开始 ④ 答案在哪。
把「取一个」换成「取一群」就行

谁能来，谁不能来？

一人来，他的直接上司就不能来。
下属之间的规则不重要，只看父子。

关键观察

「某人来不来」这件事，只影响他的直接父亲。
而他自己的最优选择，要看他的所有下属怎么选。

一句话：每个节点的答案， 都是由下往上攒出来的。
这就是树形 DP 的全部味道。

LC 337
「父子之间有约束」是树形题的信号

试着只写 dp[u]，会卡在哪？

想写 dp[u] = 以 u 为根的子树的最大开心值。

现在要把结果交给 u 的父亲。
父亲需要知道：「u 自己来没来？」
——因为 u 来了，父亲就不能来。

问题：光有 dp[u]，父亲不知道该怎么接。
所以要把「u 自己的状态」也写进下标。
要往上交的信息，必须写进状态
①

存什么？

dp[u][k] ＝ 以 u 为根的子树，在 u 处于状态 k 时的最优值。

k 是 u 自己的状态：
来 / 不来、选 / 不选、颜色、……
如果题目不关心，k 可以只有一个值。

永远是「以 u 为根的子树」，不是「u 本身」。
②

怎么转？

把每个子节点的结果合并到 u。

dp[u][k] = val(u,k) + Σ_v g( dp[v][·] )

v 跑遍 u 的所有孩子；
g 取 max / min / 求和。

子节点之间互相独立，所以可以直接相加。
③

从哪开始？

叶子节点。

没有孩子时，Σ 是空的：
dp[u][k] = val(u,k)

这就是初始条件，不用额外写。

第四问：答案在 dp[root] 吗？不一定！（后面会讲）
② 和 ④ 是最容易出错的两处

一次后序遍历，把整棵树算完

访问顺序：孩子 → 自己 → 父亲。
每到一个节点，它的孩子都已经算好，直接合并就行。

为什么必须是「从叶子到根」？
因为 dp[u][k] 要用到 dp[v][·]， 而 v 是 u 的子节点——必须先算孩子。
这正是区间 DP 里「按长度填表」在树上的对应物。
复杂度：每个节点访问一次， O(n × 状态数 × 每个孩子的枚举量)。
大多数题就是 O(n) 或 O(n·k)。
顺序就是「孩子 → 自己 → 父亲」

四步法 · 第 1、2 步

把定义和转移写清楚

dp[u] = 以 u 为根的子树的最大深度

dp[u] = 1 + max( dp[u.left], dp[u.right] )

为什么是 1 + ？
因为 u 自己也算一层。

为什么要 max？
「最远」的意思是取最深的那一支。

第 3、4 步 · 边界与答案
情况值
空节点dp[None] = 0（深度 0）
叶子节点dp[u] = 1（自动成立）
答案位置dp[root]
叶子的初值其实不用单独写。
把「空节点返回 0」写好，叶子的 1 + max(0, 0) = 1 自动就对了。
—— 这是递归写法比「递推填表」省事的地方。
小提醒：「子树的最大深度」≠「最远叶子的编号」。
状态里存的是数值，不是方案。要方案就再记录一个父亲指针。
空节点返回 0，能省掉一半边界讨论

  2. if root is None:
  3. return 0
  4. return 1 + max(maxDepth(root.left),
  5. maxDepth(root.right))

dfs(u) = 1 + f(dfs(子节点))

LeetCode 543 · 二叉树的直径

最长路径可能「拐个弯」

为什么 dp[root] 不是答案？

dp[u] 如果定义成「以 u 为根的直径」， 那它只关心穿过 u 的路径。

但最长路径可能完全落在某个子树里，根本不经过 root。

解法：两条线分开
① 向上传的贡献：u 往下最长的链（单边）
② 打擂台的答案：以 u 为拐点的最长路径

① 交给父亲；② 只用来更新全局答案。
这是树形 DP 最重要的一个意识：
「我要传上去的信息」和「我要记录的答案」经常不是一回事。
传上去的 ≠ 最后要的答案
diameter.py
  1. def diameterOfBinaryTree(root):
  2. ans = 0
  3. def dfs(u):
  4. nonlocal ans
  5. if u is None:
  6. return 0
  7. L = dfs(u.left) # 左边最长链
  8. R = dfs(u.right) # 右边最长链
  9. ans = max(ans, L + R)
  10. return 1 + max(L, R)
  11. dfs(root)
  12. return ans
三处细节
位置为什么这么写
nonlocalPython 内层函数要改外层变量，必须声明
L + R拐点路径 = 左链 + 右链，边数就是相加
1 + max向上传只能选一条链（路径不能分叉）
一个常犯的错：把 return 写成 L + R。
那样传上去就变成「拐弯的路径」， 父亲一接就出现分叉，不再是路径了。
LC 543
时间 O(n)
return 只能接一条链，别分叉

house_robber_III.py
  1. def rob(root):
  2. def dfs(u):
  3. if u is None:
  4. return (0, 0)
  5. l0, l1 = dfs(u.left)
  6. r0, r1 = dfs(u.right)
  7. no = max(l0, l1) + max(r0, r1) # u 不偷，孩子随便

LeetCode 124 · Hard

root = [-10,9,20,null,null,15,7]

难在哪？

① 答案不在根（同 LC 543，要打擂台）
② 节点值可为负—— 有时「不接」更好
③ 路径可以只是一个点

第 ② 点是新东西。
以前 return 1 + max(L, R) 永远往上接。
现在若 L、R 都是负数， 就应该不接——返回 0 不太对， 因为 u 自己还在。

所以写成 u.val + max(L, R)， 其中 L = max(0, dfs(left))。
这就是「贡献可以为 0，答案可以为负」的典型分离。
有负数，就要学会「不接」

两条公式，两个用途

① 向上传的贡献（交给父亲）
  gain(u) = u.val + max(0, max(gain(l), gain(r)))

② 打擂台的答案（更新全局）
  ans = max(ans, u.val + max(0,gain(l)) + max(0,gain(r)))
为什么 ① 只能接一条？
路径是一条线，不能分叉。
② 里的「左 + 右」是「u 当拐点」的路径，但这条路不能继续往上。
为什么要 max(0, ...)？
贡献为负时不如不接。
但 ans 本身可以是负数—— 全树都是负数时，答案就是最大的那个负数。
记住：传的是一条，记的是两条
max_path_sum.py
  1. def maxPathSum(root):
  2. ans = float('-inf')
  3. def dfs(u):
  4. nonlocal ans
  5. if u is None:
  6. return 0
  7. L = max(0, dfs(u.left))
  8. R = max(0, dfs(u.right))
  9. ans = max(ans, u.val + L + R)
  10. return u.val + max(L, R)
  11. dfs(root)
  12. return ans

易错正确写法
ans 初值必须是 -inf，不能是 0
return 加 max(0)不要—— u 一定在路径里
L、R 加 max(0)要—— 子链可以不接

L = R = 0， ans = -10， 返回 -10。
答案是 -10 而不是 0 —— 对的。

拿到题先问两个问题：
① u 自己的状态会不会约束孩子？（会 → 形状 ②）
② 答案是不是一定要过 u？（不是 → 形状 ③）
先判断形状，再动笔

如果题目问「以每个点为根，答案是多少」？

暴力：每个点当一次根，跑一遍 DFS。
复杂度 O(n²)。n = 10⁵ 就会超时。

换个角度：父子关系是「可逆」的

第一次 DFS 时，u 是 v 的父亲。
换根之后，v 变成根，u 反而是 v 的孩子。
所以答案之间可以「互相推」。

核心公式
ans[v] = ans[u] − sz[v] + (n − sz[v])

· − sz[v]：v 子树里的点，各近了 1
· +(n − sz[v])：外面的点，各远了 1
这就是换根 DP：两次 DFS，O(n) 搞定。
第一次「从下往上」算子树；
第二次「从上往下」把答案推给每个孩子。
父子可以互换，答案就能递推

LC 834
暴力 O(n²)
先手算一个答案，再写代码

第一次：从下往上，算「子树」

sz[u]   = u 的子树节点数
down[u] = u 到自己子树里所有点的距离和

sz[u] = 1 + Σ sz[v]
down[u] = Σ ( down[v] + sz[v] )
为什么 + sz[v]？
v 子树里的每个点，从 u 走过去都要多走 1 步。
第一次算完，down[0] 就是节点 0 的答案。

第二次：从上往下，把答案「推」给孩子

ans[0] = down[0]

ans[v] = ans[u] − sz[v] + (n − sz[v])
两个项的含义：
· − sz[v]：v 子树里的 sz[v] 个点， 现在各近了 1 → 总距离减 sz[v]
· + (n − sz[v])：其余点各远了 1 → 总距离加 n − sz[v]
直观记忆：
「进去的人少了，出来的人多了」
ans[v] = ans[u] + n − 2·sz[v]
先算子树，再把答案推出去
sum_distances.py
  1. def sumOfDistancesInParent(n, edges):
  2. g = [[] for _ in range(n)]
  3. for a, b in edges:
  4. g[a].append(b); g[b].append(a)
  5. sz = [1] * n # 子树大小，自己算 1
  6. down = [0] * n # 到自己子树的距离和
  7. ans = [0] * n
  8. def dfs(u, p):
  9. for v in g[u]:
  10. if v == p: continue
  11. dfs(v, u)
  12. sz[u] += sz[v]
  13. down[u] += down[v] + sz[v]
  14. dfs(0, -1)
  15. def reroot(u, p):
  16. for v in g[u]:
  17. if v == p: continue
  18. ans[v] = ans[u] + n - 2 * sz[v]
  19. reroot(v, u)
  20. ans[0] = down[0]
  21. reroot(0, -1)
  22. return ans
三个细节
位置说明
p（父亲）无向图 DFS 必须记住父亲，防止走回去
sz 初值 1节点自己也算一个
-1 当哨兵根没有父亲，用 -1 表示
为什么不用「每点当根」？
两次 DFS 是 O(n)，
暴力是 O(n²)。
n = 3×10⁴ 时，差距是 10⁴ 倍。

③ 空节点没处理 空树 / 单节点报错。 递归第一行写 if u is None: return ...。 输入 [] 和 [1] 试试。
④ 负权忘了「不接」 答案比预期小（或大）。 贡献加 max(0,·)，答案保持原值。 全负数数组，答案应是最大那个。
⑤ 递归爆栈 树退化成链时 RecursionError。 sys.setrecursionlimit(10**6) 或改迭代。 造一条 n = 10⁵ 的链测一测。

结语

树形 DP 就是
后序遍历的四步法。

今天你只需要记住四句话：
① 状态是 dp[u] 或 dp[u][k]；
② 转移是 把子节点的结果合并到 u；
③ 顺序是 从叶子到根；
④ 答案不一定在根，别忘了打擂台。

把「前两讲」和这一讲连起来看：
线性 → 区间 → 树形，变的只是状态的形状， 四步法一直没变。
