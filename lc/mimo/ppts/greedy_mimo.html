Q1

什么时候能贪？

贪心需要两个性质：
贪心选择性质 + 最优子结构。
缺一个，就会挂在某个数据上。

→ 判别信号 + 反例

Q2

怎么证明贪心对？

标准工具是交换论证：
取最优解 → 把它改成贪心解 →
证明不变差。

→ 四步证明法

Q3

有哪些固定套路？

区间三模板、排序比较器、
哈夫曼、双指针、反悔贪心。
大部分贪心题都能套进去。

→ 六类模板

一句话
贪心不是「大胆猜」，而是「先找策略，再严格证明」。 竞赛里你只需要写一遍代码，但心里得过一遍证明。
先想「凭什么对」，再动手

贪心：每一步只保留一个「当前最优」

while 没到终点:
    在当前可选的方案里
    选一个最好的
    不回头，不撤销
三个特征：
① 无后效性：做了就做了，不反悔
② 只留一条路：不像 DP 保留多个状态
③ 速度快：常常是 O(n log n) 或 O(n)
DP 不用证明，贪心一定要
①

贪心选择性质

存在一个全局最优解，它包含我这一步的贪心选择。

也就是说：不选它也不会更优。
我可以放心选。
怎么检验？
试着把这一步换成别的，看看有没有更优的解。
如果有 → 不能贪。
②

最优子结构

选完一步后，剩下的子问题仍然是同类问题，
而且子问题的最优解 + 我这一步 = 原问题最优解。

这条通常自动满足。
一个对比：
「无权最短路」（BFS）能贪；
「带权最短路」（Dijkstra）也能贪（用堆），
但「最长路」不能贪 —— 没有最优子结构。
一句话： 「选了这一步，剩下的不会变难」 —— 这就是两个条件的合体。 不能满足时，改用 DP、搜索 + 剪枝 或 网络流。
缺一条，贪心就崩

数据：coins = [1, 3, 4]，amount = 6

贪心做法：每次选面额最大的
6 → 4 + 2 → 4 + 1 + 1
用了 3 枚。
真实最优：
3 + 3 = 6，只用 2 枚。
问题在哪？
贪心选择「先用 4」不在任何最优解里。
→ 不满足贪心选择性质。
别把「大概对」当「一定对」
信号长什么样典型题目
① 能排序 答案跟「某种顺序」有关，排完序一遍扫就完事。 活动选择、装箱、排队取水
② 可交换 任意两个元素相邻交换，能判断「谁在前更好」。 国王游戏、拼数、任务调度
③ 无后效 做了选择以后，后续选择不受之前细节影响，只受「总量」影响。 跳跃游戏、区间选点
④ 能拼出 答案可以由几个独立的局部选择拼起来。 哈夫曼、区间分组
✓

大概率能贪

· 数据范围大（n = 10⁵ 以上），不能 DP
· 题目求「最多 / 最少」
· 答案形如「次数、条数、覆盖数」
· 输入能自然排序

✗

大概率不能贪

· 背包类（容量约束）
· 需要组合才能满足的条件
· 有依赖顺序（拓扑序）
· 要求输出方案字典序最小

范围大到不能 DP，先想贪心

四步交换论证

1
取一个最优解 OPT（任意的都行）
2
找第一个不同：OPT 与贪心解 G 第一处不一致的地方
3
做交换：把 OPT 那一处换成贪心选择，证明不会更差
4
重复，直到 OPT == G，于是 G 也是最优解
核心只有一句：
「把最优解里的某个选择，换成贪心的选择，不会更差。」

Interval Scheduling · 经典入门

题意速读

· 有 n 个活动，第 i 个占 [sᵢ, fᵢ)
· 一个人同一时刻只能做 1 个活动
· 问：最多能参加几个？

样例
(1,4) (3,5) (0,6) (5,7) (3,9) (5,9) (6,10) (8,11) (8,12) (2,14) (12,16)
答案：4 个：(1,4)(5,7)(8,11)(12,16)
先问自己： 能不能用 DP？
能，但状态难定义、复杂度 O(n²)。
数据一大就挂。
先别想公式，想想选谁

思路一：枚举所有子集

做法：
枚举所有 2ⁿ 个子集，
对每个检查是否合法，取最大。
n2ⁿ
201,048,576
301,073,741,824
40≈ 10¹²
10⁵完全不可能
指数级，n ≥ 30 就不行。

思路二：DP

状态： dp[i] = 只考虑前 i 个活动，最多选几个
转移：dp[i] = max(dp[i-1], dp[p(i)] + 1)
其中 p(i) = 最后一个与 i 不冲突的活动
时间 O(n log n)（要二分 p(i)）
空间 O(n)
DP 能做，但复杂。
定义状态就要想半天，转移还要二分。

问题：有没有更直接的办法？
→ 有！贪心。
贪心：排序 + 一遍扫描，
时间 O(n log n)，代码 5 行。
DP 也能做，但贪心更短

三个直觉，两个错

策略对错为什么
选开始最早的 ✗ 开始早但可能很长，把后面全占了。
选时长最短的 ✗ 短但位置卡在正中，两边都被卡死。
选结束最早的 ✓ 结束早 → 留下的时间最多，后面选择最宽。
关键直觉：
贪心要选「不会给后面挖坑」的那个。
「结束最早」正是这个意思：越早结束，后面越宽。
结束最早 = 给后面留最多空间

四步走

1
设 G = (g₁, g₂, …, g_k) 是贪心解（按结束时间），
OPT = (a₁, a₂, …, a_m) 是某个最优解。
2
由贪心定义，g₁ 是所有活动里结束最早的，
所以 f(g₁) ≤ f(a₁)。
3
做交换：把 a₁ 换成 g₁。
因为 g₁ 结束更早，后面所有 a₂、a₃…都不冲突，
新解的数量和 OPT 一样。
4
重复：对剩下的部分继续做。
最后 OPT 被完全改成 G。
所以 |G| = |OPT|，G 也是最优解。 ∎

为什么选点按右端点，覆盖按左端点？

选点：想让一个点覆盖尽量多区间， 就把它放在「右端点」——那是能盖住「左端点最晚」的区间的最后一个机会。

覆盖：想让下一段接得上， 就按左端点排，扫到「接不上下一段」时才切。
记忆口诀：
「选点看右，覆盖看左，
分组堆顶是最早的结束。」

题意速读

· n 个区间 [lᵢ, rᵢ]
· 每个区间至少要有 1 个点
· 问：最少放几个点？

样例
[1,4] [2,3] [3,6] [5,7] [6,8]
答案：2（点 3、6）

策略

右端点升序，点放在右端点。
扫到一个区间时，如果点还没覆盖它， 就在它右端点放一个新点。
为什么对？
右端点是这个区间能放点的最右位置， 也是最能顺带覆盖后面区间的位置。
交换论证：把任意解里最左的点往右移，只会覆盖更多区间。
点放右端点 = 一石多鸟

题意速读

· 给定目标线段 [L, R]
· n 条线段 [lᵢ, rᵢ]
· 用最少的线段完整覆盖 [L, R]

策略
左端点升序排序，维护 cur（已覆盖到）：
· 把所有 lᵢ ≤ cur 的线段拿来
· 选 rᵢ 最大的那条，更新 cur = max_r
· 重复，直到 cur ≥ R
为什么对？
一个 cur 处，所有能用的线段起点都 ≤ cur， 所以它们的「衔接能力」一样，终点越远越好。
交换论证：用「终点近的」换「终点远的」只会更差。
选延伸最远的，一步顶多步

题意速读

· n 个会议 [lᵢ, rᵢ]
· 一个会议室同一时刻只能开 1 个会议
· 问：最少要几个会议室？

样例
[0,30] [5,10] [15,20]
答案：2（[0,30] 占一个；[5,10][15,20] 共用一个）

策略

左端点升序，小顶堆存各会议室的结束时间：
· heap[0] ≤ lᵢ → 复用最闲的会议室（pop + push）
· 否则 → 新开一个（只 push）
答案 = 堆的最大 size
为什么对？
堆顶是最早结束的会议室； 能复用就复用，不会让后面更挤。
堆顶永远是「最闲」的那间

题意速读

· n 个非负整数
· 拼成一个最大的数（前导 0 要去掉）
· 返回字符串

样例
[10, 2] → "210"（不是 "102"）
[3, 30, 34, 5, 9] → "9534330"

策略：相邻交换法找排序键

看两个数 a 和 b： 哪个放前面更好？
比较 a+b 和 b+a （字符串拼接后比较）。
largest_number.py
  1. from functools import cmp_to_key
  2.  
  3. class Solution:
  4. def largestNumber(self, nums):
  5. a = [str(x) for x in nums]
  6. def cmp(x, y):
  7. if x + y > y + x: return -1
  8. if x + y < y + x: return 1
  9. return 0
  10. a.sort(key=cmp_to_key(cmp))
  11. ans = ''.join(a)
  12. return '0' if ans[0] == '0' else ans
为什么这么比？
任何一组数字的排列，相邻两个数的顺序 决定了整体的大小。
只要每一对相邻都满足 a+b ≥ b+a， 整体就是最大的。

rescue_boats.py
  1. class Solution:
  2. def numRescueBoats(self, people, limit):
  3. people.sort()
  4. l, r = 0, len(people) - 1
  5. ans = 0
  6. while l <= r:
  7. if people[l] + people[r] <= limit:
  8. l += 1
  9. r -= 1
  10. ans += 1
  11. return ans
为什么对？
重的人没法被别人替代，只能上船；
那和谁同船都不会更差？挑最轻的。
交换论证：换一个更重的同船，只会占掉另一条船的位置。
时间 O(n log n)

大部分贪心题的本质是：

② 极端数据法：造 a 极大、b 极小试试

题意速读

· 国王 + n 个大臣站成一队，国王固定排最前
· 第 i 个大臣有 aᵢ（左手）和 bᵢ（右手）
· 每个大臣得到 （前面所有人 a 之积）÷ 自己的 b
· 求所有大臣中的最大值最小

策略：按 aᵢ × bᵢ 升序
答案 = 每个大臣的值取最大。
需要高精度（乘积会爆 long long）。
相邻交换法推导
看大臣 i 和 j（相邻），交换只影响这两个。
设前面乘积为 P：
 顺序 (i, j)：max(P/aᵢ, P·aᵢ/bⱼ)
 顺序 (j, i)：max(P/aⱼ, P·aⱼ/bᵢ)
要让「较大者」最小，推出 aᵢ·bᵢ ≤ aⱼ·bⱼ。
king_game.py
  1. from functools import cmp_to_key
  2.  
  3. n = int(input())
  4. king_a = int(input())
  5. p = [tuple(map(int, input().split())) for _ in range(n)]
  6. def cmp(x, y):
  7. return x[0] * x[1] - y[0] * y[1]
  8.  
  9. p.sort(key=cmp_to_key(cmp))
  10. prod = king_a
  11. ans = 0
  12. for a, b in p:
  13. ans = max(ans, prod // b)
  14. prod *= a
  15. print(ans) # 题目需要高精度，此处省略
关键套路：
「求最大值最小」→ 用相邻交换推出排序键。
这是「排序比较器」类贪心的通用推导法。

题意速读

· n 个人排队，第 i 人取水要 tᵢ 分钟
· 每个人的等待时间 = 前面所有人的时间和
· 求总等待时间最小（输出顺序和总时间）

策略：按 t 升序
短的先来，后面等得少。
相邻交换
相邻两人 i、j，只看他们的贡献：
 顺序 (i,j)：tᵢ + (tᵢ+tⱼ) = 2tᵢ + tⱼ
 顺序 (j,i)：tⱼ + (tᵢ+tⱼ) = tᵢ + 2tⱼ
要 (i,j) 更好 → tᵢ ≤ tⱼ。
公式： 总时间 = Σ (n-i) × tᵢ（已排序）
短的先来，等的就少

题意速读

· n 堆果子，重量 a[i]
· 每次合并两堆，代价 = 两堆重量和
· 合并到只剩 1 堆，最小总代价

样例
[5, 2, 7, 4]
(2+4)=6 → (5+6)=11 → (7+11)=18
总 = 35

策略：小顶堆，每次取最小两堆

为什么对？
一堆果子被合并的次数越多，代价越大。
让轻的多合并几次，重的少合并，总代价最小。
—— 这就是哈夫曼编码的思想。
轻的多跑几次，重的少跑

解法思路时间空间优缺点
BFS 分层 每次跳算一层，扫到最远 O(n) O(1) 好想，但要懂「层」的概念
DP dp[i] = min(dp[j]+1)，j 能跳到 i O(n²) O(n) 通用，但数据一大就超时
贪心 维护当前层最远 cur 和下一层最远 far O(n) O(1) 最优，但要证明「不变差」
jump_ii.py · 贪心解
  1. class Solution:
  2. def jump(self, nums):
  3. n = len(nums)
  4. far = cur = ans = 0
  5. for i in range(n - 1):
  6. far = max(far, i + nums[i])
  7. if i == cur:
  8. cur = far
  9. ans += 1
  10. return ans

② 状态维护已种的树的位置集合（有序）

普通贪心「做了不能反悔」，反悔贪心「可以反悔」

核心思想
贪心时先全都要（或全都不要），
然后发现「某个选择不好」，就把它撤回。

用堆维护「可撤销的选择」，
每次弹出最差的那个。
什么时候用？
· 有总量约束（选 k 个、t 天）
· 贪心局部对，但全局可能超预算
· 能定义「这次的选择可以换掉上次的某个」
标准套路
① 按某个键排序
② 逐个尝试加入，用堆记录「已选的代价」
③ 总代价超了 → 弹出堆顶（最大的那个）
④ 最后堆里就是最优选
先全选，再退掉最差的

题意速读

· n 门课，第 i 门要 tᵢ 天， 截止 dᵢ 前完成
· 每天只能上 1 门（连续）
· 问：最多能上几门？

样例
[[100,200],[200,1300],[1000,1250],[2000,3200]]
答案：3
策略
① 按截止时间升序
② 逐个加入，维护 t（已用天数）
③ 加入后若 t > dᵢ， 弹出已选中最长的那门（大顶堆）
④ 结果 = 堆 size
course_schedule_iii.py
  1. import heapq
  2.  
  3. class Solution:
  4. def scheduleCourse(self, courses):
  5. courses.sort(key=lambda x: x[1])
  6. heap = [] # 大顶堆（存负数）
  7. t = 0
  8. for d, last in courses:
  9. if t + d <= last:
  10. heapq.heappush(heap, -d)
  11. t += d
  12. elif heap and -heap[0] > d:
  13. t += d + heapq.heappop(heap)
  14. heapq.heappush(heap, -d)
  15. return len(heap)
为什么对？
按截止排序后，「当前堆里已选的课」
和「新来的课」交换只会影响这一对。
如果新课更短，换掉最长的旧课，总天数减小，且不会挤掉别的。

拟阵 (Matroid) 是什么？

一个独立集族 M = (E, I)，
E 是元素集，I 是「独立子集」的集合，满足：

① 单调性：A ∈ I 且 B ⊆ A ⟹ B ∈ I
② 交换性：A, B ∈ I 且 |A| < |B| ⟹ 存在 x ∈ B∖A 使 A∪{x} ∈ I
定理：
权重最大化贪心正确 ⟺ 独立集族是拟阵。

换句话说：贪心不是「聪明」，是「恰好被数据结构允许」。
问题独立集族是拟阵吗
最小生成树 森林（无环边集） 是 —— 图拟阵
任务调度（区间） 不重叠的活动集 是 —— 分区拟阵
01 背包 总重 ≤ W 的子集 否 —— 交换性不成立
最长路径 简单路径集 否 —— 单调性不成立
实用价值：
竞赛里不需要写拟阵证明，
但知道「01 背包不是拟阵」能让你快速判断 「这题能不能贪」。
一句话： 「贪心的正确性是数据结构给的，不是你猜的。」
贪心被结构允许，不是被聪明允许
