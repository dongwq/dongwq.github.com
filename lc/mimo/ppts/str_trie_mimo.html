  1. def build(s):
  2.     n = len(s)
  3.     cnt = [[0]*26 for _ in range(n+1)]
  4.     for i, ch in enumerate(s):
  5.         cnt[i+1] = cnt[i][:]
  6.         cnt[i+1][ord(ch)-97] += 1
  7.     return cnt
  8.  
  9. # cnt[i][c] = s[0..i-1] 中字符 c 的个数
  10. # 空间 O(26n)，n=1e5 时约 10MB，可接受
  11.  
  12. def same(cnt, l1, r1, l2, r2):
  13.     for c in range(26):
  14.         if cnt[r1+1][c] - cnt[l1][c] \
  15.               != cnt[r2+1][c] - cnt[l2][c]:
  16.             return False
  17.     return True
  18.

  20. # 若字符集是 Unicode（21 位）→ 换哈希表

为什么转变：从「遍历」到「差分」

朴素每次查询要遍历两个子串 O(k)。把「计数」这件事提前算好，查询退化成两次减法。

这就是「预处理 O(n) → 查询 O(1)」的第一个例子。

为什么要压缩状态

「每个字符出现奇数次 / 偶数次」这类条件，用 26 位二进制 mask 存，一次异或就更新。

mask ^= 1 << (ord(ch)-97)

于是「两段子串字符奇偶性相同」= 两个 mask 相等 → O(1)。

center_expand.pyPYTHON
  1. def longest_palindrome(s):
  2.     n = len(s)
  3.     if n < 2: return s
  4.     best_l, best_r = 0, 0
  5.  
  6.     def expand(l, r):
  7.         while l >= 0 and r < n \
  8.                 and s[l] == s[r]:
  9.             l -= 1; r += 1
  10.         return l+1, r-1
  11.  
  12.     for i in range(n):
  13.         l1, r1 = expand(i, i)       # 奇
  14.         l2, r2 = expand(i, i+1)   # 偶
  15.         for l, r in ((l1, r1), (l2, r2)):
  16.             if r - l > best_r - best_l:
  17.                 best_l, best_r = l, r
  18.  
  19.     return s[best_l:best_r+1]
  20.  
  21. # 时间 O(n²)，空间 O(1)
  22. # n ≤ 1000 完全够用；再大换 Manacher

为什么需要字符串哈希：把串变成数
动机数字比较 O(1)，字符串比较 O(n)——那能不能把字符串变成数字？
目标 = f(串) → 整数，且 s == t ⇔ f(s) == f(t)（高概率成立）
O(1) （原本 "abc" == "abc" 要 3 次字符比较） 代价：不同串可能「撞」成同一个数 → 冲突

为什么要「取模」

字符串映射出的整数会爆炸（长度 10⁵ 时约 26¹⁰⁵）。

取模把它压进 0 ~ mod-1，代价是引入冲突。

冲突能有多小

单哈希、mod = 10⁹+7 时，随机碰撞概率约 1/mod。

竞赛里 单哈希基本够用，但「有人造数据卡哈希」时必须双哈希。

为什么转变

朴素做法：每次比较都走一遍。

哈希做法：把「比较」提前变成「计算」，之后只是查数。

这是「预处理换查询」的极致形态。

← 三个数一比就完事
多项式哈希：字符串 = base 进制数
原理最主流的字符串哈希：把串看成 base 进制的数，取模后作为指纹
公式 = h(s) = Σ s[i]·base^(n-1-i) mod mod；像极了 10 进制数

base 怎么选

· 取大于字符集的质数，如 131、13331、257
· 不要取 2 的幂（易被构造）
· 用 ord(ch) 的值直接当「数位」

mod 怎么选

· 常用 10⁹+7、10⁹+9、10¹⁸+9
· 模数越大冲突越少
· Python 整数不限长，10¹⁸+9 也安全

为什么是「多项式」

因为把字符串当作系数为字符、变量为 base 的多项式，在 x = base 处取值。

这就解释了为什么它叫多项式哈希，也解释了进位从哪来。

← 就是换个「进制」的 1234

朴素复杂度

n = 10⁶、m = 10⁴ 就是 10¹⁰，必炸。

要解决的到底是什么

不是「比较太慢」，而是「比较了但没记住」。

已知前 j 个字符相等，那么失配时应该跳到哪个 j'？

把「每个 j 对应的 j'」预先算好，就是 next 数组。

为什么转变

从「每次重来」到「带记忆前进」。

这与哈希的路线完全不同：哈希把比较变快，KMP 把比较变少。

两条路线互不冲突，可以互补。

← 「记住」而不是「加快」
border 与 next 数组：失配时该跳到哪
概念p 的 border = 既是前缀又是后缀的子串；next[i] 就是 p[0..i-1] 的最长 border 长度
定义 = next[i] = p[0..i-1] 最长 border 长度；它就是「失配后下一步该比第几位」
最长 border 长度 = 失配时，j 应跳到的新位置 next[5] = 2（对 "ababa"）

为什么 border 就是「答案」

若 p[0..j-1] 与 s 的某段已匹配，失配于 j，那么前缀的 border 部分仍是匹配的。

把 j 跳到 border 长度，就省掉了已知相等的部分。

1

2
KMP：跳到 next[j]，省下比较
3

一句话记住

next[i] 告诉你「还剩多少是已知相等的」。

所以失配后不用回到零，直接从那里继续。

若 i 落在已知区间 [l, r] 内，那么 s[i..] 与 s[i-l..] 前 r-i 个字符一定相等。

所以直接抄 z[i-l]，但不能超过 r-i（否则没验证过）。

  7.     for i in range(n):
