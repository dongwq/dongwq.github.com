核心思想：只维护你需要的那部分有序
抽象今天所有结构，都是这一个原则的不同实现
原则 = 需求越少，维护越少；维护越少，代价越小

堆版

只维护「最值在顶端」这一条约束。

其余元素完全无序，所以常数极小。

平衡树版

维护完整有序，但要求高度 O(log n)。

代价是要「平衡」——这就是这一章的全部难点。

树状数组版

只维护「前缀和」，够回答排名与计数。

值域小 / 离线时，它是最好的替代品。

← 三条路，同一个原则
堆是什么：完全二叉树 + 堆序性质
定义堆 = 一棵完全二叉树，且每个节点都不大于（或不小于）它的孩子
两个性质 = 形状（完全二叉树） ＋ 序（父 ≤ 子 / 父 ≥ 子），缺一不可

为什么是「完全二叉树」

因为完全二叉树可以塞进数组，不需要左右指针。

省掉指针后，常数比任何平衡树都小，缓存友好。

为什么只要「父 ≤ 子」

只要求父小于子，不要求兄弟有序，更不要求整棵树有序。

这就是「只保边界」的实现方式——约束越弱，维护越快。

两个推论

1
最值在 root，取走 O(1)
2
树高 ⌊log n⌋，所以一切操作 O(log n)
3
代价：无法回答「第 k 小」（不是有序的）
← 「兄弟不一定要有序」是关键
数组表示：父子下标公式
实现完全二叉树按层序编号塞进数组后，父子关系可以纯算术得出
公式 = parent = (i-1)//2，left = 2i+1，right = 2i+2；零指针，零递归

为什么用数组

· 零指针：省内存、少寻址
· 缓存友好：连续访问
· 常数极小：比 Treap 快 2~5 倍

三个下标陷阱

1
Python 0-indexed，教材常写 1-indexed
2
2*i+1 容易写成 2*i
3
判空：孩子 < n 才存在

一层一层看

第 0 层 1 个、第 1 层 2 个、第 2 层 4 个…

所以树高 = ⌊log₂ n⌋，一切操作都与高度成正比。

← 全是加减乘除，不用递归
上浮 sift_up：插入一个元素后怎么修
算法在堆末尾追加一个元素，它可能比父小——怎么恢复堆性质？
做法 = 不断与父交换，直到不比父小或到 root；每次上跳一层 ⇒ O(log n)

为什么只需要「一路向上」

插入前已经是合法堆。新元素只可能破坏它到根这一条链上的关系。

链外的父子关系完全没动，不需要检查。

三个细节

1
循环条件用 i > 0，别写 i >= 0
2
比较用 <= 提前停，减少交换
3
最大堆把比较反过来即可

练习：手推「插入 0 会怎样」，答：一路浮到 root。

← 只破坏「一条链」，所以只改一条链
下沉 sift_down：取出顶端后怎么修
算法把堆顶取走，把末尾元素放到堆顶——它可能比孩子大，怎么恢复？
做法 = 与「较小的孩子」交换，直到不比孩子大或到叶；每次下沉一层 ⇒ O(log n)

为什么是「较小的孩子」

要恢复父 ≤ 两个孩子，只能与较小的那个交换。

换大的那个，另一个孩子还是违反。这一步常写错。

判断是否到底

当没有左孩子时就是叶子，停止。

只有左孩子没右孩子时，候选就是左孩子。

模板里用 m = i 累积最优候选最安全。

三个常见 bug

1
与较大的孩子交换
2
忘了判 右孩子越界
3
堆为空时还调用 pop
← 换「较小」的，不是较大的
建堆为什么是 O(n)：摊销分析
证明把 n 个元素直接放进数组，然后从后往前做 sift_down——为什么比 n 次 insert 快？
关键 = 大部分节点在底层，底层下沉 0 次；总代价 Σ h·2^(H-h) = O(n)
heapify.pyPYTHON
  1. def heapify(a):
  2.     n = len(a)
  3.     for i in range(n // 2 - 1, -1, -1):
  4.         sift_down(a, i, n)
  5.     return a
  6.  
  7. # 从最后一个非叶开始，逆序下沉
  8. # 时间 O(n)，不是 O(n log n)！

为什么从 n//2-1 开始

下标 ≥ n//2 的都是叶子，已经合法，不需要下沉。

只需处理非叶节点，所以循环起点是 n//2 - 1。

· 一次给一批数据，之后只做 push/pop → heapify 快
· 数据陆续到来 → 只能逐个 push
· Python：heapq.heapify(a) 就是 O(n)

← 「一半节点在底部」是整个证明的支点

  1. class MinHeap:
  2.     def __init__(self):
  3.         self.a = []
  4.  
  5.     def push(self, x):
  6.         self.a.append(x)
  7.         self._up(len(self.a) - 1)
  8.  
  9.     def pop(self):
  10.         a = self.a
  11.         a[0], a[-1] = a[-1], a[0]
  12.         top = a.pop()
  13.         if a: self._down(0)
  14.         return top
  15.  
  16.     def top(self):
  17.         return self.a[0]
  18.  
  19.     def _up(self, i):
  20.         a = self.a
  21.         while i > 0:
  22.             p = (i - 1) // 2
  23.             if a[p] <= a[i]: break
  24.             a[p], a[i] = a[i], a[p]
  25.             i = p
  26.  
  27.     def _down(self, i):
  28.         a = self.a; n = len(a)
  29.         while True:
  30.             l, r = 2*i+1, 2*i+2
  31.             m = i
  32.             if l < n and a[l] < a[m]: m = l
  33.             if r < n and a[r] < a[m]: m = r
  34.             if m == i: break
  35.             a[i], a[m] = a[m], a[i]
  36.             i = m

为什么是「最小」堆

要淘汰的永远是当前候选中最小的，所以把最小的放在容易取的位置（堆顶）。

用最大堆反而要遍历才能找到最小。「反过来想」是这类题的关键。

merge_k_lists.pyPYTHON
  1. import heapq
  2.  
  3. def merge_k(lists):
  4.     h = []
  5.     for i, arr in enumerate(lists):
  6.         if arr:
  7.             heapq.heappush(h, (arr[0], i, 0))
  8.     out = []
  9.     while h:
  10.         v, i, j = heapq.heappop(h)
  11.         out.append(v)
  12.         if j + 1 < len(lists[i]):
  13.             heapq.heappush(h, (lists[i][j+1], i, j+1))
  14.     return out
  15.  
  16. # 堆里始终只有 K 个元素
  17. # 元组 (值, 序号, 位置) 保证不重复比较
  18. # 时间 O(n log K)，空间 O(K)

为什么只放「头」

每个序列已有序，所以「下一个可能的最小」一定在某个头里。

把 K 个头丢进堆，堆顶就是全局最小——这是贪心正确性的来源。

核心：维护每个节点的高度差 ≤ 1，违反就旋转。

优点：不写平衡条件，靠概率

核心：只写 split 与 merge，一切操作都是它们的组合。

优点：代码短、模板化、区间操作顺手

「根归哪边」的判断

u.key < k 成立 → 根归 L，那它的右子树才可能有归 R 的。

反之归 R，递归拆左子树。别弄反。

按 size 分裂（区间用）

有时要「前 k 个」而不是「key < k」。

把判断换成 size(u.l) + 1 <= k 即可，其余结构完全一样。

这是文艺平衡树（区间翻转）的基础。

↑ 「根归哪边」就决定了递归方向

  13.     if u: u.sz = 1 + size(u.l) + size(u.r)

  15. def split(u, k):  # key < k 的归 L
  16.     if not u: return (None, None)
  17.     if u.key < k:
  18.         l, r = split(u.r, k)

  27.     if not a or not b: return a or b
  28.     if a.prio < b.prio:
  29.         a.r = merge(a.r, b); pull(a); return a
  30.     else:

  36.

  38.     l, r = split(root, key)
  39.     m, r = split(r, key + 1)  # m 就是 key

  43.     while u:
  44.         left = size(u.l) + 1
  45.         if k == left: return u.key
  46.         if k < left: u = u.l
  47.         else: k -= left; u = u.r

  50.     r = 1
  51.     while u:
  52.         if key <= u.key: u = u.l
  53.         else: r += size(u.l) + 1; u = u.r
