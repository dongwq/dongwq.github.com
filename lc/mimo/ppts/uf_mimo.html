痛点：动态连通性——「现在 a 和 b 通了吗」
问题n 个点，不断加入边，每次问「a 和 b 在不在同一个连通块」——每次跑 DFS 太慢
根因 = 每次都重新扫一遍；并查集把「连通块」维护成状态，查询 O(1)

三类「连通性」问题

1
动态加边：加边时维护连通
2
静态判连通：一次判断即可（用 DFS）
3
只问不改：可以预处理，也可以并查集
→
并查集只为第 1 类而生

为什么 DFS 不行

每次查询都要重扫 O(n)，10⁵ 查询 × 10⁵ 点 = 10¹⁰，必超时。

并查集把「查」变成「比两个根」。

← 「比两个根」是全部
并查集只有三个操作：Make / Find / Union
概念不要被名字吓到——它就是「认祖宗」的三个动作
三操作 = Make：各自为政 · Find：找祖宗 · Union：改祖宗
three_ops.pyPYTHON
  1. # ① 初始化
  2. par = list(range(n))  # 每个点是自己的根
  3.  
  4. # ② 找祖宗（朴素版）
  5. def find(x):
  6.     while par[x] != x:
  7.         x = par[x]
  8.     return x
  9.  
  10. # ③ 合并
  11. def union(a, b):
  12.     ra, rb = find(a), find(b)
  13.     if ra != rb:
  14.         par[ra] = rb
  15.  
  16. # ④ 判同集合
  17. def same(a, b):
  18.     return find(a) == find(b)

为什么「以谁为根」不重要

因为我们只关心两个点是否同根，不关心谁是老大。

这给了后面的「按大小合并」留出自由度。

为什么这个抽象能撑起这么多算法

因为它把「关系」变成了「指针」。

指针可以改、可以比较、可以附加信息——三件事一组合，就能解一大类题。

它和「树」的关系

并查集的每个集合就是一棵树，par[x] 就是树上的父。

区别：不关心形状（所以可以随便压缩），只关心根。

这是「上一讲树」的极简版。

↑ 「关系变指针」是核心抽象
朴素实现：写出第一版，能跑就行
实现怎么用 Python 实现最简单的并查集？——一个数组 + 两个函数
最简版 = par[x] 记父；find 一路向上，union 改一个指针
naive_dsu.pyPYTHON
  1. class DSU:
  2.     def __init__(self, n):
  3.         self.p = list(range(n))
  4.         self.cnt = n  # 集合个数
  5.  
  6.     def find(self, x):
  7.         while self.p[x] != x:
  8.             x = self.p[x]
  9.         return x
  10.  
  11.     def union(self, a, b):
  12.         ra, rb = self.find(a), self.find(b)
  13.         if ra == rb: return False
  14.         self.p[ra] = rb
  15.         self.cnt -= 1
  16.         return True
  17.  
  18.     def same(self, a, b):
  19.         return self.find(a) == self.find(b)
  20.  
  21. # self.cnt 维护「还剩几个集合」
  22. # 判「全部连通」⇔ cnt == 1
↑ 「一个数组 + 两个函数」就是朴素版
Union 时「以谁为根」——这个选择值一个复杂度
决策par[A]=B 还是 par[B]=A？随手写会怎样？——决定了树会不会退化
差别 = 随手写 → 可能退化成链；按大小写 → 高度最多 log n
union_choice.pyPY
  1. # ❌ 随手写
  2. def union_bad(a, b):
  3.     par[find(a)] = find(b)
  4.  
  5. # ✅ 按大小
  6. def union_size(a, b):
  7.     ra, rb = find(a), find(b)
  8.     if ra == rb: return
  9.     if size[ra] < size[rb]:
  10.         ra, rb = rb, ra
  11.     par[rb] = ra
  12.     size[ra] += size[rb]
  13.  
  14. # ✅ 也可以按秩（rank = 树高）
  15. def union_rank(a, b):
  16.     ra, rb = find(a), find(b)
  17.     if ra == rb: return
  18.     if rank[ra] < rank[rb]: ra, rb = rb, ra
  19.     par[rb] = ra
  20.     if rank[ra] == rank[rb]: rank[ra] += 1

按大小 vs 按秩，选哪个

· 按大小：还能顺手维护 size[]，更实用
· 按秩：严格证明更干净，但少一个附加信息

竞赛里一般写「按大小」。

「为什么 log n」一句话解释

小的挂到大的 ⇒ 每次被挂的那棵树，size 至少翻倍。

一个点最多被「翻倍」log n 次，高度 ≤ log n。

compress.pyPY
  1. # ① 递归版（好写）
  2. def find(x):
  3.     if par[x] != x:
  4.         par[x] = find(par[x])  # 关键一行
  5.     return par[x]
  6.  
  7. # ② 迭代版（不爆栈）
  8. def find_iter(x):
  9.     root = x
  10.     while par[root] != root:
  11.         root = par[root]
  12.     # 第二遍：把路上所有点挂到 root
  13.     while par[x] != root:
  14.         nxt = par[x]
  15.         par[x] = root
  16.         x = nxt
  17.     return root
  18.  
  19. # ③ 路径减半（折中）
  20. # par[x] = par[par[x]] 每次跳两格

⚠ 递归版可能爆栈

n 很大时 find 递归深度可能上万。

Python 用 sys.setrecursionlimit 或直接写迭代版。

↑ 「关键一行」是并查集的精华
优化二：按大小合并——让树天然矮
技巧压缩是「事后补救」，有没有「事前预防」？——合并时挑个好方向
技巧 = 小的挂到大的；被挂的 size 至少翻倍，高度 ≤ log n
by_size.pyPY
  1. class DSU:
  2.     def __init__(self, n):
  3.         self.p = list(range(n))
  4.         self.sz = [1] * n
  5.  
  6.     def find(self, x):
  7.         while self.p[x] != x:
  8.             self.p[x] = self.p[self.p[x]]  # 减半
  9.             x = self.p[x]
  10.         return x
  11.  
  12.     def union(self, a, b):
  13.         a, b = self.find(a), self.find(b)
  14.         if a == b: return False
  15.         if self.sz[a] < self.sz[b]: a, b = b, a
  16.         self.p[b] = a
  17.         self.sz[a] += self.sz[b]
  18.         return True
  19.  
  20.     def size(self, x):
  21.         return self.sz[self.find(x)]

「α(n)」这个名字要认识

读作「反阿克曼」，增长极慢，比 log n 还慢得多。

竞赛中不要试图证，直接记住结论：两个一起用 = α(n)。

实战写法（直接抄）

· find 用递归压缩或迭代减半
· union 用按大小
· 两者一定要同时写

这一版从下一节开始就叫「完整版 DSU」。

↑ 「两个一起」才有 α(n)，只用一个没用
实测：三种实现跑同样数据，差多少
对比口说无凭——把三种实现放在同一组数据上跑，看时间
实测 = 朴素 3.2s → 压缩 0.11s → 双优化 0.08s；量级差异

  2.     # edges: (w, u, v)
  3.     edges.sort()
  4.     dsu = DSU(n)
  5.     total = 0; cnt = 0
  6.     for w, u, v in edges:
  7.         if dsu.union(u, v):  # 判环 + 合并
  8.             total += w
  9.             cnt += 1
  10.             if cnt == n - 1: break

为什么一定要并查集

因为 Kruskal 的核心操作是「这条边会不会形成环」，而并查集就是为判环而生。

两者是天然一对。

带权并查集：不只问「同不同」，还问「差多少」

转化 = 再存一个 d[x]：x 到根的「差值」；find 时顺手更新 d

「带权」的真正含义

不是点权也不是边权，而是「点与根之间的关系量」。

可以是数值差（高低、距离）、类别差（天敌/猎物）、奇偶（两性关系）。

为什么需要「更新 d」

路径压缩会改变父指针，如果不更新 d，关系就断了。

压缩和权值必须一起维护——这是带权并查集的核心。

三类典型

带权并查集模板：一次 find，三个改动
实现怎么把「朴素 DSU」升级成「带权 DSU」？——就改 find 与 union 两处
改动 = find 返回 d[x]；union 时算 d[ra]；其他照抄
weighted_dsu.pyPYTHON
  1. class WDSU:
  2.     def __init__(self, n):
  3.         self.p = list(range(n))
  4.         self.d = [0] * n  # 到根的差
  5.  
  6.     def find(self, x):
  7.         if self.p[x] != x:
  8.             root = self.find(self.p[x])
  9.             self.d[x] += self.d[self.p[x]]  # 先累
  10.             self.p[x] = root
  11.         return self.p[x]
  12.  
  13.     def union(self, a, b, w):  # a 到 b 的差 = w
  14.         ra, rb = self.find(a), self.find(b)
  15.         if ra == rb: return
  16.         self.p[ra] = rb
  17.         # 推 ra 到 rb 的差
  18.         self.d[ra] = self.d[b] - self.d[a] + w
  19.  
  20.     def query(self, a, b):
  21.         if self.find(a) != self.find(b):
  22.             return None
  23.         return self.d[a] - self.d[b]

三个改动

1
多一个 d[] 数组
2
find 时先递归，再累加 d（顺序别反）
3
union 时用「关系式」反推 d[ra]

「关系式反推」怎么算

画个小图：a → ra、b → rb、ra → rb。

要求 d[a] + w = d[b] + d[ra]，解出 d[ra]。

画图比背公式稳。

「信息放根上」是通用原则

因为只有根不会变。子节点会被压缩改父，把信息放子上会乱。

所有附加信息都要跟着根走。

· 可合并的：max / min / sum / xor
· 可合并的计数：种类数（配合 set）
· 不可合并的：比如「中位数」→ 换结构

回滚并查集：能「撤销」的并查集
技巧有时候做完一步要撤回——普通并查集能撤吗？不行，那怎么改？

rollback_dsu.pyPYTHON
  1. class RollbackDSU:
  2.     def __init__(self, n):
  3.         self.p = list(range(n))
  4.         self.sz = [1] * n
  5.         self.hist = []  # 改动栈
  6.  
  7.     def find(self, x):  # 不压缩
  8.         while self.p[x] != x: x = self.p[x]
  9.         return x
  10.  
  11.     def union(self, a, b):
  12.         a, b = self.find(a), self.find(b)
  13.         if a == b: return False
  14.         if self.sz[a] < self.sz[b]: a, b = b, a
  15.         self.hist.append((b, self.p[b], self.sz[a]))
  16.         self.p[b] = a
  17.         self.sz[a] += self.sz[b]
  18.         return True
  19.  
  20.     def snapshot(self):
  21.         return len(self.hist)
  22.  
  23.     def rollback(self, mark):
  24.         while len(self.hist) > mark:
  25.             b, oldp, oldsz = self.hist.pop()
  26.             self.sz[self.p[b]] = oldsz
  27.             self.p[b] = oldp

为什么不能压缩

压缩一次会改很多父指针，撤销要记很多，得不偿失。

回滚版只保留按秩，高度仍然 O(log n)。

什么时候需要回滚

· 分治：递归完左子树要退回去
· 时间轴：在某一时刻的状态
· 枚举：试完一个要重来

和「可持久化并查集」不是一回事，回滚只能撤最近的。

↑ 「不压缩」是回滚版的代价
离线处理：倒着来，删边变加边
技巧「删边 + 问连通」很难，「加边 + 问连通」很简单——能不能倒过来？
技巧 = 时间倒流；删边 ⇒ 变加边，再用并查集一次性处理
offline.pyPYTHON
  1. def offline(n, edges, ops):
  2.     # ops: ('del', i) 或 ('ask', a, b)
  3.     alive = [True] * len(edges)
  4.     for op in ops:
  5.         if op[0] == 'del': alive[op[1]] = False
  6.  
  7.     dsu = DSU(n)
  8.     for i, (u, v) in enumerate(edges):
  9.         if alive[i]: dsu.union(u, v)
  10.  
  11.     ans = []
  12.     for op in reversed(ops):
  13.         if op[0] == 'ask':
  14.             ans.append(dsu.same(op[1], op[2]))
  15.         else:
  16.             u, v = edges[op[1]]
  17.             dsu.union(u, v)
  18.     return reversed(ans)
  19.  
  20. # 关键：先算出「最终存活的边」
  21. # 倒着处理 ops，删边变加边

不是每次都 O(1)，是很多次的平均。

dsu_template.pyPYTHON
  1. class DSU:
  2.     __slots__ = ('p', 'sz', 'cnt')
  3.     def __init__(self, n):
  4.         self.p = list(range(n))
  5.         self.sz = [1] * n
  6.         self.cnt = n
  7.  
  8.     def find(self, x):
  9.         p = self.p
  10.         while p[x] != x:
  11.             p[x] = p[p[x]]
  12.             x = p[x]
  13.         return x
  14.  
  15.     def union(self, a, b):
  16.         a, b = self.find(a), self.find(b)
  17.         if a == b: return False
  18.         if self.sz[a] < self.sz[b]: a, b = b, a
  19.         self.p[b] = a
  20.         self.sz[a] += self.sz[b]
  21.         self.cnt -= 1
  22.         return True
  23.  
  24.     def same(self, a, b):
  25.         return self.find(a) == self.find(b)
  26.     def size(self, x):
  27.         return self.sz[self.find(x)]

这份模板的特点

1
路径减半，不递归，不爆栈
2
按大小合并，还能查 size
3
union 返回 bool，判环方便
4
cnt 顺手维护集合个数

tarjan_lca.pyPY
  1. # Tarjan 离线 LCA：并查集找祖先
  2. def tarjan_lca(n, g, queries):
  3.     dsu = DSU(n)
  4.     seen = [False] * n
  5.     ans = {}
  6.     def dfs(u):
  7.         seen[u] = True
  8.         for v in g[u]:
  9.             if not seen[v]:
  10.                 dfs(v)
  11.                 dsu.union(v, u)  # 回溯时合并
  12.         for v in queries[u]:
  13.             if seen[v]:
  14.                 ans[(u, v)] = dsu.find(v)
  15.     dfs(0)
  16.     return ans
  17.  
  18. # 核心：DFS 回溯时「认父」
  19. # 这就是并查集在树上的妙用

← 「会识别」是最难的一段
经典题精讲：P1525 关押罪犯
题意n 个罪犯，m 对仇恨关系（有仇恨值）。要把他们分到两个监狱，同监狱内仇恨值最大者尽量小
思路 = 按仇恨值从大到小排序；尽量让「仇恨大的」分开，矛盾时输出答案
p1525.pyPYTHON
  1. def solve(n, hates):
  2.     # hates: (w, a, b)
  3.     hates.sort(reverse=True)
  4.     dsu = DSU(2 * n + 1)
  5.     for w, a, b in hates:
  6.         if dsu.same(a, b):
  7.             return w  # 不得不同监，答案
  8.         dsu.union(a, b + n)  # a 与 b 的敌人同
  9.         dsu.union(b, a + n)
  10.     return 0
  11.  
  12. # 关键：降序处理 + 「敌人」副本
  13. # 用 2n 表示「a 与 a+n 是敌人」
  14. # 矛盾 = 同集合但本应是敌人

为什么「降序」

要最大化「同监内仇恨值的最小」，等价于降序贪心：能分开就分开，分不开就停下。

贪心 + 并查集是这类题的标准组合。

↑ 「贪心 + 并查集」是标准组合
经典题精讲：P1197 星球大战
题意n 个星球 m 条通道，依次摧毁 k 个星球。每次摧毁后问剩几个连通块
思路 = 倒序：从「全毁」开始，逐步「重建」；删边变加边，用并查集
p1197.pyPYTHON
  1. def solve(n, edges, kills):
  2.     g = [[] for _ in range(n)]
  3.     for u, v in edges:
  4.         g[u].append(v)
  5.         g[v].append(u)
  6.  
  7.     destroyed = set(kills)
  8.     dsu = DSU(n + 1)
  9.     # ① 先把「没被毁」的边都加上
  10.     for u, v in edges:
  11.         if u not in destroyed and v not in destroyed:
  12.             dsu.union(u, v)
  13.  
  14.     ans = []
  15.     for x in reversed(kills):
  16.         ans.append(dsu.cnt - len(destroyed))
  17.         destroyed.discard(x)
  18.         for v in g[x]:
  19.             if v not in destroyed:
  20.                 dsu.union(x, v)
  21.     return reversed(ans)
  22.  
  23. # 关键：cnt 减去「还毁着的点数」
