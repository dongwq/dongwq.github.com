00先看它要解决的矛盾

一个数组，既要能"改一个数"，又要能"查一段区间的和"，这两个需求天生互相拖后腿。

如果什么都不做，直接在原数组上改一个数是 O(1)，但查一段区间的和要老老实实加一遍，是 O(n)。

如果提前算好前缀和数组，查区间和只要减两个数，是 O(1)，但只要改动一个数，后面所有前缀和都要重新算，变成 O(n)。

树状数组的目标，是让这两件事都落在 O(log n)，用空间和结构上的巧思，换来两头都快。

方案单点更新区间查询
原始数组O(1)O(n)
前缀和数组O(n)O(1)
树状数组O(log n)O(log n)

01核心武器：lowbit

树状数组的一切结构，都建立在一个位运算小技巧上。

lowbit(x) = x & (-x)，它做的事情很单纯： 从 x 的二进制表示里，抠出最低位那个 1，其余全部清零。 比如 6 是 110，最低的 1 在第 2 位，所以 lowbit(6) = 2。

高亮的那一位，就是 lowbit 抓到的位置。记住这一个数字， 后面的"管辖范围""更新往哪跳""查询往哪跳"全部由它决定。

02结构：每个节点管一段"以自己结尾"的区间

树状数组的第 i 个位置，存的不是 A[i] 本身，而是一段区间的和。

树状数组 C[i] 管辖的区间是 [i − lowbit(i) + 1, i]，也就是"以 i 结尾、 长度正好等于 lowbit(i)"的那一段。lowbit 越大，这个节点管得越宽。

图1　管辖范围（n = 8）
每根橙色条的宽度就是 lowbit(i)，条越宽，节点管的范围越大，最上面的 C8 直接管了全部。

03更新：往上跳，一路加

改了 A[i]，所有"管辖范围包含 i"的节点都要跟着更新。

从 i 出发，每次跳到 i + lowbit(i)，一直跳到超过 数组长度为止，沿途碰到的每个节点都加上变化量。这条路径正好穿过所有 管辖范围盖住了 i 的节点，不多也不少。 

// 单点更新：A[i] += val
void update(int i, int val){
    for (; i <= n; i += lowbit(i))
        tree[i] += val;
}
图2　update(3) 的传播路径
高亮路径：3 → 4 → 8，一共 3 步，对应 log₂8 = 3。

04查询：往下跳，一路加

求前缀和 sum(1..i)，从 i 出发往回收，每一步吞掉一段区间。

从 i 出发，每次先把 C[i] 加进结果，再跳到 i − lowbit(i)，直到跳到 0。因为每一步都甩掉 当前最低位的 1，最多跳 log₂n 次就能走完。 任意区间 [l, r] 的和，就是 query(r) − query(l − 1)。 

// 前缀和：sum(1..i)
int query(int i){
    int res = 0;
    for (; i > 0; i -= lowbit(i))
        res += tree[i];
    return res;
}
图3　query(7) 的跳跃路径
query(7) = C7 + C6 + C4，跳了 3 步落到 0，跳的次数等于 7 的二进制里有几个 1。

05三种常见玩法

基础版之外，树状数组还能通过"换一层含义"解决更多问题。

单点更新 + 区间查询　就是前面讲的基础版：树状数组直接维护原数组的和。

区间更新 + 单点查询　对差分数组建树状数组。给区间 [l, r] 整体加 v， 等价于 update(l, +v) 和 update(r+1, -v) 两次单点更新； 查任意一点的值，就是对差分数组求一次前缀和。

区间更新 + 区间查询　在差分思路上再维护第二棵树状数组， 把区间和公式拆开变形即可，本质还是两次前缀和的组合，不需要死记，遇到再推。

统计逆序对 / 第 K 大　把数值离散化成排名后，从左到右（或从右到左）扫描， 每处理一个数就查询"目前已出现、比它小（或大）的数有多少个"，再把它自己插入树状数组。 这是树状数组在 LeetCode 上最常见的高阶用法。
