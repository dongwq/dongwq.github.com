先理解：什么是 BST？
基础结构

二叉搜索树规则

8 / \ 3 15 / \ / \ 1 5 10 20
节点 8：左边全部 < 8，右边全部 > 8

查找 10 的路径

8 ↓ 15 ↓ 10
理想情况：高度 O(log n)
查找 / 插入 / 删除 = O(log n)
03
为什么必须“平衡”？
退化成链

普通 BST（插入 1..7）

1 \ 2 \ 3 \ 4 \ 5 \ 6 \ 7
高度 O(n) → 退化成链表

平衡 BST

4 / \ 2 6 / \ / \ 1 3 5 7
高度 O(log n) → 所有操作稳定
04
平衡树在“平衡”什么？
三种常见策略

🌲 AVL Tree

|height(L) - height(R)| ≤ 1

优点：查找非常稳定
缺点：修改维护严格

🔴 Red-Black Tree

通过颜色规则控制树高

优点：修改性能好
典型：C++ std::set / std::map

⚡ Treap

BST + Heap

优点：代码短，适合竞赛
核心：随机 priority
核心思想：不要让树退化成链。

场景三：动态维护中位数
平衡树 vs 双堆

平衡树做法

维护 subtree_size
第 (n+1)/2 小就是中位数
插入O(log n)
查询中位数O(log n)

双堆做法（竞赛常用）

小于中位数 / \ 大根堆 小根堆 max-heap min-heap
左边大根堆，右边小根堆
保持两边大小平衡
提醒：竞赛中“动态中位数”不一定首选平衡树。应该根据操作集合选择数据结构，而不是“看到中位数 → 平衡树”。

场景六：二维问题 —— 一维平衡树作为扫描线工具
扫描线思想

扫描过程

点集 (x, y) 按 x 从左到右扫描： x → ────────────────────→
扫描到某个 x 时，把活跃点的 y 放进平衡树

降维思想

二维问题 (x, y) ↓ 扫描 x + 维护 y 的有序集合
这就是 扫描线 Sweep Line 的基本思想。

竞赛中最值得掌握的：Treap
Tree + Heap

节点结构

┌──────────────┐ │ key │ ← BST │ priority │ ← Heap │ size │ ← 子树大小 │ left │ │ right │ └──────────────┘

示例

(8,90) / \ (3,50) (15,70) key：3 < 8 < 15 priority：90 > 50，90 > 70

16
什么时候“不应该”使用平衡树？
常见误区
情况不要用平衡树优先选择
只需要最大值❌Heap
只需要判断存在性❌HashSet
数据完全静态❌排序 + 二分
值域非常小❌计数数组 / Fenwick / Segment Tree
常见误区：看到“有序”就上平衡树。应该先问：数据是否动态？是否需要前驱后继/排名？如果只是查存在，HashSet 更快；如果只要最值，Heap 更简单。

最后：用一句话记住平衡树
总结
🎯 记住这三句话
Hash 表 解决“有没有”。
堆 解决“最大/最小”。
平衡树 解决“动态数据中的有序关系”。

尤其是：前驱、后继、 lower_bound、 upper_bound、排名、第 k 小。
平衡树 │ ┌───────────┼───────────┐ ↓ ↓ ↓ 动态 有序 查询 │ │ │ insert min/max lower_bound erase 排序关系 upper_bound │ ┌────────┼────────┐ ↓ ↓ ↓ 前驱 后继 第k小
动态插入 + 动态删除 + 保持有序 + 查询附近元素/排名 → 平衡树 / Treap
